ID: idea_31-simplified

static-temporal-embedding-comparison

Hypothesis

Incorporating basic temporal information into entity embeddings will improve forecasting accuracy on temporal knowledge graphs compared to static embeddings, as measured by Hits@3 and MRR on a subset of the ICEWS dataset.

Elements

  • Independent variable: Type of entity embedding (static vs. time-aware)
  • Dependent variable: Forecasting accuracy on temporal knowledge graphs
  • Comparison groups: Static embedding model vs. Time-aware embedding model
  • Baseline/control: Static embedding model (TransE)
  • Context/setting: Temporal knowledge graph forecasting on ICEWS dataset subset
  • Assumptions: Time-aware embeddings will capture temporal patterns better than static embeddings
  • Relationship type: Causation
  • Population: Entities and relations in the ICEWS dataset subset
  • Timeframe: Training on historical data, testing on future data
  • Measurement method: Hits@3 and MRR metrics

Description

This research explores a simplified approach to temporal knowledge graph forecasting by comparing static entity embeddings with basic time-aware embeddings. Rather than implementing the full diachronic embedding with neural time point process model, this study focuses on a more accessible comparison between traditional static entity embeddings and a simplified time-aware embedding approach. The research will evaluate how incorporating basic temporal information into entity representations affects forecasting accuracy on a subset of a temporal knowledge graph dataset. This simplified approach provides an entry point to understanding temporal knowledge graph forecasting while requiring less computational resources and implementation complexity than the original research idea.

Implementation Design

This experiment compares static entity embeddings with simplified time-aware embeddings for temporal knowledge graph forecasting. Follow these steps:

1. Data Preparation:
- Download the ICEWS dataset (a subset from 2014).
- Preprocess the data to create training, validation, and test sets. The test set should contain future events relative to the training set.
- Create a smaller subset (e.g., 1-2 months) for initial development and testing.

2. Model Implementation:
- Baseline Model: Implement a standard TransE model with static entity embeddings. Use PyTorch for implementation.
- Time-aware Model: Modify the TransE model to incorporate temporal information by concatenating a time embedding to the entity embedding. The time embedding can be created by encoding the timestamp using sinusoidal functions (similar to positional encoding in transformers).

3. Training Procedure:
- Train both models on the training set using negative sampling and a margin-based loss function.
- Use early stopping based on validation set performance.
- Hyperparameters to tune: embedding dimension (start with 100), learning rate (start with 0.001), batch size (start with 128), margin (start with 1.0).

4. Evaluation:
- For each test triple (s, r, ?, t) where we need to predict the object entity at time t, rank all possible entities and compute Hits@3 and MRR.
- Similarly, evaluate subject prediction with triples (?, r, o, t).
- Compare the performance of the static and time-aware models.
- Analyze results based on different relation types and time intervals.

5. Output and Analysis:
- Save trained models and embeddings for future use.
- Generate tables and plots comparing the performance of both models.
- Perform error analysis to identify types of predictions where temporal information helps most.
- Save all results in CSV format for easy analysis.

Implementation Notes:

- Use NumPy and Pandas for data processing.
- Use Matplotlib and Seaborn for visualization.
- Structure your code with separate modules for data processing, model implementation, training, and evaluation.

Operationalization

Please implement a comparative experiment between static and time-aware embeddings for temporal knowledge graph forecasting. The experiment should follow these specifications:

1. PILOT MODE SETTINGS:
- Create a global variable PILOT_MODE that can be set to 'MINI_PILOT', 'PILOT', or 'FULL_EXPERIMENT'
- MINI_PILOT: Use 100 triples for training, 20 for validation, 20 for testing. Run for 5 epochs.
- PILOT: Use 1000 triples for training, 200 for validation, 200 for testing. Run for 10 epochs.
- FULL_EXPERIMENT: Use the full ICEWS14 dataset with standard splits. Run for 100 epochs.

2. DATA PREPARATION:
- Use the Huggingface Datasets API to load the ICEWS14 dataset
- Each triple should be in format (subject, relation, object, timestamp)
- Create train/validation/test splits ensuring test data is temporally after training data
- For MINI_PILOT and PILOT, randomly sample the specified number of triples from each split

3. MODEL IMPLEMENTATION:
A. Static TransE (Baseline):
- Implement standard TransE with entity embeddings of dimension 100
- Initialize embeddings randomly from uniform(-0.1, 0.1)
- Use L2 normalization for entity embeddings

B. Time-aware TransE (Experimental):
- Modify TransE to include temporal information
- Create time embeddings using sinusoidal encoding (dimension 20)
- Concatenate time embeddings with entity embeddings
- Total embedding dimension: 120 (100 for entity + 20 for time)

4. TRAINING PROCEDURE:
- Use Adam optimizer with learning rate 0.001
- Batch size: 32 for MINI_PILOT, 128 for PILOT/FULL
- Negative sampling: 5 negative samples per positive triple
- Margin-based loss with margin=1.0
- Early stopping on validation loss with patience=3

5. EVALUATION:
For each test triple (s,r,?,t):
- Generate all possible (s,r,o,t) candidates
- Rank candidates by score
- Calculate Hits@3 and MRR
- Repeat for (?,r,o,t) format
- Average metrics across both formats

6. ANALYSIS AND VISUALIZATION:

- Create bar plots comparing Hits@3 and MRR between models
- Use bootstrap resampling to test for significant differences
- Save all results to a CSV file including:
