domain-enhanced-prompting

Hypothesis

In few-shot text classification tasks, using domain-enhanced prompts will result in a higher F1-score compared to using standard prompts without domain-specific information.

Elements

  • Independent variable: Type of prompt (domain-enhanced vs. standard)
  • Dependent variable: F1-score in text classification
  • Comparison groups: Domain-enhanced prompts vs. standard prompts
  • Baseline/control: Standard prompts without domain-specific information
  • Context/setting: Few-shot text classification in a specific domain (e.g., product reviews)
  • Assumptions: Domain-enhanced prompts are effectively designed with relevant domain knowledge
  • Relationship type: Causation
  • Population: Text classification tasks in the chosen domain
  • Timeframe: Not specified
  • Measurement method: F1-score

Description

This research explores the effectiveness of domain-enhanced prompts in few-shot text classification tasks. Domain-enhanced prompts incorporate domain-specific knowledge and terminology into prompt design, potentially improving model performance by providing contextually relevant information. The study will compare the performance of a language model using domain-enhanced prompts against standard prompts without domain-specific information. By focusing on a single domain (e.g., sentiment analysis of product reviews), the research aims to determine whether incorporating domain knowledge into prompts can significantly improve classification accuracy in low-data scenarios. This addresses an important question in prompt engineering while being feasible for a researcher with limited resources.

Operationalization

Please implement an experiment to evaluate domain-enhanced prompting in few-shot text classification. The experiment should follow these specifications:

1. PILOT MODES AND DATASET:
- Create a global variable PILOT_MODE that can be set to 'MINI_PILOT', 'PILOT', or 'FULL_EXPERIMENT'
- Use the IMDB dataset from Huggingface for sentiment classification (positive/negative)
- Dataset sizes for different modes:
* MINI_PILOT: 10 test examples (5 pos, 5 neg), 2 few-shot examples per class
* PILOT: 100 test examples (50 pos, 50 neg), 5 few-shot examples per class
* FULL_EXPERIMENT: 1000 test examples (500 pos, 500 neg), 5 few-shot examples per class

2. PROMPT DESIGN:
Create two prompt templates:
a) Standard prompt template:
```
Classify the sentiment of the following movie review as either positive or negative.

Here are some examples:
[FEW SHOT EXAMPLES]

Now classify this review:
[INPUT]
```

b) Domain-enhanced prompt template:
```
Analyze the sentiment (positive or negative) of the following movie review. When evaluating movie reviews, consider aspects like:
- Acting performances and character development
- Plot coherence and pacing
- Visual effects and cinematography
- Emotional impact and entertainment value
- Direction and technical execution

Here are some examples with explanations:
[FEW SHOT EXAMPLES WITH DOMAIN CONTEXT]

Now classify this review:
[INPUT]
```

3. EXPERIMENTAL PROCEDURE:
- Use gpt-4o-mini for all LLM calls
- For each test example:
* Run classification with both prompt types
* Record the prediction and ground truth
* Log the full prompt and response
- Calculate metrics (F1, precision, recall, accuracy)
- Use bootstrap resampling to test for significant differences
- Generate plots comparing metrics between conditions

4. SPECIFIC STEPS:
a) Load and prepare data:
- Load IMDB dataset using Huggingface
- Sample appropriate number of examples based on PILOT_MODE
- Split into few-shot and test sets

b) Run classifications:
- For each test example:
* Format both standard and domain-enhanced prompts
* Get classifications from gpt-4o-mini
* Store results in a structured format

c) Analysis:
- Calculate all metrics
- Run bootstrap significance tests
- Generate comparison plots
- Save all results and logs

5. OUTPUT:
- Save all prompts used
- Save raw model outputs
- Save performance metrics
- Generate plots comparing conditions
- Create summary report

6. EXECUTION ORDER:
1. Run MINI_PILOT first
2. If successful, run PILOT
3. Stop after PILOT (await human verification before FULL_EXPERIMENT)
