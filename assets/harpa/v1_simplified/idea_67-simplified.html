ID: idea_67-simplified

simple-debate-fact-checking

Hypothesis

A structured two-agent debate protocol with defined supporting and opposing roles will improve fact-checking accuracy compared to single-agent fact-checking approaches.

Elements

  • Independent variable: Fact-checking method (two-agent debate vs. single-agent)
  • Dependent variable: Accuracy of fact-checking verdicts
  • Comparison groups: Two-agent debate protocol vs. single-agent fact-checking
  • Baseline/control: Single-agent fact-checking
  • Context/setting: Fact-checking of simple factual claims
  • Assumptions: Structured debate between agents will lead to more accurate verdicts
  • Relationship type: Causation
  • Population: LLM outputs on fact-checking tasks
  • Timeframe: Not specified
  • Measurement method: Accuracy assessment against ground truth

Description

This research explores a simplified approach to improving fact-checking using a structured debate framework between two LLM agents. Rather than implementing a full Quantitative Bipolar Argumentation Framework (QBAF), this project focuses on creating a basic debate protocol where two LLM agents discuss claims with defined roles: one agent presents supporting evidence while the other presents counterarguments. The debate is structured in rounds, with a final consensus phase where both agents must agree on a fact-check verdict. This approach aims to improve fact-checking accuracy compared to single-agent approaches by leveraging the benefits of structured argumentation and consensus-building, while being significantly simpler to implement than a full QBAF integration.

Implementation Design

This experiment compares a structured two-agent debate approach to fact-checking against single-agent approaches. Here's how to implement it:

1. Dataset Preparation:
- Use the FEVER dataset (Fact Extraction and VERification), which contains claims labeled as SUPPORTED, REFUTED, or NOT ENOUGH INFO.
- For the pilot, randomly select 100 claims (40 SUPPORTED, 40 REFUTED, 20 NOT ENOUGH INFO).
- Convert the FEVER labels to TRUE, FALSE, and PARTIALLY TRUE/UNCERTAIN for simplicity.

2. Baseline Implementation:
- Single-Agent Fact-Checker: Create a prompt that asks the LLM to fact-check a claim and provide a verdict (TRUE, FALSE, or PARTIALLY TRUE/UNCERTAIN) with reasoning.
- Naive Ensemble: Run two independent single-agent fact-checkers and combine their verdicts using majority voting (if they disagree, default to PARTIALLY TRUE/UNCERTAIN).

3. Two-Agent Debate Implementation:
- Create two agent roles with different system prompts:
- Supporter Agent: "You are a fact-checking agent tasked with finding evidence that supports the given claim. Present the strongest evidence and reasoning in favor of the claim being true."
- Critic Agent: "You are a fact-checking agent tasked with finding evidence that contradicts or challenges the given claim. Present the strongest evidence and reasoning against the claim being true."
- Debate Protocol:
- Round 1: Both agents provide initial arguments based on the claim.
- Round 2: Both agents respond to each other's arguments from Round 1.
- Consensus Phase: Both agents must work together to reach a consensus verdict (TRUE, FALSE, or PARTIALLY TRUE/UNCERTAIN) based on the evidence presented.

4. Implementation Details:
- Use the same LLM (e.g., GPT-3.5-Turbo) for all approaches to ensure fair comparison.
- For the debate, use separate chat contexts for each agent, but share the previous messages between them.
- Store the full conversation history and final verdicts for analysis.
- Implement a simple parser to extract the final verdict from the consensus phase.

5. Evaluation:
- Calculate accuracy, precision, recall, and F1-score for each approach compared to the ground truth labels.
- Analyze agreement rates between agents in the debate approach.
- Perform error analysis on cases where the debate approach fails vs. succeeds compared to baselines.
- Use bootstrap resampling to calculate confidence intervals for the performance metrics.

6. Output and Reporting:
- Save all model outputs, verdicts, and evaluation metrics to CSV files.
- Generate summary statistics and visualizations (confusion matrices, accuracy comparisons).
- Report on qualitative patterns observed in the debate process, including common types of evidence presented and how consensus was reached.

The experiment should be implemented as a Python script that can be run from the command line, with arguments for the dataset path, number of examples to use, and which approaches to evaluate.

Operationalization

Please implement a fact-checking experiment comparing a two-agent debate protocol against single-agent baselines. The experiment should be implemented with three pilot modes (MINI_PILOT, PILOT, FULL_EXPERIMENT), with the following specifications:

PILOT MODES:
- MINI_PILOT: Use 10 claims (4 SUPPORTED, 4 REFUTED, 2 NOT_ENOUGH_INFO) from the FEVER training set
- PILOT: Use 100 claims (40/40/20 split) from the FEVER training set
- FULL_EXPERIMENT: Use 1000 claims (400/400/200 split) from the FEVER dataset, with training/dev/test splits

DATASET PREPARATION:
1. Use the Huggingface Datasets API to load the FEVER dataset
2. Convert FEVER labels (SUPPORTED->TRUE, REFUTED->FALSE, NOT_ENOUGH_INFO->PARTIALLY_TRUE)
3. Sample the appropriate number of examples based on PILOT_MODE

BASELINE IMPLEMENTATIONS:
1. Single-Agent Baseline:
- System prompt: 'You are a fact-checking agent. Analyze the claim and determine if it is TRUE, FALSE, or PARTIALLY TRUE. Provide your reasoning.'
- Use gpt-4o-mini for all LLM calls
- Store verdict and reasoning

2. Naive Ensemble Baseline:
- Run two independent single-agent fact-checkers
- Use majority voting (if disagree, use PARTIALLY TRUE)
- Store both verdicts and final ensemble verdict

EXPERIMENTAL IMPLEMENTATION:
1. Two-Agent Debate Protocol:
- Supporter Agent prompt: 'You are a fact-checking agent focused on finding supporting evidence. Present the strongest evidence that the claim is TRUE.'
- Critic Agent prompt: 'You are a fact-checking agent focused on finding contradicting evidence. Present the strongest evidence that the claim is FALSE.'
- Debate format (2 rounds + consensus):
* Round 1: Both agents provide initial arguments
* Round 2: Both agents respond to the other's arguments
* Consensus: Agents must agree on final verdict (TRUE/FALSE/PARTIALLY TRUE)
- Store full conversation and final consensus verdict

EVALUATION:
1. For each approach, calculate:
- Accuracy (% correct verdicts)
- Precision/Recall for each class
- F1-score
- Inter-agent agreement rate (for debate protocol)

2. Statistical Analysis:
- Use bootstrap resampling to compare approaches
- Calculate 95% confidence intervals
- Report p-values for baseline vs experimental comparisons

3. Visualization:
- Generate confusion matrices
- Plot accuracy comparisons
- Create agreement rate visualizations

OUTPUT FILES:
1. results.json: Contains all metrics and statistical tests
2. debate_logs.json: Full conversation histories
3. confusion_matrices.pdf: Visualization of results
4. statistical_analysis.txt: Detailed statistical findings

EXECUTION ORDER:
1. Start with MINI_PILOT (10 claims)
2. If successful, proceed to PILOT (100 claims)
3. Stop after PILOT - await human verification before FULL_EXPERIMENT

ERROR HANDLING:
- Log all LLM calls and responses
- Implement timeout handling for LLM calls (retry up to 3 times)
- Save intermediate results after each claim

REQUIRED OUTPUT FORMAT:
- All verdicts must be exactly 'TRUE', 'FALSE', or 'PARTIALLY TRUE'
- JSON output must include claim text, ground truth, and predictions from all methods
- Statistical tests must include effect sizes and confidence intervals
