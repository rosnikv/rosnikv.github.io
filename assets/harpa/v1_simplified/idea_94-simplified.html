ID: idea_94-simplified

simple-metric-prompt-tuning

Hypothesis

Optimizing prompts using different evaluation metrics (accuracy, F1-score, precision) will lead to varying performance across different sentiment analysis subtasks, with certain metrics producing better results for specific subtasks.

Elements

  • Independent variable: Evaluation metric used for prompt optimization (accuracy, F1-score, precision)
  • Dependent variable: Sentiment analysis performance (measured by accuracy, F1-score, and qualitative error analysis)
  • Comparison groups: Prompts optimized using different evaluation metrics
  • Baseline/control: Default prompt without optimization
  • Context/setting: Sentiment analysis on product reviews dataset
  • Assumptions: Different evaluation metrics will prioritize different aspects of model performance
  • Relationship type: Causation
  • Population: English language product reviews
  • Timeframe: Not time-dependent
  • Measurement method: Quantitative performance metrics and qualitative error analysis

Description

This research explores a simplified approach to enhancing sentiment analysis by focusing on a single aspect of prompt optimization: metric-guided prompt tuning. Rather than implementing a fully dynamic system, this project will investigate how different evaluation metrics influence the effectiveness of prompt configurations for sentiment analysis tasks. The research will compare the performance of sentiment analysis models using prompts optimized with different fixed metrics (e.g., accuracy, F1-score, precision) to determine which metrics lead to better performance for specific sentiment analysis subtasks. This approach provides valuable insights into the relationship between evaluation metrics and prompt effectiveness while being more manageable for researchers with limited resources.

Operationalization

Please create an experiment to investigate how different evaluation metrics influence prompt optimization for sentiment analysis. The experiment should follow these specifications:

1. PILOT MODE SETTINGS:
- Create a global variable PILOT_MODE that can be set to 'MINI_PILOT', 'PILOT', or 'FULL_EXPERIMENT'
- MINI_PILOT: Use 50 reviews total (25 positive, 25 negative). Split: 30 train, 10 validation, 10 test
- PILOT: Use 500 reviews total (250 positive, 250 negative). Split: 350 train, 75 validation, 75 test
- FULL_EXPERIMENT: Use 10000 reviews (5000 each). Split: 7000 train, 1500 validation, 1500 test

2. DATASET PREPARATION:
- Use the Huggingface Datasets API to load the Amazon product reviews dataset
- Filter to only include clearly positive (5 star) or negative (1 star) reviews for a clear binary task
- Ensure balanced distribution between positive/negative
- Create train/validation/test splits according to PILOT_MODE settings

3. BASELINE IMPLEMENTATION:
- Use gpt-4o-mini as the model (per special conditioning instructions)
- Create a baseline prompt: "Is the following product review positive or negative? Answer with only 'positive' or 'negative'. Review: [REVIEW]"
- Run this baseline on the validation set
- Store results including the review text, true label, predicted label

4. PROMPT OPTIMIZATION:
- Create 5 different prompt variations, such as:
a. "Analyze the sentiment of this product review. Respond with only 'positive' or 'negative': [REVIEW]"
b. "Rate this product review as either 'positive' or 'negative'. Review: [REVIEW]"
c. "What is the sentiment of this customer review? Answer only 'positive' or 'negative': [REVIEW]"
d. "Determine if this review expresses satisfaction (answer 'positive') or dissatisfaction (answer 'negative'): [REVIEW]"
e. "Based on this product review, was the customer happy ('positive') or unhappy ('negative')? Review: [REVIEW]"
- Test each prompt variation on the validation set
- Create three separate optimized prompts by selecting the best performing prompt according to:
a. Accuracy (correct predictions / total predictions)
b. F1-score (harmonic mean of precision and recall)
c. Precision (true positives / (true positives + false positives))

5. EVALUATION:
- Test the baseline and three optimized prompts on the test set
- Calculate accuracy, F1-score, precision, and recall for each
- Use bootstrap resampling to determine if differences between prompts are significant
- Create a confusion matrix for each prompt
- For each prompt, identify 10 misclassified examples and store them for error analysis

6. VISUALIZATION:
- Create a bar plot comparing the performance metrics across prompts
- Create confusion matrices as heatmaps for each prompt

7. OUTPUT:
- Save all results to a JSON file including:
* All prompt variations tested
* Performance metrics for each prompt
* Statistical significance results
* Misclassified examples
- Generate a brief report summarizing the findings

8. EXECUTION ORDER:
- First run with MINI_PILOT to verify code functionality
- If successful, run with PILOT to verify approach validity
- Stop before FULL_EXPERIMENT for human verification

Notes:
- Use appropriate error handling and logging throughout
- Save intermediate results in case of interruption
- Report progress regularly through the logger
- All prompts must enforce the 'positive'/'negative' only response format to ensure clean data collection
