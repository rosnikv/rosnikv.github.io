ID: idea_53-simplified

simple-memory-web-agent

Hypothesis

Web agents augmented with a simple memory mechanism will demonstrate higher success rates on multi-step web tasks compared to baseline agents without memory, as measured by task completion rates and efficiency metrics.

Elements

  • Independent variable: Presence of a simple memory mechanism in the web agent
  • Dependent variable: Task success rates and efficiency metrics
  • Comparison groups: Web agents with memory vs. web agents without memory
  • Baseline/control: Web agents without memory
  • Context/setting: Predefined multi-step web tasks
  • Assumptions: The tasks selected require memory of previous steps to complete efficiently
  • Relationship type: Causation
  • Population: LLM-based web agents
  • Timeframe: Not specified
  • Measurement method: Task completion rates and efficiency metrics (number of steps, time to completion)

Description

This research investigates how adding a simple memory mechanism to LLM-based web agents affects their performance on multi-step web tasks. Rather than implementing complex dynamic task decomposition, this study focuses on comparing a baseline web agent against one augmented with a straightforward memory component that stores and retrieves information from previous steps. The memory-augmented agent will maintain a history of actions and observations that can be referenced during task execution. The research will evaluate both agents on a small set of predefined web tasks that require remembering information across multiple steps, such as comparing product information across different pages or filling out forms with previously gathered data.

Implementation Design

This experiment compares the performance of two LLM-based web agents on multi-step web tasks: a baseline agent without memory and an agent augmented with a simple memory mechanism.

1. Implementation:
a. Baseline Agent:
- Implement a web agent using an LLM (e.g., GPT-3.5-turbo) that can navigate web pages, extract information, and perform actions like clicking buttons and filling forms.
- The agent should receive the current observation (screenshot or HTML) and task description as input, and output the next action to take.
- Use a simple prompt template that includes the task description, current observation, and available actions.

b. Memory-Augmented Agent:
- Extend the baseline agent by adding a simple memory component that stores previous observations and actions.
- Implement the memory as a list of past observations and actions, limited to the most recent N steps (e.g., N=5).
- Modify the prompt template to include the memory component, allowing the agent to reference previous steps.

c. Web Interaction Framework:
- Use Selenium or Playwright to enable the agents to interact with web pages.
- Implement functions for common web actions: clicking elements, typing text, navigating pages, and extracting information.

2. Data and Tasks:
a. Create a set of 5-10 multi-step web tasks that require memory of previous steps, such as:
- Compare prices of a specific product across 3 different e-commerce websites.
- Fill out a multi-page form where information from the first page is needed on subsequent pages.
- Search for information across multiple pages and compile it into a summary.
b. For each task, define clear success criteria and subtasks.
c. Use publicly accessible websites for these tasks to avoid authentication issues.

3. Evaluation:
a. Run each agent on each task 3 times to account for variability.
b. Record the following metrics for each run:
- Task completion (binary: success/failure)
- Number of steps taken
- Time to completion
- Subtask completion rates
c. Calculate average performance metrics across all runs.
d. Perform statistical analysis (t-tests) to determine if differences between agents are significant.
e. Conduct error analysis by categorizing the types of failures for each agent.

4. Output and Reporting:
a. Save all experimental data in CSV format, including:
- Agent type (baseline or memory-augmented)
- Task ID and description
- Run number
- Success/failure status
- Number of steps taken
- Time to completion
- Subtask completion status
b. Generate visualizations comparing the performance of both agents:
- Bar charts for task completion rates
- Box plots for efficiency metrics
c. Write a detailed report including:
- Experimental setup and methodology
- Quantitative results with statistical analysis
- Qualitative analysis of agent behaviors
- Discussion of when and why memory helps or doesn't help
- Limitations and future work

The experiment should be designed to run on a standard laptop with internet connection, and should not require specialized hardware or extensive computational resources.

Operationalization

Please implement an experiment comparing a baseline web agent against a memory-augmented web agent on multi-step web tasks. The experiment should follow these specifications:

1. PILOT MODES:
Implement a global variable PILOT_MODE that can be set to 'MINI_PILOT', 'PILOT', or 'FULL_EXPERIMENT'. The settings should work as follows:

MINI_PILOT:
- Use 2 tasks: (1) Compare prices of a specific laptop model across 2 e-commerce sites, (2) Fill out a 2-page form where info from page 1 is needed on page 2
- Run each task 2 times per agent
- Maximum 10 steps per task
- Use training websites: amazon.com and bestbuy.com for price comparison, and httpbin.org/forms/post for form filling

PILOT:
- Use 5 tasks: Add 3 more tasks including product feature comparison, multi-page navigation, and information gathering
- Run each task 3 times per agent
- Maximum 20 steps per task
- Add additional training websites like walmart.com, target.com

FULL_EXPERIMENT:
- Use 10 tasks with more complex scenarios
- Run each task 5 times per agent
- Maximum 40 steps per task
- Use full range of websites including newegg.com, officedepot.com

2. AGENT IMPLEMENTATION:

Baseline Agent:
- Use the gpt-4o-mini model
- Input: Current webpage HTML/text, task description
- Output: Next action to take (click, type, navigate)
- No memory of previous steps

Memory-Augmented Agent:
- Use the gpt-4o-mini model
- Input: Current webpage HTML/text, task description, plus last 3 steps of history (observations and actions)
- Output: Next action to take
- Implement using the Memory Agent Example codeblock

3. EVALUATION METRICS:

For each task run:
- Success/Failure (binary)
- Number of steps taken
- Time to completion
- Subtask completion (e.g., for price comparison: found price 1, found price 2, compared prices)

4. DATA COLLECTION:

Create a CSV file with columns:
- agent_type (baseline/memory)
- task_id
- task_name
- run_number
- success (0/1)
- steps_taken
- time_taken
- subtasks_completed

5. ANALYSIS:

- Calculate mean success rate, steps, and time for each agent
- Use bootstrap resampling to compare performance differences
- Generate plots:
* Bar chart of success rates
* Box plot of steps taken
* Box plot of completion times

6. EXECUTION ORDER:

1. Run MINI_PILOT first
2. If successful, run PILOT
3. Stop after PILOT (do not run FULL_EXPERIMENT)
4. Generate analysis and plots for both MINI_PILOT and PILOT
5. Save all results in a 'results' directory with subdirectories for each pilot mode

7. ERROR HANDLING:

- Log all actions, errors, and responses
- Implement timeouts for web interactions (30 seconds)
- Handle common web errors (element not found, page load failures)
- Save screenshots on failures for debugging

8. REQUIRED OUTPUT:

- CSV files with raw data
- Statistical analysis results
- Plots as PDF files
- Log files with full execution traces
- Summary report in markdown format

Please implement this experiment starting with the MINI_PILOT mode. The experiment should stop after completing the PILOT mode, allowing for human verification before proceeding to FULL_EXPERIMENT.
