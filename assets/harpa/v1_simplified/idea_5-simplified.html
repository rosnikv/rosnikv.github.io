ID: idea_5-simplified

simplified-gpl-retrieval

Hypothesis

A simplified query generation approach using pre-trained language models will improve nDCG@10 performance in scientific article retrieval compared to a basic BM25 baseline.

Elements

  • Independent variable: Query generation strategy (basic vs. enhanced)
  • Dependent variable: Retrieval performance
  • Comparison groups: Basic BM25 retrieval vs. GPL-enhanced retrieval
  • Baseline/control: BM25 retrieval without query generation
  • Context/setting: Scientific article retrieval on a small domain-specific dataset
  • Assumptions: Pre-trained language models can generate relevant queries for scientific articles
  • Relationship type: Causation
  • Population: Scientific articles in a specific domain
  • Timeframe: Not applicable
  • Measurement method: nDCG@10 performance

Description

This research explores a simplified approach to improving scientific article retrieval by enhancing the Generative Pseudo Labeling (GPL) process. Instead of the full TSDAE integration, this study focuses on using a pre-trained language model to generate synthetic queries for scientific articles and evaluating how different query generation strategies affect retrieval performance. The research will use a small, manageable dataset of scientific articles from a specific domain (e.g., computer science or medicine) and implement a basic retrieval system using existing libraries. The goal is to determine whether simple modifications to the query generation process can improve retrieval performance without requiring extensive computational resources or complex model architectures.

Operationalization

Please implement a pilot experiment comparing BM25 baseline retrieval against a GPL-enhanced retrieval system for scientific articles. The experiment should support three modes (PILOT_MODE): MINI_PILOT, PILOT, and FULL_EXPERIMENT.

Data Requirements by Mode:
MINI_PILOT:
- Use 20 scientific articles from the ACL Anthology dataset (via Huggingface)
- Generate 2 test queries
- Generate 2 synthetic queries per article
- Maximum 10-minute runtime target

PILOT:
- Use 100 scientific articles
- Generate 10 test queries
- Generate 3 synthetic queries per article
- Maximum 1-hour runtime target

FULL_EXPERIMENT:
- Use 500 scientific articles
- Generate 20 test queries
- Generate 5 synthetic queries per article
- Runtime as needed

Implementation Steps:

1. Setup and Configuration:
- Initialize logger
- Set random seeds (use 42, 123, 456 for three runs)
- Configure gpt-4o-mini as the LLM through the proxy server
- Create directories for storing results

2. Data Preparation:
- Use Huggingface Datasets to load ACL Anthology papers
- Extract title and abstract for each paper
- Split into train/dev/test sets (60/20/20)
- For MINI_PILOT, use only first N papers from training set

3. Baseline Implementation:
- Implement BM25 retrieval (using scikit-learn's TfidfVectorizer as BM25 approximation)
- Index papers using titles and abstracts
- Run test queries through baseline system
- Calculate and store nDCG@10 scores

4. Query Generation:
- For each paper, use gpt-4o-mini to generate synthetic queries
- Basic strategy prompt: "Generate a search query that would help find this scientific paper, based on its title and abstract: [TITLE] [ABSTRACT]"
- Enhanced strategy prompt: "Generate a natural question that this scientific paper answers, based on its title and abstract: [TITLE] [ABSTRACT]"

5. GPL-Enhanced Retrieval:
- Create pseudo-relevance judgments (paper is relevant to its generated queries)
- Use generated queries to create training data
- Train a simple retrieval model using TfidfVectorizer and cosine similarity
- Evaluate on test queries

6. Evaluation:
- Calculate nDCG@10 for both systems
- Use bootstrap resampling to compare performance
- Generate line plots showing performance across different query types
- Log all results, including example queries and their performance

7. Output Requirements:
- Save all generated queries to JSON files
- Create performance comparison plots
- Generate detailed logs of all operations
- Output statistical comparison results
- Save summary results in a structured format

Specific Implementation Notes:
1. Use gpt-4o-mini for all LLM operations
2. Run MINI_PILOT first, verify results
3. If successful, run PILOT
4. Stop before FULL_EXPERIMENT for human verification
5. Log all random seeds and configuration parameters
6. Include error handling and progress reporting
7. Save intermediate results frequently

Success Criteria:
1. MINI_PILOT completes within 10 minutes
2. PILOT completes within 1 hour
3. All evaluation metrics are properly calculated
4. Statistical comparisons are performed correctly
5. Results are reproducible with same random seeds
