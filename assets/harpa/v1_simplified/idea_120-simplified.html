ID: idea_120-simplified

simple-discriminator-guidance

Hypothesis

A small language model guided by a binary classifier that evaluates reasoning step correctness will achieve higher accuracy on arithmetic reasoning tasks compared to the same model without discriminator guidance.

Elements

  • Independent variable: Presence or absence of binary classifier guidance
  • Dependent variable: Accuracy on arithmetic reasoning tasks
  • Comparison groups: Small language model with discriminator guidance vs. same model without guidance
  • Baseline/control: Small language model without discriminator guidance
  • Context/setting: Simple arithmetic reasoning tasks from a subset of GSM8K
  • Assumptions: The binary classifier can be effectively trained on a small dataset of labeled reasoning steps
  • Relationship type: Causation
  • Population: Small language models (e.g., 7B parameters)
  • Timeframe: Not specified
  • Measurement method: Comparison of task accuracy

Description

This research investigates the effectiveness of a simple binary classifier discriminator to guide reasoning in small language models on arithmetic problems. Rather than implementing a complex hybrid system with zero-shot prompting and distillation, this study focuses on developing a straightforward binary classifier that evaluates whether individual reasoning steps are correct or incorrect. The classifier will be trained on a small, manually labeled dataset of arithmetic reasoning steps from the GSM8K dataset. The research will explore whether providing this binary feedback to a small language model (e.g., 7B parameters) can improve its reasoning accuracy on simple arithmetic problems compared to the same model without discriminator guidance. This approach reduces the complexity of the original research idea while still exploring the core concept of using discriminator feedback to enhance reasoning capabilities in smaller models.

Operationalization

Please implement an experiment to evaluate whether a simple binary classifier can improve reasoning accuracy in small language models on arithmetic problems. The experiment should be implemented in three pilot phases (MINI_PILOT, PILOT, FULL_EXPERIMENT), controlled by a global PILOT_MODE variable.

Phase Specifications:
1. MINI_PILOT:
- Use 10 simple arithmetic problems from GSM8K training set
- Split: 5 for training classifier, 5 for testing
- Maximum 3 reasoning steps per problem
- Maximum 2 retries if step classified as incorrect
- Run time: ~5-10 minutes

2. PILOT:
- Use 100 simple arithmetic problems from GSM8K
- Split: 50 training (from training set), 50 testing (from dev set)
- Maximum 5 reasoning steps per problem
- Maximum 3 retries if step classified as incorrect
- Run time: ~1-2 hours

3. FULL_EXPERIMENT (not to be run automatically - requires human verification):
- Use 1000 problems from GSM8K
- Split: 500 training, 250 dev, 250 test
- No limit on reasoning steps
- Maximum 5 retries if step classified as incorrect

Implementation Steps:

1. Dataset Preparation:
- Use Huggingface Datasets API to load GSM8K
- Filter for simple arithmetic (containing only +,-,*,/)
- Split according to pilot phase specifications

2. Generate Training Data:
- Use gpt-4o-mini to generate reasoning steps for training problems
- Format: Each step should be a single arithmetic operation
- Example: '12 + 5 = 17' or 'multiply 6 by 3 to get 18'
- Manually label each step as correct(1)/incorrect(0)
- Store labeled data as JSON: {"step": "text", "label": 1/0}

3. Train Binary Classifier:
- Use gpt-4o-mini to get embeddings for each reasoning step
- Train logistic regression classifier on embeddings
- Evaluate precision, recall, F1-score on validation set
- Save classifier for reuse

4. Implement Three Conditions:
a) Baseline: gpt-4o-mini with standard prompting
b) Chain-of-thought baseline: gpt-4o-mini with CoT prompting
c) Experimental: gpt-4o-mini with classifier guidance

5. Run Evaluation:
- For each problem in test set:
* Run all three conditions
* Record full reasoning chains
* Record final answers
* Calculate accuracy
- Use bootstrap resampling to test significance
- Generate plots comparing performance

6. Logging and Output:
- Log all LLM calls, responses, and classifier decisions
- Save all reasoning chains and final answers
- Generate summary statistics and plots
- Create error analysis report

Specific Requirements:
1. Use gpt-4o-mini for all LLM calls
2. Run MINI_PILOT first
3. If successful, run PILOT
4. Stop before FULL_EXPERIMENT
5. Save all intermediate results
6. Generate plots of accuracy by condition
7. Perform bootstrap significance testing

Expected Output Format:
1. Results directory containing:
- Labeled training data
- Trained classifier model
- Full reasoning chains for all conditions
- Accuracy metrics and statistical tests
- Performance plots
- Error analysis report

Success Criteria:
1. MINI_PILOT completes without errors
2. PILOT shows clear comparison between conditions
3. Statistical tests properly implemented
4. All results properly logged and saved
