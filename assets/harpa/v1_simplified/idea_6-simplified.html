ID: idea_6-simplified

simplified-irct-qa-coherence

Hypothesis

A simplified implementation of Interleaved Retrieval with Chain-of-Thought (IRCoT) will improve explanation coherence and factual accuracy compared to standard Chain-of-Thought reasoning in question answering tasks on a small, curated dataset.

Elements

  • Independent variable: Implementation of simplified IRCoT vs. standard Chain-of-Thought
  • Dependent variable: Explanation coherence and factual accuracy
  • Comparison groups: Simplified IRCoT approach vs. standard Chain-of-Thought
  • Baseline/control: Standard Chain-of-Thought reasoning without interleaved retrieval
  • Context/setting: Question answering on a small, curated dataset
  • Assumptions: The retrieval system can provide relevant information for the reasoning steps
  • Relationship type: Causation
  • Population: A curated set of 50-100 factual questions requiring multi-step reasoning
  • Timeframe: Not applicable
  • Measurement method: Manual evaluation of coherence and automated evaluation of factual accuracy

Description

This research explores a simplified approach to enhancing explanation coherence in question answering systems by implementing a basic version of Interleaved Retrieval with Chain-of-Thought (IRCoT). Instead of combining IRCoT with Information Bottleneck techniques, this project focuses solely on implementing a lightweight IRCoT approach that interleaves simple retrieval steps with reasoning steps. The study will examine how this basic implementation affects the coherence and factual accuracy of explanations in a controlled question answering setting using a small, curated dataset. This simplified approach allows for meaningful research with limited computational resources while still addressing an important aspect of the original research question.

Operationalization

Please implement a pilot experiment comparing standard Chain-of-Thought (CoT) versus Interleaved Retrieval Chain-of-Thought (IRCoT) for question answering. The experiment should follow these specifications:

1. EXPERIMENT MODES
Implement a global variable PILOT_MODE that can be set to one of: ['MINI_PILOT', 'PILOT', 'FULL_EXPERIMENT']
- MINI_PILOT: Use 5 questions, 2 reasoning steps per question, max 3 retrieved passages per step
- PILOT: Use 25 questions, 3 reasoning steps per question, max 5 retrieved passages per step
- FULL_EXPERIMENT: Use 100 questions, 3 reasoning steps per question, max 5 retrieved passages per step

2. DATA PREPARATION
- Use the Data generation with LLM codeblock to create multi-step reasoning questions
- For MINI_PILOT, generate 5 questions about basic science facts
- For PILOT, generate 25 questions across science/history/geography
- Questions should require 2-3 reasoning steps to answer
- Store reference answers with key facts for evaluation

3. KNOWLEDGE SOURCE
- Use Huggingface Datasets to load a subset of Wikipedia articles
- For MINI_PILOT: Use only 100 Wikipedia articles
- For PILOT: Use 1000 Wikipedia articles
- Create embeddings for each paragraph using the LLM API's embedding endpoint

4. BASELINE IMPLEMENTATION (Standard CoT)
- Use the LLM proxy server codeblock
- Use gpt-4o-mini as specified
- Prompt template: 'Question: {question}\nPlease think through this step-by-step:\n1.\n2.\n3.\nFinal Answer:'

5. EXPERIMENTAL IMPLEMENTATION (IRCoT)
- For each reasoning step:
a. Generate search query using LLM
b. Retrieve relevant Wikipedia passages
c. Incorporate retrieved info into next reasoning step
- Use same base model (gpt-4o-mini)
- Maximum 3 reasoning steps

6. EVALUATION
- For each question, collect:
a. Coherence score (1-5 scale)
b. Factual accuracy (% correct claims)
c. Number of reasoning steps used
d. Time taken

7. ANALYSIS
- Use Non-parametric Bootstrap Resampling to compare:
a. Average coherence scores
b. Average factual accuracy
c. Average number of steps
- Generate plots using MatPlotLib Line Plot showing:
a. Coherence scores distribution
b. Factual accuracy distribution
c. Performance over number of reasoning steps

8. LOGGING
- Use Logger/Debugging for all major steps
- Log all LLM interactions
- Log retrieval steps and results
- Log evaluation scores

9. OUTPUT FORMAT
Store results in JSON format:
{
'question_id': str,
'question': str,
'condition': 'CoT' or 'IRCoT',
'reasoning_steps': List[str],
'retrieved_passages': List[List[str]], # For IRCoT only
'final_answer': str,
'metrics': {
'coherence': float,
'factual_accuracy': float,
'num_steps': int,
'time_taken': float
}
}

10. EXECUTION ORDER
1. Run MINI_PILOT first
2. If successful, run PILOT
3. Stop after PILOT (await human verification)

Please implement this experiment, ensuring proper error handling and logging throughout. The system should gracefully handle API failures and maintain partial results.
