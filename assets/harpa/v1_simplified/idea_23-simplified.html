ID: idea_23-simplified

monolingual-legal-judgment-prediction

Hypothesis

A fine-tuned transformer model on a single-language subset of the FSCS Cases Dataset will achieve significantly higher legal judgment prediction accuracy, as measured by F1-score, compared to a TF-IDF with logistic regression baseline.

Elements

  • Independent variable: Model type (fine-tuned transformer vs. TF-IDF with logistic regression)
  • Dependent variable: Legal judgment prediction accuracy
  • Comparison groups: Fine-tuned transformer model vs. TF-IDF with logistic regression baseline
  • Baseline/control: TF-IDF with logistic regression model
  • Context/setting: Single-language subset of FSCS Cases Dataset (e.g., German only)
  • Assumptions: Transformer models can effectively capture legal reasoning in a single language context
  • Relationship type: Causation
  • Population: Legal judgments in a single language
  • Timeframe: Not specified
  • Measurement method: F1-score

Description

This research aims to develop a simplified legal judgment prediction system focusing on a single language subset of the FSCS Cases Dataset. Rather than implementing complex hierarchical transformers with cross-task consistency constraints, this project will explore the effectiveness of a standard transformer model (such as BERT or RoBERTa) fine-tuned specifically for legal judgment prediction. The research will focus on extracting key legal facts from case documents and predicting judgment outcomes, with particular attention to the model's ability to identify relevant legal concepts. The project will compare the performance of the fine-tuned model against a simple baseline (such as TF-IDF with logistic regression) to demonstrate the value of transformer-based approaches in legal text analysis. This simplified approach maintains scientific rigor while being feasible for a student researcher with limited computational resources.

Operationalization

Please implement a legal judgment prediction experiment that compares a transformer-based model against a TF-IDF/logistic regression baseline. The experiment should follow these specifications:

1. PILOT MODE SETTINGS:
Create a global variable PILOT_MODE that can be set to one of:
- MINI_PILOT: Use 50 cases (40 train/10 test)
- PILOT: Use 500 cases (400 train/100 test)
- FULL_EXPERIMENT: Use all 5000 cases (4000 train/1000 test)

Initially set PILOT_MODE = 'MINI_PILOT'

2. DATA PREPARATION:
- Use the Huggingface Datasets API to load the German subset of the FSCS Cases Dataset
- Filter to include only cases with binary outcomes (granted/denied)
- Based on PILOT_MODE, randomly sample the appropriate number of cases
- Split into train/test sets (80/20)
- Clean text: Remove irrelevant sections, standardize formatting
- Log the class distribution in both splits

3. BASELINE MODEL (TF-IDF + Logistic Regression):
- Parameters for TF-IDF:
* max_features=10000 (1000 for MINI_PILOT, 5000 for PILOT)
* min_df=2 (2 for MINI_PILOT, 3 for PILOT)
* ngram_range=(1,2)
- Train logistic regression with L2 regularization
- Use 3-fold cross-validation (MINI_PILOT), 5-fold (PILOT/FULL)

4. TRANSFORMER MODEL:
- Use gpt-4o-mini for all LLM calls
- Load German BERT (bert-base-german-cased)
- Implement fine-tuning with:
* max_length=512
* batch_size=4 (MINI_PILOT), 8 (PILOT), 16 (FULL)
* learning_rate=2e-5
* epochs=3 (MINI_PILOT), 5 (PILOT), 10 (FULL)
* early_stopping on validation loss

5. EVALUATION:
- Calculate metrics:
* F1-score (primary)
* Accuracy, Precision, Recall
- Use bootstrap resampling (100 iterations for MINI_PILOT, 500 for PILOT, 1000 for FULL)
- Create plots:
* Confusion matrices
* ROC curves
* Top features from baseline model

6. LOGGING AND OUTPUT:
- Log all hyperparameters and configuration
- Save preprocessed data splits
- Save model checkpoints
- Generate summary tables of results
- Create visualization plots

7. ERROR ANALYSIS:
- Log examples where:
* Both models correct/incorrect
* Only transformer correct
* Only baseline correct

IMPORTANT NOTES:
1. Start with MINI_PILOT mode
2. If successful, proceed to PILOT mode
3. Stop after PILOT mode - do not proceed to FULL_EXPERIMENT
4. Log all steps and decisions
5. Save all intermediate results

Success Criteria:
1. Both models successfully train
2. Performance metrics are calculated
3. Statistical comparison completed
4. Results are reproducible
5. Error analysis provides insights into model differences
