ID: idea_133-simplified

simplified-mt5-fact-verification

Hypothesis

Translating non-English claims from the X-Fact dataset to English using mT5 before applying an English language model for verification will yield higher F1-scores compared to direct verification in the original languages.

Elements

  • Independent variable: Translation approach (translate-then-verify vs. verify-in-original-language)
  • Dependent variable: Fact verification accuracy
  • Comparison groups: Translate-then-verify approach vs. verify-in-original-language approach
  • Baseline/control: Verify-in-original-language approach
  • Context/setting: A subset of the X-Fact dataset (3-5 languages)
  • Assumptions: ['Pre-trained models are accessible via APIs', 'X-Fact dataset is publicly available']
  • Relationship type: Causation
  • Population: ['Claims from selected languages in the X-Fact dataset']
  • Timeframe: ['Short-term experiment (1-2 months)']
  • Measurement method: F1-score

Description

This research explores a simplified approach to cross-lingual fact verification by using mT5 to translate claims from the X-Fact dataset into English, followed by applying a pre-trained English language model for verification. Rather than implementing complex zero-shot prompting with self-consistency, this study focuses on comparing the effectiveness of translation-then-verification versus direct multilingual verification. The research will evaluate whether translating non-English claims to English before verification improves accuracy compared to verifying claims in their original languages. This approach reduces implementation complexity while still addressing an important question in cross-lingual fact verification.

Operationalization

Please implement a cross-lingual fact verification experiment comparing translation-then-verify versus direct verification approaches. The experiment should be implemented in three pilot phases (MINI_PILOT, PILOT, and FULL_EXPERIMENT), controlled by a global PILOT_MODE variable.

Phase Specifications:
1. MINI_PILOT:
- Use only 2 languages (Spanish and German)
- Sample 10 claims per language (5 TRUE, 5 FALSE)
- Maximum 20 total claims for quick verification
- Use training set data only

2. PILOT:
- Use 3 languages (Spanish, German, French)
- Sample 50 claims per language (25 TRUE, 25 FALSE)
- Maximum 150 total claims
- Use training set for training, dev set for evaluation

3. FULL_EXPERIMENT (not to be run initially):
- Use 5 languages (Spanish, German, French, Arabic, Chinese)
- Use full balanced dataset
- Proper train/dev/test splits

Implementation Steps:

1. Dataset Preparation:
- Use Huggingface Datasets API to load X-Fact dataset
- Create balanced subsets based on PILOT_MODE
- Log dataset statistics

2. Model Setup:
- Use gpt-4o-mini through the LLM proxy for both translation and verification
- For translation prompt: "Translate the following [LANGUAGE] text to English, preserving its meaning: [TEXT]"
- For verification prompt: "Is the following claim TRUE or FALSE? Respond with only TRUE or FALSE. Claim: [CLAIM]"

3. Experiment Pipeline:
a) Baseline (verify-in-original):
- Format each claim in prompt template
- Get verification directly using gpt-4o-mini
- Store predictions

b) Experimental (translate-then-verify):
- Translate each claim to English
- Format translated claim in verification prompt
- Get verification using gpt-4o-mini
- Store predictions

4. Evaluation:
- Calculate F1-score, precision, recall, accuracy for both approaches
- Use bootstrap resampling to test for significant differences
- Generate performance comparison plots
- Log all results

5. Output Requirements:
- Save all predictions and scores to CSV files
- Generate bar plots comparing metrics between approaches
- Create detailed log file of all operations
- Report statistical significance results

Specific Requirements:
1. Start with MINI_PILOT mode
2. If successful, proceed to PILOT mode
3. Stop before FULL_EXPERIMENT (await human verification)
4. Log all LLM calls and responses
5. Include error handling for API failures
6. Save intermediate results frequently

Expected Output Files:
1. predictions_{pilot_mode}.csv
2. metrics_{pilot_mode}.csv
3. statistical_tests_{pilot_mode}.txt
4. performance_plots_{pilot_mode}.pdf
5. experiment_log_{pilot_mode}.txt

Success Criteria:
1. All code runs without errors
2. Results are properly logged and saved
3. Statistical comparisons are performed
4. Visualizations are generated
5. Performance metrics are calculated correctly
