SHAP-Enhanced-Sentiment-Analysis

Hypothesis

Integrating SHAP feature attribution into a pre-trained sentiment analysis model will enhance interpretability by highlighting sentiment-bearing words and phrases that align with human intuition.

Elements

  • Independent variable: Application of SHAP feature attribution to sentiment analysis model predictions
  • Dependent variable: Interpretability of model predictions (measured through alignment with human-identified sentiment words)
  • Comparison groups: SHAP explanations vs. human annotations of sentiment-bearing words
  • Baseline/control: Pre-trained sentiment analysis model without SHAP explanations
  • Context/setting: Sentiment analysis on product reviews
  • Assumptions: SHAP values will highlight words that humans would also identify as sentiment-bearing
  • Relationship type: Correlation between SHAP-identified important features and human-identified sentiment words
  • Population: English product reviews from Amazon
  • Timeframe: Not time-dependent
  • Measurement method: Jaccard similarity between SHAP-highlighted words and human-annotated sentiment words

Description

This research investigates the impact of integrating SHAP (SHapley Additive exPlanations) feature attribution into a pre-trained sentiment analysis model to enhance interpretability. Rather than combining multiple complex techniques, this simplified approach focuses solely on applying SHAP to explain predictions of an existing sentiment classifier. The study will examine whether SHAP explanations align with human intuition about sentiment-bearing words and phrases, and whether these explanations can help identify model weaknesses. The research will use a small, well-curated dataset to demonstrate the value of interpretability techniques in natural language processing applications, particularly for sentiment analysis tasks.

Implementation Design

This experiment will investigate how SHAP feature attribution can enhance the interpretability of sentiment analysis models. Follow these steps:

1. Data Preparation:
- Select 100-200 product reviews from the Amazon Reviews dataset (use the 'Electronics' category for simplicity)
- Ensure a balanced distribution of positive and negative reviews
- Split the data into 80% for analysis and 20% for validation

2. Model Setup:
- Use a pre-trained BERT-based sentiment classifier (HuggingFace's 'distilbert-base-uncased-finetuned-sst-2-english')
- No additional fine-tuning is required

3. SHAP Implementation:
- Use the SHAP library to generate explanations for model predictions
- Specifically, implement the Partition SHAP explainer which works well with transformer models
- Generate SHAP values for each token in the input text
- Create visualizations that highlight the contribution of each word to the sentiment prediction

4. Human Annotation:
- Have 2-3 researchers independently annotate sentiment-bearing words in the validation set
- Create a gold standard by taking the union of annotations where at least 2 annotators agree

5. Evaluation:
- Calculate Jaccard similarity between SHAP-highlighted words (top 20% by absolute SHAP value) and human-annotated words
- Perform qualitative analysis of cases where SHAP and human annotations differ significantly
- Identify patterns in model errors by examining SHAP explanations for incorrectly classified reviews

6. Baseline Comparison:
- Implement a simple word-frequency based approach that highlights words based on their TF-IDF scores
- Compare the Jaccard similarity of this approach against SHAP

7. Output Generation:
- Save SHAP visualizations for all reviews in the validation set
- Generate a CSV file with review text, model prediction, ground truth, SHAP-highlighted words, human-annotated words, and Jaccard similarity
- Create summary statistics for the alignment between SHAP and human annotations
- Document patterns of model errors identified through SHAP analysis

8. Reporting:
- Create visualizations comparing SHAP-highlighted words with human annotations
- Report average Jaccard similarity and standard deviation
- Provide qualitative analysis of cases where SHAP provided particularly useful or misleading explanations
- Discuss implications for model trustworthiness and potential improvements

Operationalization

Please implement a SHAP-enhanced sentiment analysis experiment to investigate whether SHAP explanations align with human intuition about sentiment-bearing words. The experiment should support three modes (PILOT_MODE): MINI_PILOT, PILOT, and FULL_EXPERIMENT.

Data Sizes by Mode:
- MINI_PILOT: 10 reviews total (5 positive, 5 negative)
- PILOT: 100 reviews total (50 positive, 50 negative)
- FULL_EXPERIMENT: 1000 reviews total (500 positive, 500 negative)

Core Steps:

1. Dataset Preparation:
- Use the Huggingface Datasets API to load the Amazon reviews dataset
- Filter for Electronics category
- For each mode, select the appropriate number of reviews, ensuring balanced positive/negative distribution
- Split into 80% analysis, 20% validation

2. Model Setup:
- Load DistilBERT sentiment model ('distilbert-base-uncased-finetuned-sst-2-english')
- Generate baseline predictions for all reviews

3. SHAP Analysis:
- Apply SHAP to model predictions
- For each review, store the SHAP values for each token
- Generate visualizations highlighting word contributions

4. Human Annotation:
- Create a simple interface using the LLM proxy to collect human annotations
- For MINI_PILOT: 1 annotator
- For PILOT: 2 annotators
- For FULL_EXPERIMENT: 3 annotators
- Store annotations and calculate inter-annotator agreement

5. Evaluation:
- Calculate Jaccard similarity between SHAP-highlighted words (top 20%) and human annotations
- Generate TF-IDF baseline scores
- Use bootstrap resampling to compare SHAP vs TF-IDF performance
- Create visualization comparing distributions

6. Reporting:
- Generate summary statistics
- Create plots showing:
* Distribution of Jaccard similarities
* Comparison of SHAP vs TF-IDF performance
* Inter-annotator agreement (except MINI_PILOT)

Execution Flow:
1. Start with MINI_PILOT
2. If successful, proceed to PILOT
3. Stop after PILOT for human verification
4. (FULL_EXPERIMENT requires manual activation)
