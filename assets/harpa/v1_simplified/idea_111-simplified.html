ID: idea_111-simplified

simple-seq2seq-event-extraction

Hypothesis

Adding explicit event type information as prompts to a pretrained seq2seq model will improve precision and recall in event extraction tasks compared to using the basic seq2seq model alone on a small subset of the ACE05 dataset.

Elements

  • Independent variable: Addition of explicit event type information as prompts to the seq2seq model
  • Dependent variable: Precision and recall in event extraction tasks
  • Comparison groups: Basic seq2seq model vs. seq2seq model with event type prompts
  • Baseline/control: Basic seq2seq model without event type prompts
  • Context/setting: Small subset of the ACE05 dataset (100-200 examples)
  • Assumptions: Event type information can be effectively incorporated as explicit prompts
  • Relationship type: Causation
  • Population: Event extraction tasks on the ACE05 dataset subset
  • Timeframe: Not specified
  • Measurement method: Precision and recall metrics

Description

This research explores the effectiveness of a simple seq2seq model for event extraction on a subset of the ACE05 dataset. Rather than implementing complex task-aware representations, this project focuses on comparing a basic pretrained seq2seq model against a minimally enhanced version that incorporates event type information as explicit prompts. The study will evaluate whether providing explicit event type information in the input improves precision and recall in a limited-data scenario. This simplified approach maintains the core investigation of enhancing seq2seq models for event extraction while reducing implementation complexity and computational requirements.

Implementation Design

This experiment will compare a basic seq2seq model against one enhanced with event type prompts for event extraction. Follow these steps:

1. Data Preparation:
- Download the ACE05 dataset and extract a subset of 100-200 examples covering 3-5 common event types (e.g., Attack, Transport, Die, Meet, Arrest).
- Split this subset into training (70%), validation (15%), and test (15%) sets.
- Format the data for seq2seq input/output: input is the original text, output is a structured representation of events (e.g., "Event: Attack; Trigger: bombed; Agent: terrorists; Target: embassy").

2. Model Implementation:
- Baseline Model: Fine-tune a pretrained T5-small or BART-base model on the training data using the HuggingFace Transformers library. Input is the raw text, output is the structured event representation.
- Enhanced Model: Fine-tune the same pretrained model, but add explicit event type information to the input prompt (e.g., "Extract Attack events from: [original text]").
- Use the same hyperparameters for both models (learning rate, batch size, etc.).

3. Training:
- Train both models for 5-10 epochs or until validation performance plateaus.
- Save checkpoints and select the best model based on validation performance.

4. Evaluation:
- Evaluate both models on the test set.
- Calculate precision, recall, and F1 score for event extraction.
- Perform bootstrap resampling (1000 iterations) to assess statistical significance of performance differences.
- Analyze performance by event type to identify where the enhanced model performs better or worse.

5. Output and Analysis:
- Save the trained models and evaluation results.
- Generate a report with tables showing overall performance metrics and performance by event type.
- Include example predictions from both models to illustrate differences.
- Perform error analysis on 20 random examples where models differ in performance.

Implementation Notes:
- Use HuggingFace's Transformers and Datasets libraries for model implementation and data handling.
- Keep the seq2seq output format consistent between models for fair comparison.
- Log training progress and save intermediate results to allow for experiment resumption if needed.
