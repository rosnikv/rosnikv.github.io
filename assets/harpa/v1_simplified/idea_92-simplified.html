ID: idea_92-simplified

simplified-factual-editing

Hypothesis

A simplified implementation of KnowledgeEditor's hyper-network approach will improve a language model's factual accuracy on a curated test set, as measured by FActScore, compared to the unedited base model.

Elements

  • Independent variable: Application of simplified hyper-network weight editing
  • Dependent variable: Language model's factual accuracy
  • Comparison groups: Edited model vs. unedited base model
  • Baseline/control: Unedited base model
  • Context/setting: Curated test set of factual statements in a limited domain
  • Assumptions: The simplified hyper-network can effectively learn to predict weight updates
  • Relationship type: Causation
  • Population: Small to medium-sized language models (e.g., GPT-2 or DistilGPT-2)
  • Timeframe: Single point-in-time evaluation
  • Measurement method: FActScore on test set

Description

This research explores a simplified approach to enhancing factual accuracy in language models through targeted weight editing. Rather than implementing the full integration of hyper-networks with constrained optimization and inference-time prediction, this project focuses on implementing a basic version of KnowledgeEditor's hyper-network approach and evaluating its effectiveness on a small, curated dataset of factual statements. The research will investigate how a simplified hyper-network can be trained to predict weight updates for specific factual corrections, and measure the improvement in factual accuracy using FActScore on a limited domain of knowledge. This approach provides a more accessible entry point to understanding how neural network weights can be edited to correct factual information, while still offering insights into the broader challenge of maintaining factual accuracy in language models.

Operationalization

Please implement a simplified factual editing experiment that tests whether a basic hyper-network can improve factual accuracy in language models. The experiment should be implemented with three pilot modes (PILOT_MODE variable): MINI_PILOT, PILOT, and FULL_EXPERIMENT.

Pilot Settings:
1. MINI_PILOT:
- Dataset: 5 fact pairs (original/corrected) in geography domain (e.g., capital cities)
- 2 prompts per fact
- 5 unrelated facts for preservation testing
- 2 training runs with different random seeds
- Maximum 50 training steps per run

2. PILOT:
- Dataset: 20 fact pairs in geography domain
- 3 prompts per fact
- 10 unrelated facts for preservation testing
- 3 training runs with different random seeds
- Maximum 200 training steps per run

3. FULL_EXPERIMENT (not to be run initially):
- Dataset: 100 fact pairs across multiple domains
- 5-10 prompts per fact
- 30 unrelated facts for preservation testing
- 5 training runs with different random seeds
- Training until convergence

Implementation Steps:

1. Data Generation:
- Use gpt-4o-mini to generate the factual datasets for each pilot mode
- Format: JSON with fields for original_fact, corrected_fact, domain, and prompts
- Example fact pair: {"original_fact": "The capital of France is London", "corrected_fact": "The capital of France is Paris"}

2. Model Setup:
- Load DistilGPT-2 as the base model
- Implement simplified hyper-network (2-layer MLP)
- Input: Concatenated embeddings of original fact, corrected fact, and subset of model weights
- Output: Weight updates for final two layers of DistilGPT-2

3. Training Loop:
- For each fact pair:
a. Get base model response to prompts
b. Generate weight updates using hyper-network
c. Apply updates to create edited model
d. Evaluate edited model on prompts
e. Calculate loss based on:
- Accuracy of corrected fact generation
- Preservation of unrelated facts

4. Evaluation:
- Use gpt-4o-mini to implement simplified FActScore:
* Send model outputs to gpt-4o-mini
* Prompt: "Does the following text accurately state the fact: [fact]? Output only True or False."
- Metrics to track:
a. Edit success rate (% of correct fact generations)
b. FActScore
c. Preservation rate on unrelated facts

5. Baselines:
- Unedited base model (primary baseline)
- Fine-tuning baseline (secondary)
* Fine-tune model on fact pairs for same number of steps
* Use same evaluation metrics

6. Analysis and Visualization:
- Create line plots showing:
* Training loss over time
* Edit success rate vs preservation rate
* Comparison of metrics across approaches
- Use bootstrap resampling to compare approaches

7. Output Requirements:
- Save all generated datasets
- Log all hyperparameters and training details
- Save model checkpoints after each run
- Generate PDF report with all plots and statistics

Execution Order:
1. Run MINI_PILOT first
2. If successful, run PILOT
3. Stop after PILOT (await human verification before FULL_EXPERIMENT)

Success Criteria:
- MINI_PILOT: Verify basic functionality, any improvement over baseline
- PILOT: Statistically significant improvement over baseline in at least one metric

Please implement the experiment starting with MINI_PILOT mode, and ensure all logs and error handling are properly configured.
