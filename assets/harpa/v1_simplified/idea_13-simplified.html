ID: idea_13-simplified

template-enhanced-ner

Hypothesis

Template-based demonstrations that highlight entity-type relationships will significantly improve Named Entity Recognition performance in low-resource settings compared to standard fine-tuning approaches, as measured by F1 score.

Elements

  • Independent variable: Use of template-based demonstrations for NER
  • Dependent variable: Named Entity Recognition performance (F1 score)
  • Comparison groups: Template-based approach vs. standard fine-tuning
  • Baseline/control: Standard fine-tuning approach without templates
  • Context/setting: Low-resource settings (limited labeled data)
  • Assumptions: Templates that highlight entity-type relationships will help models better understand the NER task
  • Relationship type: Causation
  • Population: Text data from a selected domain (e.g., news articles or biomedical texts)
  • Timeframe: Not applicable
  • Measurement method: F1 score on test set

Description

This research investigates how template-based demonstrations can improve Named Entity Recognition (NER) performance in low-resource settings. Template-based demonstrations provide structured input formats that emphasize entity relationships, potentially aiding the model's understanding of entity types. The research will focus on designing effective templates that highlight entity-type relationships and testing their impact on NER performance using a small set of labeled data. By providing the model with clear patterns to follow through these templates, we hypothesize that it will better generalize from limited training examples. This approach addresses a practical challenge in NER: achieving reasonable performance when labeled data is scarce, which is common in specialized domains or low-resource languages.

Implementation Design

This experiment investigates whether template-based demonstrations can improve Named Entity Recognition (NER) in low-resource settings.

1. Implementation Details:
a. Dataset Preparation:
- Use the CoNLL-2003 English dataset, which contains four entity types: Person (PER), Organization (ORG), Location (LOC), and Miscellaneous (MISC).
- Create a low-resource setting by randomly sampling 10% of the training data (approximately 1,400 sentences).
- Use the standard development and test sets for validation and final evaluation.

b. Template Design:
- Design 5 different templates that highlight entity-type relationships. Examples include:
- "In this sentence, [SENTENCE], the entities are: [ENTITY] is a [TYPE]."
- "Find all entities in: [SENTENCE]. Entities: [ENTITY] - [TYPE], ..."
- "Identify the following types of entities in this text: Person, Organization, Location, Miscellaneous. Text: [SENTENCE]. Entities found: [ENTITY] is a [TYPE], ..."
- For each template, create training examples by filling in the [SENTENCE], [ENTITY], and [TYPE] placeholders with actual data from the training set.

c. Model Implementation:
- Use the Hugging Face Transformers library to load a pre-trained DistilBERT model.
- Implement two approaches:
- Baseline: Standard fine-tuning for token classification (NER) using the sampled training data.
- Template-based: Fine-tune the model using the template-formatted examples.
- For the template-based approach, frame NER as a text generation task where the model generates the entities and their types based on the template structure.

2. Experimental Setup:
a. Training:
- Train both models using the same hyperparameters: learning rate of 5e-5, batch size of 16, and 10 epochs.
- Use early stopping based on F1 score on the development set to prevent overfitting.
- Run each experiment with 3 different random seeds to account for variability.

b. Evaluation:
- Evaluate both models on the standard test set using the F1 score, precision, and recall.
- For the template-based approach, extract the predicted entities and their types from the generated text using regular expressions.
- Perform bootstrap resampling (1000 iterations) to determine if differences in performance are statistically significant.

3. Output and Analysis:
a. Save the following outputs:
- Trained model checkpoints for both approaches.
- Prediction results on the test set in JSON format, including the input text, ground truth entities, and predicted entities.
- Performance metrics (F1, precision, recall) for each entity type and overall.

b. Analysis:
- Compare the overall F1 scores between the baseline and template-based approach.
- Analyze performance differences across entity types to identify if templates help more for certain types.
- Conduct error analysis by categorizing errors (false positives, false negatives) and identifying patterns.
- Examine how performance varies with different templates to determine which template designs are most effective.

4. Reporting Results:
- Create tables showing performance metrics for both approaches, broken down by entity type.
- Generate visualizations comparing the performance of different templates.
- Summarize key findings, including whether templates significantly improve NER performance in the low-resource setting and which template designs work best.
- Discuss limitations and potential future work, such as testing on different domains or with other pre-trained models.

Please implement a Named Entity Recognition (NER) experiment comparing template-based demonstrations against standard fine-tuning in low-resource settings. The experiment should be implemented with three pilot modes (controlled by PILOT_MODE global variable):

PILOT MODES:
- MINI_PILOT: Use 50 sentences for training, 10 for validation. Maximum 3 epochs. One template design.
- PILOT: Use 200 sentences for training, 50 for validation. Maximum 5 epochs. Three template designs.
- FULL_EXPERIMENT: Use 1400 sentences (10% of CoNLL-2003) for training, full dev set for validation. Maximum 10 epochs. Five template designs.

DATASET:
1. Load the CoNLL-2003 English dataset using the Huggingface Datasets library
2. Filter for the pilot-appropriate number of sentences
3. Ensure sentences contain at least one named entity

MODELS AND TEMPLATES:
1. Use gpt-4o-mini as the base model for both conditions
2. Baseline Condition:
- Standard NER prompt format: 'Find all named entities in this text: [TEXT]'
- Model should output entities and their types
3. Experimental Condition (Template-based):
- Template 1: 'In this text: [TEXT]\nList each named entity and its type (Person, Organization, Location, or Miscellaneous): [ENTITY] is a [TYPE]'
- Template 2: 'Analyze this text for named entities: [TEXT]\nEntities found (format: ENTITY - TYPE): '
- Template 3: 'What named entities appear in: [TEXT]\nEntity list (one per line): [ENTITY] -> [TYPE]'

1. For each condition:
- Split data into train/validation sets
- Train on training set
- Evaluate on validation set after each epoch

2. Track metrics:
- F1 score (primary metric)
