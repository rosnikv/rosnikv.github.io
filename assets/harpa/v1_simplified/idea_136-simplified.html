ID: idea_136-simplified

factcc-enhanced-summarization

Hypothesis

Implementing FactCC as a post-processing filter will significantly improve factual consistency in abstractive summaries generated by pre-trained models without substantially reducing their informativeness.

Elements

  • Independent variable: Application of FactCC as a post-processing filter
  • Dependent variable: Factual consistency and informativeness of summaries
  • Comparison groups: Summaries before and after FactCC filtering
  • Baseline/control: Original summaries from pre-trained models without FactCC filtering
  • Context/setting: Abstractive summarization on news articles
  • Assumptions: FactCC can effectively identify factual inconsistencies
  • Relationship type: Causation
  • Population: News articles from CNN/DM dataset
  • Timeframe: Not time-dependent
  • Measurement method: Factual consistency scores and ROUGE metrics

Description

This research investigates how integrating FactCC, a factual consistency evaluation method, can improve abstractive summarization models. The study focuses on implementing FactCC as a post-processing filter to detect and correct factual inconsistencies in summaries generated by pre-trained models. By comparing summaries before and after FactCC filtering, the research aims to quantify improvements in factual consistency while maintaining summary quality. This simplified approach provides a practical entry point into factual consistency research without requiring complex model modifications or extensive computational resources.

Implementation Design

This experiment will implement and evaluate a FactCC-enhanced summarization pipeline to improve factual consistency in abstractive summaries. Follow these steps:

1. Setup and Data Preparation:
- Download a subset of the CNN/DM dataset (100-200 articles for the pilot, more for the full experiment)
- Split the data into training (if needed for fine-tuning), validation, and test sets
- Preprocess the articles to be compatible with the summarization model

2. Baseline Implementation:
- Use a pre-trained BART-base model from Hugging Face to generate baseline summaries
- Save these summaries along with their source documents for later comparison
- Calculate ROUGE scores between the generated summaries and reference summaries

3. FactCC Implementation:
- Download the pre-trained FactCC model from the authors' repository
- Implement a function that takes a source document and a generated summary as input
- The function should use FactCC to evaluate each sentence in the summary for factual consistency
- Output a factual consistency score for each summary

4. Post-processing Filter Implementation:
- Implement a filtering mechanism that identifies sentences with low factual consistency scores
- For sentences below a threshold (e.g., 0.5), either:
a) Remove the sentence from the summary, or
b) Replace it with a more factually consistent alternative (if implementing the extension)
- Save the filtered summaries along with their factual consistency scores

5. Evaluation:
- Calculate factual consistency scores for both baseline and filtered summaries
- Calculate ROUGE scores for both baseline and filtered summaries against reference summaries
- Perform statistical significance testing (paired t-test) to determine if improvements are significant
- Create visualizations comparing the factual consistency and ROUGE scores

6. Optional Extensions (if time permits):
- Implement a simple sentence replacement strategy instead of just filtering
- Try different thresholds for filtering to find the optimal balance
- Compare results across different pre-trained summarization models

7. Output and Reporting:
- Save all generated summaries (baseline and filtered) in a structured format
- Create a results table showing factual consistency scores and ROUGE metrics
- Generate example pairs of summaries before and after filtering to illustrate improvements
- Write a brief report analyzing the results and discussing implications

The experiment should be implemented in Python using PyTorch and the Transformers library. All code should be modular and well-documented to facilitate future extensions.

Operationalization

Please implement a pilot experiment to evaluate how FactCC post-processing can improve factual consistency in abstractive summarization. The experiment should include three pilot modes (MINI_PILOT, PILOT, FULL_EXPERIMENT) with the following specifications:

PILOT MODE SPECIFICATIONS:
- MINI_PILOT: Use 10 articles from CNN/DM training set
- PILOT: Use 100 articles from CNN/DM training set, 50 from validation set
- FULL_EXPERIMENT: Use 1000 articles from training, 200 from validation, 200 from test set

The experiment should initially run in MINI_PILOT mode, then PILOT mode if successful. DO NOT run FULL_EXPERIMENT mode (this requires manual verification first).

STEPS:

1. Dataset Loading and Preprocessing:
- Use Huggingface Datasets to load CNN/DM dataset
- For MINI_PILOT, load first 10 training articles
- For PILOT, load first 100 training + 50 validation articles
- Preprocess articles: truncate to max 512 tokens, clean text

2. Model Setup:
- Load pre-trained BART-base model via Huggingface
- Load pre-trained FactCC model
- Use gpt-4o-mini for any LLM operations

3. Baseline Generation:
- Generate summaries using BART-base
- Store source articles, generated summaries, reference summaries
- Calculate ROUGE scores (ROUGE-1, ROUGE-2, ROUGE-L)

4. FactCC Enhancement:
- For each summary:
* Split into sentences
* Score each sentence with FactCC
* Remove sentences below 0.5 confidence
* Store filtered summaries

5. Evaluation:
- Calculate ROUGE scores for filtered summaries
- Compare baseline vs filtered using bootstrap resampling
- Create line plots comparing scores
- Generate 3 example pairs (original vs filtered) with scores

6. Logging and Output:
- Log all steps, including dataset statistics
- Save all generated summaries
- Create results table with:
* Average ROUGE scores (baseline vs filtered)
* Average summary length (baseline vs filtered)
* Statistical significance results
* Example pairs with scores

REQUIRED OUTPUT FILES:
1. results.json: Contains all metrics and statistics
2. summaries.json: All generated summaries (baseline and filtered)
3. examples.txt: 3 example pairs with scores
4. plots.pdf: Visualization of results
5. log.txt: Detailed execution log

ERROR HANDLING:
- Implement robust error handling for model loading
- Catch and log any preprocessing errors
- Ensure graceful handling of failed summary generation

The experiment should first run in MINI_PILOT mode. If successful (no errors, reasonable outputs), proceed to PILOT mode. Stop after PILOT mode completion and await human verification before proceeding to FULL_EXPERIMENT.

Success Criteria:
