ID: idea_82-simplified

simple-hallucination-detection

Hypothesis

A lightweight post-processing filter that combines basic semantic retrieval with rule-based token verification will effectively identify hallucinations in dialogue system responses, as measured by precision and recall on a small test dataset.

Elements

  • Independent variable: The application of the lightweight post-processing filter
  • Dependent variable: Hallucination detection accuracy (precision and recall)
  • Comparison groups: Generated responses with and without the filter applied
  • Baseline/control: Generated responses without any hallucination detection
  • Context/setting: A small-scale dialogue system with a limited knowledge base
  • Assumptions: Pre-trained embeddings can effectively retrieve relevant documents; rule-based approaches can identify unsupported tokens
  • Relationship type: Causation
  • Population: A curated set of dialogue contexts and responses
  • Timeframe: Single-turn dialogue exchanges
  • Measurement method: Manual annotation of hallucinations in a test set, compared with system predictions

Description

This research explores a simplified approach to reducing hallucinations in dialogue systems by implementing a basic semantic retrieval mechanism paired with a simple token-level hallucination detection method. Rather than building a complex integrated system, this project focuses on developing a lightweight post-processing filter that can identify potential hallucinations in generated text by comparing it against retrieved reference documents. The system will use pre-trained embeddings to retrieve relevant documents from a small knowledge base, and then apply a rule-based approach to flag tokens in the generated response that lack support in the retrieved documents. This simplified approach provides a practical entry point into hallucination detection research while still offering potential for meaningful results that could contribute to a workshop paper.

Operationalization

Please implement a lightweight hallucination detection system that post-processes dialogue responses. The experiment should be implemented in three pilot phases (controlled by PILOT_MODE global variable):

PILOT PHASES:
- MINI_PILOT: Use 5 knowledge base documents, 3 dialogue contexts. Run time <5min.
- PILOT: Use 20 knowledge base documents, 10 dialogue contexts. Run time <1hr.
- FULL_EXPERIMENT: Use 100 knowledge base documents, 50 dialogue contexts.

Please implement and run MINI_PILOT first, then if successful, run PILOT. Stop before FULL_EXPERIMENT.

STEPS:

1. Knowledge Base Creation:
- Create knowledge base from Wikipedia paragraphs about simple topics (e.g., animals, basic science)
- MINI_PILOT: 5 documents
- PILOT: 20 documents
- FULL_EXPERIMENT: 100 documents

2. Dialogue Context Generation:
- Use gpt-4o-mini to generate questions about facts in the knowledge base
- MINI_PILOT: 3 contexts
- PILOT: 10 contexts
- FULL_EXPERIMENT: 50 contexts

3. Response Generation:
- Use gpt-4o-mini to generate responses to each context
- Generate two responses per context:
a. With knowledge base content visible (ground truth)
b. Without knowledge base (potentially hallucinated)

4. Manual Annotation:
- Compare responses to knowledge base
- Mark hallucinated spans (tokens/phrases not supported by knowledge base)
- Store annotations in JSON format

5. Implement Two Systems:
BASELINE SYSTEM:
- Simple keyword matching
- Flag any content words (excluding stopwords from NLTK) not in knowledge base

EXPERIMENTAL SYSTEM:
- Semantic retrieval using cosine similarity between context and knowledge base
- Token verification using retrieved documents
- Use WordNet to help identify content words vs function words

6. Evaluation:
For each pilot phase:
- Calculate precision, recall, F1 for both systems
- Measure processing time
- Use bootstrap resampling to compare systems
- Generate plots of results

REQUIRED OUTPUT:
1. JSON file containing:
- Knowledge base documents
- Dialogue contexts
- Generated responses
- Manual annotations
- System predictions
- Evaluation metrics

2. Plots:
- Precision/recall curves
- Processing time comparison
- Error analysis visualization

3. Log file with:
- All system parameters
- Intermediate results
- Error messages/warnings
- Final evaluation metrics

Please implement the MINI_PILOT first. If successful (defined as both systems running without errors and producing meaningful metrics), proceed to PILOT phase. Stop before FULL_EXPERIMENT phase.

Note: Use gpt-4o-mini for all LLM operations as specified in the conditioning instructions.
