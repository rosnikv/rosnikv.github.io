ID: idea_64-simplified

simple-mip-memorization-analysis

Hypothesis

Increasing the percentage of masked identifiers during pre-training will reduce a code model's tendency to memorize training data while maintaining or improving its performance on code completion tasks.

Elements

  • Independent variable: Percentage of identifiers masked during pre-training (e.g., 15%, 30%, 45%)
  • Dependent variables: 1) Code completion performance measured by accuracy and BLEU score, 2) Memorization rate measured by exact match percentage with training data
  • Comparison groups: Models trained with different masking percentages
  • Baseline/control: Model trained without masked identifier prediction
  • Context/setting: Small-scale code completion tasks using Python code snippets
  • Assumptions: The pre-trained model architecture remains constant across experiments
  • Relationship type: Correlation and potential causation
  • Population: Small transformer-based code models
  • Timeframe: Short-term evaluation immediately after training
  • Measurement method: Accuracy and BLEU scores for performance, exact match percentage for memorization

Description

This research explores the relationship between masked identifier prediction (MIP) in code models and their tendency to memorize training data. Rather than implementing a complex integration of techniques, this study focuses on analyzing how different levels of identifier masking during pre-training affect a model's memorization behavior. The research will use a small pre-trained code model and evaluate how varying the percentage of masked identifiers impacts both the model's performance on code completion tasks and its tendency to reproduce memorized code snippets. This simplified approach provides valuable insights into the relationship between semantic understanding (via MIP) and memorization in code models, while being feasible for a student researcher with limited resources.

Operationalization

Please implement a pilot experiment to investigate how different levels of masked identifier prediction affect code model memorization and performance. The experiment should have three pilot modes (PILOT_MODE: str = 'MINI_PILOT'/'PILOT'/'FULL_EXPERIMENT').

Pilot Configurations:
- MINI_PILOT: Use 10 training functions, 4 test functions (2 for performance, 2 for memorization). Train for 2 epochs.
- PILOT: Use 100 training functions, 40 test functions (20 each). Train for 5 epochs.
- FULL_EXPERIMENT: Use original 1000/200 split and 10 epochs.

Steps:

1. Dataset Preparation:
- Use the Huggingface Hub API to download a small subset of the CodeSearchNet Python dataset
- For each pilot mode, select the appropriate number of functions
- Preprocess by identifying variable/function identifiers using gpt-4o-mini to analyze the code and extract identifiers
- Store preprocessed data as JSON files

2. Model Variants:
- Create 4 model configurations:
* Baseline (0% masking)
* Low masking (15%)
* Medium masking (30%)
* High masking (45%)
- For masked versions, replace identifiers with [MASK] at the specified rates

3. Training:
- Train each variant using the same hyperparameters:
* Learning rate: 5e-5
* Batch size: 4 (MINI), 8 (PILOT), 16 (FULL)
* Epochs: 2 (MINI), 5 (PILOT), 10 (FULL)

4. Evaluation:
- Performance Test:
* Remove last 20% of each test function
* Have models complete the functions
* Calculate accuracy and BLEU scores
- Memorization Test:
* Use beginnings of training functions
* Calculate exact match percentage

5. Analysis and Visualization:
- Create line plots showing:
* Masking percentage vs Performance (accuracy, BLEU)
* Masking percentage vs Memorization rate
- Use bootstrap resampling to compare:
* Each masking level vs baseline
* Adjacent masking levels (15% vs 30%, 30% vs 45%)

6. Logging and Output:
- Log all major steps, including:
* Dataset statistics
* Training progress
* Evaluation results
* Statistical test results
- Save results in a structured format (CSV)
- Generate plots as PNG files

IMPORTANT NOTES:
1. Start with MINI_PILOT mode
2. If successful, proceed to PILOT mode
3. Stop after PILOT mode - do not run FULL_EXPERIMENT
4. Use gpt-4o-mini for all LLM operations
5. Include clear error handling and logging
6. Save all intermediate results

Success Criteria:
1. All code runs without errors
2. Results show clear differences between masking levels
3. Statistical tests show significant results
4. Plots clearly visualize relationships
5. Memory usage and runtime are reasonable
