ID: idea_20-simplified

simple-distilgpt2-cybersecurity-mapping

Hypothesis

DistilGPT-2 with chain-of-thought prompting will achieve higher accuracy in vulnerability-to-tactic mapping tasks compared to zero-shot and few-shot prompting approaches, as measured by precision and recall against a manually labeled test set.

Elements

  • Independent variable: Prompting technique (zero-shot, few-shot, chain-of-thought)
  • Dependent variable: Accuracy in vulnerability-to-tactic mapping tasks
  • Comparison groups: DistilGPT-2 with different prompting techniques
  • Baseline/control: Zero-shot prompting
  • Context/setting: Vulnerability-to-tactic mapping tasks using a small dataset of CVE entries
  • Assumptions: Chain-of-thought prompting can improve reasoning capabilities of small models
  • Relationship type: Comparison
  • Population: Common Vulnerabilities and Exposures (CVE) entries
  • Timeframe: Recent CVEs (last 2 years)
  • Measurement method: Precision and recall

Description

This research investigates whether a small language model (DistilGPT-2) can effectively map cybersecurity vulnerabilities to tactics with simple prompt engineering techniques. Rather than implementing complex distillation methods like SCoTD, this study focuses on comparing basic prompting strategies (zero-shot, few-shot, and chain-of-thought) to determine which approach yields the best performance for vulnerability-to-tactic mapping tasks. The research aims to establish whether lightweight models with appropriate prompting can achieve reasonable performance on specialized cybersecurity tasks, potentially offering resource-efficient alternatives to larger models for specific applications.

Operationalization

Please create an experiment to evaluate whether different prompting techniques (zero-shot, few-shot, and chain-of-thought) affect a language model's ability to map cybersecurity vulnerabilities to MITRE ATT&CK tactics. Use gpt-4o-mini as the base model.

The experiment should include three pilot modes (PILOT_MODE values of MINI_PILOT, PILOT, and FULL_EXPERIMENT):

MINI_PILOT:
- Use 6 CVE entries total (4 for few-shot examples if needed, 2 for testing)
- Run each prompting technique once on each test entry
- Purpose: Quick code verification and debugging
- Runtime target: 5-10 minutes

PILOT:
- Use 30 CVE entries total (20 for few-shot examples if needed, 10 for testing)
- Run each prompting technique once on each test entry
- Purpose: Initial assessment of approach viability
- Runtime target: 30-60 minutes

FULL_EXPERIMENT:
- Use 150 CVE entries total (100 for few-shot examples if needed, 50 for testing)
- Run each prompting technique three times on each test entry
- Purpose: Complete experimental evaluation
- Runtime target: 4-6 hours

Experimental Setup:
1. Create three prompting techniques:
a. Zero-shot (baseline): Direct question about mapping
b. Few-shot: Include examples before question
c. Chain-of-thought: Guide through reasoning steps

2. Prompt Templates:
Zero-shot:
"Given the following vulnerability description, identify which MITRE ATT&CK tactic it is most associated with. Choose from: Initial Access, Execution, Persistence, Privilege Escalation, Defense Evasion, Credential Access, Discovery, Lateral Movement, Collection, Command and Control, Exfiltration, Impact.\n\nVulnerability: [CVE_DESCRIPTION]\n\nMost relevant MITRE ATT&CK tactic:"

Few-shot:
"Here are some examples of vulnerabilities and their associated MITRE ATT&CK tactics:\n\nVulnerability: A buffer overflow in a web application allows remote code execution.\nTactic: Execution\n\nVulnerability: A flaw in the authentication mechanism allows attackers to bypass login screens.\nTactic: Initial Access\n\n[Additional examples]\n\nBased on these examples, identify which MITRE ATT&CK tactic is most associated with the following vulnerability:\n\nVulnerability: [CVE_DESCRIPTION]\n\nMost relevant MITRE ATT&CK tactic:"

Chain-of-thought:
"Given the following vulnerability description, analyze it step by step to determine the most relevant MITRE ATT&CK tactic.\n\nVulnerability: [CVE_DESCRIPTION]\n\nStep 1: Identify what type of vulnerability this is (e.g., buffer overflow, SQL injection, etc.).\nStep 2: Determine what an attacker could accomplish by exploiting this vulnerability.\nStep 3: Based on the attacker's potential actions, identify which MITRE ATT&CK tactic this vulnerability is most associated with. Choose from: Initial Access, Execution, Persistence, Privilege Escalation, Defense Evasion, Credential Access, Discovery, Lateral Movement, Collection, Command and Control, Exfiltration, Impact.\n\nMost relevant MITRE ATT&CK tactic:"

3. Evaluation Process:
- For each test CVE:
* Apply each prompting technique
* Extract predicted tactic
* Compare against ground truth
* Log full prompt and response

4. Metrics to Calculate:
- Precision, Recall, F1 score per technique
- Create confusion matrices
- Generate performance comparison plots
- Perform bootstrap resampling to test for significant differences

5. Required Outputs:
- CSV file with all predictions and ground truth
- Performance metrics summary
- Confusion matrix plots
- Statistical comparison results
- Example successes/failures for each technique

Please implement this experiment starting with MINI_PILOT mode. After successful completion, run PILOT mode. Stop before FULL_EXPERIMENT for human verification of results.

Note: All responses from the model should be logged for analysis, including any errors or unexpected outputs. Use appropriate error handling throughout.
