ID: idea_45-simplified

simple-graph-verification-for-math

Hypothesis

A simple graph-based verification approach can improve the accuracy of solutions to basic arithmetic word problems from the GSM8K dataset compared to standard language model solutions.

Elements

  • Independent variable: Use of a simple graph-based verification approach
  • Dependent variable: Solution accuracy on arithmetic word problems
  • Comparison groups: Solutions with graph verification vs. solutions without verification
  • Baseline/control: Standard language model solutions without verification
  • Context/setting: Solving basic arithmetic word problems from the GSM8K dataset
  • Assumptions: Graph verification will identify and correct errors in arithmetic reasoning
  • Relationship type: Causation
  • Population: Basic arithmetic word problems from the GSM8K dataset
  • Timeframe: Not specified
  • Measurement method: Exact Match (EM) Score

Description

This research explores the effectiveness of a simple graph-based verification approach for improving the accuracy of solutions to basic arithmetic word problems. Instead of developing a complex numerically-aware graph neural network, this simplified approach focuses on using basic graph structures to represent and verify the reasoning steps in arithmetic problem-solving. The research will use a subset of the GSM8K dataset, focusing on problems that involve basic arithmetic operations (addition, subtraction, multiplication, and division). The verification approach will construct simple reasoning graphs from solutions generated by a language model, where nodes represent numerical values and intermediate results, and edges represent arithmetic operations. These graphs will be used to verify the correctness of the arithmetic operations and identify potential errors in the reasoning process. The research aims to demonstrate that even a simple graph-based verification approach can significantly improve the accuracy of solutions to arithmetic word problems, providing a foundation for more complex verification methods in the future.

Operationalization

Please implement an experiment to evaluate whether a simple graph-based verification approach can improve the accuracy of solutions to basic arithmetic word problems. The experiment should have three modes (PILOT_MODE): MINI_PILOT, PILOT, and FULL_EXPERIMENT.

Data Preparation:
- Use the Huggingface Datasets API to load the GSM8K dataset
- For MINI_PILOT: Use 10 problems from the training set
- For PILOT: Use 100 problems from training set for development, 50 from validation set for testing
- For FULL_EXPERIMENT: Use 1000 problems from training, 200 from validation, 200 from test set
- Filter to include only problems with basic arithmetic (+-*/)

Baseline Implementation:
- Use gpt-4o-mini (via proxy) to solve each problem
- Prompt template: 'Solve this math problem step by step, showing all arithmetic operations clearly:
[problem]'
- Extract the final numerical answer

Graph Verification Implementation:
1. For each solution:
- Parse the solution text to identify:
* Input numbers
* Arithmetic operations (+-*/)
* Intermediate results
* Final answer
- Create a DOT graph where:
* Nodes are numbers (inputs, intermediates, final)
* Edges are operations (labeled with +-*/)
- Verify each operation by:
* Recomputing the result
* If different, mark the node red in graph
* If error found, recalculate path to final answer

Evaluation:
- Calculate for both baseline and verified:
* Exact Match (EM) score
* Number of arithmetic errors found
* Number of corrections made
- Use bootstrap resampling to test significance

Output:
1. For each problem:
- Original problem text
- Model solution
- Verification graph (DOT -> PDF)
- Whether verification helped/hurt
2. Summary statistics:
- EM scores (baseline vs verified)
- Error detection/correction counts
- Statistical significance results

Pilot Process:
1. Run MINI_PILOT first (10 problems)
- Verify all components work
- Check graph visualization
- Ensure error detection works
2. If successful, run PILOT (150 total problems)
- Analyze initial results
- Look for significant differences
3. Stop before FULL_EXPERIMENT
- Human verification required
- Manual approval needed

Logging Requirements:
- Log all LLM calls
- Log all arithmetic operations
- Log all error detections
- Log timing information
- Save all graphs as both DOT and PDF

Success Criteria:
- All components functional in MINI_PILOT
- Clear comparison possible in PILOT
- Error detection working reliably
- Graphs properly visualized
- Statistical testing completed
