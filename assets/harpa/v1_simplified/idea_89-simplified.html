Hypothesis

A GPT-based agent with a simple memory mechanism will complete tasks more efficiently than an equivalent agent without memory in a partially observable grid-world environment.

Elements

  • Independent variable: Presence of a simple memory mechanism in a GPT-based agent
  • Dependent variable: Task completion efficiency (steps taken, success rate)
  • Comparison groups: GPT-based agent with memory vs. GPT-based agent without memory
  • Baseline/control: GPT-based agent without memory
  • Context/setting: Partially observable grid-world environment
  • Assumptions: GPT can effectively use the provided memory mechanism
  • Relationship type: Causation
  • Population: Single-agent systems in grid-world environments
  • Timeframe: Not specified
  • Measurement method: Steps to completion, success rate

Description

This research investigates the impact of a simple memory mechanism on the performance of GPT-based agents in a partially observable grid-world environment. The memory mechanism will store the agent's observations and actions in a structured format, allowing the agent to reference past experiences when making decisions. The grid-world environment will be designed with partial observability, requiring the agent to remember previously observed information to complete tasks efficiently. Tasks will include navigating to specific locations, collecting objects, and avoiding obstacles. The hypothesis is that an agent equipped with memory will complete these tasks more efficiently than an agent without memory, as measured by the number of steps taken and the success rate. This research simplifies the original idea by focusing on a single agent in a simpler environment, using a basic memory mechanism rather than complex memory-augmented planning, and employing readily available grid-world environments instead of Overcooked-AI.

Implementation Design

# Simple Memory Agent Experiment Design

## Overview
This experiment compares the performance of a GPT-based agent with a simple memory mechanism against an equivalent agent without memory in a partially observable grid-world environment.

## Implementation Details

### 1. Grid-World Environment
- Create a simple grid-world environment (e.g., 10x10 grid)
- Implement partial observability where the agent can only see its immediate surroundings (1 cell in each direction)
- Include obstacles, target objects, and a clear starting position
- Design three task types of increasing complexity:
- Task 1: Navigate to a specific location
- Task 2: Collect a specific object and return to start
- Task 3: Collect multiple objects in a specific order

### 2. Agent Implementation
- Memory Agent:
- Implement a simple memory mechanism that stores past observations and actions
- Format: List of dictionaries with keys 'observation', 'action', and 'step_number'
- Limit memory to the most recent 10 steps to keep it manageable
- Include memory in the prompt to GPT along with the current observation

- No-Memory Agent:
- Identical to Memory Agent but without access to past observations/actions
- Only the current observation is included in the prompt

### 3. GPT Interface
- Use GPT-3.5-turbo to reduce costs while maintaining reasonable performance
- Create a prompt template that includes:
- Description of the environment and task
- Available actions (move up/down/left/right, pick up, drop)
- Current observation
- Past observations and actions (for Memory Agent only)
- Request for the next action with reasoning

### 4. Experiment Procedure
- For each task type, create 10 different scenarios (varying start positions, object placements)
- Run each agent (Memory, No-Memory, Random) on each scenario
- Set a maximum of 100 steps per scenario
- Record steps to completion and success/failure
- Repeat each scenario 3 times to account for GPT's non-deterministic responses

### 5. Data Collection and Storage
- For each run, save:
- Agent type (Memory/No-Memory/Random)
- Task type and scenario ID
- Complete trajectory (all observations and actions)
- Steps to completion
- Success/failure status
- GPT prompts and responses
- Save data in JSON format for easy analysis

### 6. Analysis and Evaluation
- Calculate for each agent type and task type:
- Average steps to completion (for successful runs)
- Success rate
- Efficiency improvement (percentage reduction in steps compared to baseline)
- Perform statistical significance testing (t-test) to compare Memory vs. No-Memory
- Create visualizations:
- Bar charts comparing performance metrics
- Sample trajectories showing different behaviors

### 7. Error Analysis
- Identify common failure patterns for each agent type
- Analyze scenarios where memory provides the largest advantage
- Examine GPT's reasoning to understand how it utilizes memory

## Output and Reporting
- Generate a comprehensive report including:
- Experimental setup description
- Performance metrics for all agent types across all tasks
- Statistical analysis results
- Visualizations of key findings
- Discussion of when and why memory helps
- Limitations and potential improvements
- Include code and data for reproducibility

FULL_EXPERIMENT:

- Max 100 steps per episode

## Agent Implementation

- Use Memory Agent Example codeblock

2. No-Memory Agent:
- Identical to Memory Agent but without memory storage

- Randomly select from valid actions
