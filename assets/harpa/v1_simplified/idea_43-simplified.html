ID: idea_43-simplified

Text-Based-Tone-Detection

Hypothesis

A text-based tone detection model analyzing punctuation, capitalization, and lexical features can significantly improve the contextual appropriateness of dialogue system responses compared to a baseline system without tone awareness.

Elements

  • Independent variable: Implementation of text-based tone detection
  • Dependent variable: Contextual appropriateness of dialogue responses
  • Comparison groups: Dialogue system with tone detection vs. system without tone detection
  • Baseline/control: Basic dialogue system without tone detection
  • Context/setting: Text-based conversations on common topics
  • Assumptions: Textual features contain sufficient information to detect basic emotional tones
  • Relationship type: Causation
  • Population: Text-based dialogue systems
  • Timeframe: Not specified
  • Measurement method: Human evaluation and automated metrics

Description

This research explores a simplified approach to tone detection in text-based dialogue systems using only textual features. Instead of integrating complex motivation inferences with prosody analysis, this project focuses on developing a lightweight tone detection model that analyzes textual cues such as punctuation, capitalization, word choice, and sentence structure to infer the emotional tone of user messages. The model will be trained on a publicly available dataset of annotated conversations and will be integrated into a simple dialogue system to generate tone-appropriate responses. This approach offers a more accessible entry point into dialogue personalization research while still addressing the important challenge of making conversational agents more contextually aware and emotionally intelligent.

Operationalization

Please implement a text-based tone detection experiment that evaluates whether adding tone detection improves dialogue system responses. The experiment should be implemented with three pilot modes (controlled by PILOT_MODE:str = ['MINI_PILOT', 'PILOT', 'FULL_EXPERIMENT']).

Data and Scope:
MINI_PILOT:
- Use 50 utterances total from DailyDialog dataset (35 train, 8 val, 7 test)
- Detect only 3 tones: neutral, happy, sad
- Generate 3 response templates per tone using gpt-4o-mini
- 2 human evaluators rating 5 responses each

PILOT:
- Use 500 utterances (350 train, 75 val, 75 test)
- Detect 5 tones: neutral, happy, sad, angry, curious
- Generate 5 response templates per tone using gpt-4o-mini
- 3 human evaluators rating 10 responses each

FULL_EXPERIMENT:
- Use 2000 utterances (1400 train, 300 val, 300 test)
- Detect 5 tones: neutral, happy, sad, angry, curious
- Generate 10 response templates per tone using gpt-4o-mini
- 5-10 human evaluators rating 20 responses each

Implementation Steps:

1. Dataset Preparation:
- Use the Huggingface Datasets API to load DailyDialog
- Filter for utterances with clear emotional labels matching our tone set
- Split into train/val/test according to pilot mode

2. Feature Extraction:
- Extract per-utterance features:
* Punctuation counts ('!', '?', '...')
* Capitalization ratios
* Basic sentiment scores

3. System Implementation:
- Baseline System:
* Simple template-based responses without tone awareness
* Use gpt-4o-mini to generate generic response templates

- Experimental System:
* Same template-based responses, but with tone detection
* Use gpt-4o-mini to generate tone-specific response templates

4. Evaluation:
- Automated Metrics:
* Tone classification accuracy
* Response diversity (unique responses/total)

- Human Evaluation:
* Appropriateness ratings (1-5 Likert scale)
* Inter-rater agreement calculation

5. Analysis:
- Use bootstrap resampling to compare baseline vs experimental
- Generate confusion matrices for tone classification
- Plot appropriateness ratings distributions

Required Outputs:
1. Logs of all major steps and decisions
2. Plots of classification accuracy and human ratings
3. Statistical test results comparing systems
4. Example dialogues from both systems

Notes:
- Start with MINI_PILOT mode
- If successful, proceed to PILOT mode
- Stop before FULL_EXPERIMENT (awaiting human verification)
- Use gpt-4o-mini for all LLM operations
- Save all intermediate results for reproducibility
