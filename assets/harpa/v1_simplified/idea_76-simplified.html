ID: idea_76-simplified

prompt-based-federated-learning

Hypothesis

A combined global-local prompt strategy in federated learning will reduce communication costs compared to full model sharing while maintaining comparable task performance to a global-only prompt approach, particularly when client data distributions are heterogeneous.

Elements

  • Independent variable: Prompt strategy type (global-only vs. global-local)
  • Dependent variable: Communication costs, task performance (accuracy, F1 score)
  • Comparison groups: Global-only prompt strategy vs. Global-local prompt strategy
  • Baseline/control: Standard federated learning with full model sharing (FedAvg)
  • Context/setting: Simulated federated learning environment with non-IID data distributions
  • Assumptions: Prompt-based learning can effectively capture task-specific knowledge; communication of prompt embeddings is more efficient than full model weights
  • Relationship type: Causation
  • Population: Text classification tasks with heterogeneous data distributions
  • Timeframe: Short-term experiment (days to weeks)
  • Measurement method: Communication volume measurement, classification metrics

Description

This research explores a simplified approach to integrating prompt-based learning with federated learning. Instead of the complex FedOTP framework with optimal transport alignment, this project focuses on comparing a basic global prompt approach versus a combined global-local prompt strategy in federated learning. The study will examine how these prompt-based approaches affect communication efficiency and model performance across heterogeneous client data. By focusing on prompt embeddings rather than full model weights, the research aims to demonstrate a practical way to reduce communication costs while maintaining or improving task performance in federated settings. This simplified approach provides an accessible entry point to federated prompt learning while still addressing key challenges in the field.

Operationalization

Please implement a federated learning experiment comparing different prompt-based strategies, with the following specifications:

PILOT MODES:
- MINI_PILOT: Use SST-2 dataset, 3 clients, 50 examples per client, 5 communication rounds, prompt length 5
- PILOT: Use SST-2 dataset, 4 clients, 200 examples per client, 10 communication rounds, prompt length 10
- FULL_EXPERIMENT: Use AG News dataset, 5 clients, full dataset, 20 communication rounds, prompt length 20

Implementation Steps:

1. Dataset Preparation:
- Load SST-2 (binary sentiment) for MINI_PILOT/PILOT, or AG News (4-class) for FULL_EXPERIMENT using Huggingface datasets
- Create non-IID splits by assigning skewed class distributions to each client
- MINI_PILOT: 80-20 class split per client
- PILOT/FULL: More nuanced splits (e.g., [0.8,0.2], [0.6,0.4], [0.4,0.6], [0.2,0.8])
- Reserve 20% for testing

2. Model Setup:
- Use gpt-4o-mini as base model
- Initialize three configurations:
a) Standard FedAvg (baseline)
b) Global-only prompt
c) Global-local prompt

3. Training Loop:
- For each approach:
- Initialize client models/prompts
- For each communication round:
- Train each client on their local data (1 epoch MINI_PILOT, 2 epochs PILOT, 3 epochs FULL)
- Aggregate updates (FedAvg for baseline, prompt aggregation for others)
- Evaluate on test set
- Log communication costs (parameter sizes)

4. Metrics Collection:
- Per round:
- Accuracy and F1 score per client
- Communication cost (MB)
- Total training time
- Final:
- Average/std performance metrics
- Total communication cost
- Time to 90% max performance

5. Analysis:
- Generate line plots:
- Performance vs. rounds
- Performance vs. communication cost
- Statistical comparison:
- Bootstrap test comparing approaches
- Per-client performance analysis

6. Output:
- CSV files with all metrics
- PDF plots
- Summary report

Specific Settings:
MINI_PILOT:
- 50 examples/client
- 3 clients
- 5 rounds
- 5 prompt tokens
- 1 training epoch/round

PILOT:
- 200 examples/client
- 4 clients
- 10 rounds
- 10 prompt tokens
- 2 training epochs/round

FULL_EXPERIMENT:
- Full dataset
- 5 clients
- 20 rounds
- 20 prompt tokens
- 3 training epochs/round

Run MINI_PILOT first. If successful, run PILOT. Stop before FULL_EXPERIMENT for human verification.

Success Criteria:
1. All three approaches run without errors
2. Communication costs are measurably different
3. Performance metrics are collected and analyzed
4. Statistical comparisons completed
5. Visualizations generated

Please log all steps, errors, and results using the logger.
