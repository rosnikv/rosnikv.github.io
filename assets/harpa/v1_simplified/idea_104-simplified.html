ID: idea_104-simplified

simple-bge-retrieval-enhancement

Hypothesis

Integrating a simple knowledge graph with the BGE-M3 model will enhance retrieval accuracy for academic regulatory queries compared to using the BGE-M3 model alone.

Elements

  • Independent variable: Integration of a simple knowledge graph
  • Dependent variable: Retrieval accuracy
  • Comparison groups: BGE-M3 model with knowledge graph vs. BGE-M3 model alone
  • Baseline/control: BGE-M3 model without knowledge graph
  • Context/setting: Academic regulatory queries within a limited domain
  • Assumptions: The knowledge graph integration will have a measurable impact on retrieval accuracy
  • Relationship type: Causation
  • Population: Academic regulatory queries from a single institution or department
  • Timeframe: Not specified
  • Measurement method: Comparison of retrieval accuracy using standard IR metrics

Description

This research explores a simplified approach to enhancing the BGE-M3 model's performance in retrieving academic regulatory information. Instead of implementing both Rotary Position Embeddings and a complex knowledge graph, this study focuses solely on integrating a basic knowledge graph with the pre-trained BGE-M3 model. The knowledge graph will represent key academic concepts and their relationships in a structured format, focusing on a limited domain of academic regulations. The research will evaluate whether this integration improves retrieval accuracy for academic queries compared to using the BGE-M3 model alone. This approach provides a more accessible entry point for exploring how structured knowledge representations can enhance embedding-based retrieval systems, while still addressing an important gap in current retrieval systems for academic regulatory information.

Implementation Design

This experiment will evaluate whether integrating a simple knowledge graph with the BGE-M3 model improves retrieval accuracy for academic regulatory queries.

1. Implementation:
a. Set up the BGE-M3 model using the Hugging Face transformers library. Use the pre-trained model without any modifications.
b. Create a simple knowledge graph using NetworkX or a similar Python library. The graph should represent:
- Nodes: Key academic concepts (e.g., 'course registration', 'academic probation', 'graduation requirements')
- Edges: Relationships between concepts (e.g., 'prerequisite_for', 'part_of', 'related_to')
c. Implement a retrieval system that:
- Takes a query as input
- Uses BGE-M3 to encode the query into an embedding
- Retrieves relevant documents using vector similarity
- For the enhanced version, augment the query using information from the knowledge graph
- Identify concepts in the query that match nodes in the knowledge graph
- Expand the query with related concepts based on graph connections
- Use the expanded query for retrieval

2. Data:
a. Collect a corpus of academic regulatory documents from a single department or institution (100-200 documents)
b. Preprocess the documents by:
- Splitting into chunks of appropriate size (e.g., paragraphs or sections)
- Removing irrelevant content (headers, footers, etc.)
- Creating embeddings for each chunk using BGE-M3
c. Create a test set of 100 realistic academic queries
d. Create relevance judgments for each query (which documents are relevant)

3. Evaluation:
a. For each query in the test set:
- Run retrieval using the baseline BGE-M3 model
- Run retrieval using the BGE-M3 model with knowledge graph integration
- Run retrieval using BM25 (secondary baseline)
b. Calculate the following metrics for each approach:
- Mean Average Precision (MAP)
- Normalized Discounted Cumulative Gain (nDCG@10)
- Mean Reciprocal Rank (MRR)
c. Perform statistical significance testing (paired t-test) to determine if the differences are significant
d. Conduct error analysis on cases where the knowledge graph integration performs worse than the baseline

4. Output and Reporting:
a. Save all retrieval results in CSV format with columns for query ID, document ID, relevance score, and rank
b. Generate summary tables of all evaluation metrics
c. Create visualizations comparing the performance of different approaches
d. Write a detailed report including:
- Methodology description
- Results and analysis
- Discussion of findings
- Limitations and future work

Operationalization

Please implement a pilot experiment to evaluate whether integrating a simple knowledge graph with the BGE-M3 model improves retrieval accuracy for academic regulatory queries. The experiment should support three modes (PILOT_MODE): MINI_PILOT, PILOT, and FULL_EXPERIMENT.

Pilot Specifications:
1. MINI_PILOT:
- Use 5 academic regulatory documents
- Generate 10 test queries using gpt-4o-mini
- Create a small knowledge graph with 5 key concepts
- Maximum runtime: ~10 minutes

2. PILOT:
- Use 25 academic regulatory documents
- Generate 50 test queries using gpt-4o-mini
- Create a knowledge graph with 15 key concepts
- Maximum runtime: ~1 hour

3. FULL_EXPERIMENT (not to be run initially):
- Use 100-200 academic regulatory documents
- Generate 100 test queries
- Create a knowledge graph with 30 key concepts

Implementation Steps:

1. Knowledge Graph Creation:
- Use DOT/Graphviz to create and visualize the knowledge graph
- Nodes: Academic concepts (e.g., 'course_registration', 'academic_probation')
- Edges: Relationships (e.g., 'prerequisite_for', 'part_of')
- Export graph visualization to PDF for inspection

2. Document Processing:
- Split documents into chunks (max 512 tokens)
- Remove headers, footers, and formatting
- Create embeddings using BGE-M3

3. Query Generation and Processing:
- Use gpt-4o-mini to generate realistic academic queries
- For each query:
a. Create baseline embedding using BGE-M3
b. Identify concepts in query that match knowledge graph nodes
c. Expand query using connected nodes (1-hop only)
d. Create embedding for expanded query

4. Retrieval Implementation:
a. Baseline (BGE-M3 only):
- Use original query embedding
- Retrieve top 10 most similar documents
b. Enhanced (BGE-M3 + Knowledge Graph):
- Use expanded query embedding
- Retrieve top 10 most similar documents
c. BM25 Baseline:
- Implement simple keyword-based retrieval

5. Evaluation:
- Calculate MAP, nDCG@10, and MRR for each approach
- Use bootstrap resampling to test statistical significance
- Create line plots comparing performance across methods

6. Output Requirements:
- Save knowledge graph visualization
- Log all query expansions and retrievals
- Generate CSV with performance metrics
- Create performance comparison plots
- Report statistical significance results

Special Instructions:

3. Stop after PILOT for human verification
4. Log all steps and errors comprehensively
5. Generate visualizations for both knowledge graph and results
