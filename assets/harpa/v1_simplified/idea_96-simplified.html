ID: idea_96-simplified

simple-constraint-dspy-integration

Hypothesis

Integrating a simple constraint solver with a DSPy-based neural-symbolic pipeline will improve LLM performance on constrained planning tasks compared to using DSPy alone.

Elements

  • Independent variable: Integration of a simple constraint solver with a DSPy-based neural-symbolic pipeline
  • Dependent variable: Task completion success rate and solution quality
  • Comparison groups: DSPy pipeline with and without constraint solver integration
  • Baseline/control: DSPy pipeline without constraint solver
  • Context/setting: Simple planning tasks with explicit constraints
  • Assumptions: The integration will function as intended for simple planning problems
  • Relationship type: Causation
  • Population: LLMs (specifically, a single accessible model like GPT-3.5-turbo)
  • Timeframe: Not specified
  • Measurement method: Success rate, constraint violation count, and solution steps count

Description

This research investigates the integration of a simple constraint solver with DSPy-based neural-symbolic pipelines to enhance problem-solving capabilities of Large Language Models (LLMs). Rather than tackling complex dynamic environments like Overcooked-AI, this study focuses on a more manageable domain: solving simple planning problems with fixed constraints. The research will implement a basic constraint solver using the python-constraint library and integrate it with a DSPy pipeline to create a hybrid system. This system will be evaluated on a set of simple planning tasks where constraints must be satisfied, comparing performance against a baseline DSPy pipeline without constraint integration. The study aims to demonstrate how even simple constraint integration can improve task completion rates and solution quality in structured problem-solving scenarios.

Operationalization

Please implement an experiment to evaluate the integration of a simple constraint solver with DSPy-based neural-symbolic pipelines. The experiment should follow these specifications:

1. CONFIGURATION
- Create a global PILOT_MODE variable that can be set to 'MINI_PILOT', 'PILOT', or 'FULL_EXPERIMENT'
- Default to MINI_PILOT initially
- Use gpt-4o-mini as the LLM for all conditions

2. PLANNING PROBLEMS
Implement these simplified planning problems:
a) Task Scheduling:
- Schedule N tasks across M workers
- Constraints: No overlapping tasks, precedence requirements
b) Resource Allocation:
- Allocate resources to projects
- Constraints: Limited quantities, minimum requirements

Scale based on PILOT_MODE:
- MINI_PILOT: 1 problem type, 2 instances each
- PILOT: Both problem types, 5 instances each
- FULL_EXPERIMENT: Both problem types, 20 instances each

3. IMPLEMENTATION
Create three conditions:
a) Baseline 1 (LLM-only):
- Direct prompting to gpt-4o-mini
- Include constraints in the prompt
b) Baseline 2 (DSPy-only):
- Basic DSPy pipeline without constraint checking
- Use DSPy's Predict module
c) Experimental (Integrated):
- DSPy pipeline with constraint solver integration
- Implement constraint checking/enforcement

4. EVALUATION METRICS
For each problem instance, measure:
- Success Rate: Binary (1 if all constraints satisfied, 0 if not)
- Constraint Violations: Count of violated constraints
- Solution Steps: Number of steps in final solution

5. LOGGING
For each run, log:
- Problem instance details
- Full prompts and responses
- Metrics for each condition
- Any constraint solver operations
- Timing information

6. ANALYSIS
For each pilot phase:
a) Calculate summary statistics:
- Mean/std for each metric
- Success rates across conditions
b) Statistical testing:
- Use bootstrap resampling to compare conditions
- Test significance of differences in metrics
c) Generate plots:
- Bar plots comparing metrics across conditions
- Success rate comparisons

7. PILOT PROGRESSION
- Start with MINI_PILOT
- If successful (no errors, reasonable outputs), proceed to PILOT
- Stop after PILOT for human verification
- Do not proceed to FULL_EXPERIMENT automatically

8. OUTPUT
Generate a results file containing:
- Configuration details
- Summary statistics
- Statistical test results
- Plots (saved as PDFs)
- Raw data in CSV format

9. ERROR HANDLING
- Implement robust error handling
- Log all errors with stack traces
- Continue experiment even if individual runs fail

Please implement this experiment, starting with MINI_PILOT, and ensure all logging and analysis components are in place before running any conditions.
