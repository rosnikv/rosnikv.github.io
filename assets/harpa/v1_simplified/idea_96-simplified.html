simple-constraint-dspy-integration

Hypothesis

Integrating a simple constraint solver with a DSPy-based neural-symbolic pipeline will improve LLM performance on constrained planning tasks compared to using DSPy alone.

Elements

  • Independent variable: Integration of a simple constraint solver with a DSPy-based neural-symbolic pipeline
  • Dependent variable: Task completion success rate and solution quality
  • Comparison groups: DSPy pipeline with and without constraint solver integration
  • Baseline/control: DSPy pipeline without constraint solver
  • Context/setting: Simple planning tasks with explicit constraints
  • Assumptions: The integration will function as intended for simple planning problems
  • Relationship type: Causation
  • Population: LLMs (specifically, a single accessible model like GPT-3.5-turbo)
  • Timeframe: Not specified
  • Measurement method: Success rate, constraint violation count, and solution steps count

Description

This research investigates the integration of a simple constraint solver with DSPy-based neural-symbolic pipelines to enhance problem-solving capabilities of Large Language Models (LLMs). Rather than tackling complex dynamic environments like Overcooked-AI, this study focuses on a more manageable domain: solving simple planning problems with fixed constraints. The research will implement a basic constraint solver using the python-constraint library and integrate it with a DSPy pipeline to create a hybrid system. This system will be evaluated on a set of simple planning tasks where constraints must be satisfied, comparing performance against a baseline DSPy pipeline without constraint integration. The study aims to demonstrate how even simple constraint integration can improve task completion rates and solution quality in structured problem-solving scenarios.

self.problem.addVariable(var, domain)

def add_constraint(self, constraint_func, variables):
self.problem.addConstraint(constraint_func, variables)

def solve(self):
return self.problem.getSolution()

## 2. Data for Pilot Experiment

Create a small dataset of 5 planning problems with explicit constraints:

1. **Task Scheduling Problem**:
- Task: Schedule 5 tasks with different durations on 2 workers
- Constraints: No worker can have overlapping tasks, certain tasks must be completed before others

2. **Resource Allocation Problem**:
- Task: Allocate 3 types of resources to 4 projects
- Constraints: Limited quantity of each resource, minimum requirements for each project

3. **Simple Path Finding**:
- Task: Find a path from point A to B on a small grid
- Constraints: Avoid obstacles, maximum path length

4. **Meeting Scheduling**:
- Task: Schedule 3 meetings for 4 people
- Constraints: Availability windows, meeting duration requirements

5. **Item Selection Problem**:
- Task: Select items to pack in a knapsack
- Constraints: Weight limit, some items must be included/excluded together

Format each problem as a JSON object with fields for task description, constraints, and ground truth solution.

## 3. Experiment Procedure

1. **Setup**:
- Implement the baseline DSPy pipeline without constraint integration
- Implement the integrated system with constraint solver
- Implement a simple LLM-only baseline (direct prompting)

2. **Evaluation**:
- For each planning problem in the dataset:
- Run all three approaches (LLM-only, DSPy-only, Integrated)
- Record the proposed solution
- Evaluate metrics: success rate, constraint violations, solution steps

3. **Output Generation**:

- Problem ID
- Approach (LLM-only, DSPy-only, Integrated)
- Success (boolean)

- Solution Steps (count)

4. **Analysis**:
- Calculate average metrics across all problems for each approach
- Perform statistical significance testing (paired t-test) to compare approaches
