binary-token-retrieval

Hypothesis

Binary Token Representations will significantly reduce computational cost while maintaining comparable retrieval accuracy compared to standard dense vector representations in legal document retrieval tasks.

Elements

  • Independent variable: Token representation method (Binary vs. Dense vector)
  • Dependent variables: Retrieval efficiency (speed), computational cost (memory usage), and retrieval accuracy (precision, recall, F1-score)
  • Comparison groups: Binary Token Representation vs. Standard dense vector representation
  • Baseline/control: Standard dense vector representation retrieval system
  • Context/setting: Legal document retrieval
  • Assumptions: Binary representations can maintain sufficient semantic information for effective retrieval
  • Relationship type: Causation
  • Population: Legal documents from publicly available datasets
  • Timeframe: Not time-dependent
  • Measurement method: Computational benchmarks and information retrieval metrics

Description

This research explores the use of Binary Token Representations (BTR) to enhance retrieval efficiency in information retrieval systems. By compressing token representations into binary formats, the research aims to reduce computational costs while maintaining retrieval accuracy. The study will focus on a single domain (legal documents) and implement a straightforward binary encoding scheme for document vectors. The research will compare the performance of the binary representation approach against a standard dense vector retrieval baseline, measuring both computational efficiency and retrieval accuracy. This simplified approach provides a focused investigation into the benefits of binary representations without the complexity of adaptive frameworks, making it suitable for researchers with limited resources while still offering potential insights into efficient retrieval methods.

Implementation Design

# Binary Token Representation for Efficient Legal Document Retrieval

## Implementation Details

### 1. Data Preparation
- Download a subset of legal documents from the LEDGAR dataset (https://huggingface.co/datasets/lex_glue/ledgar)
- Select 5,000 documents for the full experiment, with 1,000 for the pilot
- Preprocess documents by removing boilerplate text, normalizing whitespace, and tokenizing
- Create a set of 100 test queries by extracting key phrases from documents not in the retrieval set

### 2. Baseline Dense Vector System
- Use a pretrained legal domain model like Legal-BERT or a general model like BERT-base
- Generate document embeddings by averaging token embeddings for each document
- Store these embeddings in a vector database (FAISS or similar)
- Implement retrieval by computing query embeddings and finding nearest neighbors
- Measure and record memory usage and retrieval time

### 3. Binary Token Representation System
- Start with the same embeddings as the baseline system
- Implement binary quantization using one of these methods:
a. Simple thresholding: For each dimension, set to 1 if value > median, 0 otherwise
b. Iterative Quantization (ITQ): A more sophisticated approach that tries to preserve distances
- Convert all document embeddings to binary format
- Implement Hamming distance for similarity computation
- Store binary vectors efficiently using bit packing
- Measure and record memory usage and retrieval time

### 4. Evaluation
- For each system, retrieve top-k documents (k = 5, 10, 20) for each test query
- Compute precision@k, recall@k, and F1-score by comparing against relevance judgments
- Measure query processing time (average over 5 runs)
- Measure memory usage for storing embeddings
- Perform statistical significance testing (paired t-test) on performance differences
- Create visualizations comparing performance metrics

### 5. Output and Analysis
- Save all embeddings (both dense and binary) for reproducibility
- Record all performance metrics in CSV format
- Generate plots comparing retrieval accuracy vs. computational efficiency
- Analyze trade-offs between accuracy and efficiency
- Identify types of queries where binary representation performs well or poorly

## Pilot Experiment
- Use only 1,000 documents and 50 queries
- Implement only the simple thresholding method for binary quantization
- Focus on basic metrics: precision@10, memory usage, and query time
- Use results to refine the full experiment design

## Expected Results
- Binary representations should require significantly less memory (potentially 32x reduction from float32 to binary)
- Query processing should be faster with binary representations
- Retrieval accuracy may decrease slightly but should remain within 5-10% of the baseline
- The analysis should reveal specific conditions where binary representations are most beneficial

Operationalization

# Binary Token Representation for Legal Document Retrieval - Pilot Study

Implement a comparison between binary and dense vector representations for legal document retrieval, with three experimental modes (MINI_PILOT, PILOT, FULL_EXPERIMENT). The experiment should automatically stop after PILOT for human verification.

## Experiment Modes
- MINI_PILOT: Use 50 documents, 10 queries, run for quick verification (target: <5 minutes)
- PILOT: Use 500 documents, 50 queries (target: <1 hour)
- FULL_EXPERIMENT: Use 5000 documents, 500 queries (not to be run automatically)

## Implementation Steps

1. Dataset Preparation:
- Use the Huggingface Datasets API to load LEDGAR dataset
- For MINI_PILOT: First 50 documents
- For PILOT: First 500 documents
- For FULL_EXPERIMENT: First 5000 documents
- Create test queries by extracting key phrases from separate documents

2. Document Embedding (using gpt-4o-mini):
- Generate embeddings for each document
- Store original embeddings for baseline
- Log memory usage and generation time

3. Binary Representation:
- Implement simple median thresholding:
* For each dimension, compute median across all documents
* Convert values above median to 1, below to 0
- Store binary vectors using bit packing
- Log memory usage

4. Retrieval Implementation:
- Baseline: Cosine similarity with dense vectors
- Experimental: Hamming distance with binary vectors
- For each query:
* Get top-k results (k=5 for MINI_PILOT, k=10 for others)
* Record retrieval time
* Calculate precision@k

5. Evaluation:
- Compare retrieval times (mean, std)
- Compare memory usage
- Compare precision@k
- Use bootstrap resampling to test statistical significance
- Generate plots comparing metrics

6. Output Requirements:
- Save all raw results to CSV files
- Generate summary statistics
- Create performance comparison plots
- Log all experimental parameters

## Success Criteria
- Binary representation should use significantly less memory (expected: ~32x reduction)
- Retrieval time should be faster with binary representation
- Precision@k should be within 10% of dense vector baseline

## Required Logging
- All experimental parameters
- Memory usage at each stage
- Timing information for embedding generation and retrieval
- Precision@k for each query
- Statistical test results

Please implement the experiment starting with MINI_PILOT mode. If successful, proceed to PILOT mode, then stop for human verification before FULL_EXPERIMENT.
