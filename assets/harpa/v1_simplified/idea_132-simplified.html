ID: idea_132-simplified

Simple-Graph-QA

Hypothesis

A lightweight graph representation of table relationships will improve question answering accuracy on multi-table queries by enhancing the system's ability to identify relevant tables for a given question.

Elements

  • Independent variable: Use of graph representation for table relationships
  • Dependent variable: Accuracy of question answering on multi-table queries
  • Comparison groups: Graph-based approach vs. non-graph baseline
  • Baseline/control: Standard question answering without graph representation
  • Context/setting: Subset of TQA-Bench dataset (100-200 multi-table questions)
  • Assumptions: Graph representation can effectively capture table relationships
  • Relationship type: Causation
  • Population: Multi-table questions in the TQA-Bench dataset
  • Timeframe: Not applicable
  • Measurement method: Accuracy metrics (exact match, F1 score)

Description

This research explores a simplified approach to enhancing question answering over tabular data by implementing a basic graph representation of table relationships. Instead of the complex integration proposed in the original idea, this project focuses on creating a lightweight graph structure to represent relationships between tables in the TQA-Bench dataset, and using this structure to improve the routing of questions to relevant tables before applying standard QA techniques. The research will evaluate whether this simpler graph-based approach can improve accuracy on a subset of multi-table questions compared to a baseline that doesn't use graph representations.

Operationalization

Please implement a pilot experiment to evaluate whether a simple graph-based approach can improve table selection for multi-table question answering. The experiment should support three modes (PILOT_MODE): MINI_PILOT, PILOT, and FULL_EXPERIMENT.

Data Preparation:
- Use the Huggingface Datasets API to load TQA-Bench
- For MINI_PILOT: Select 10 multi-table questions requiring 2-3 tables each
- For PILOT: Select 50 multi-table questions
- For FULL_EXPERIMENT: Use 100-200 questions
- Split into train/dev/test (70/15/15)

Graph Construction:
1. Create a graph using NetworkX where:
- Nodes represent tables
- Edges represent relationships (shared column names or similar values)
- Store table metadata as node attributes
2. Export the graph visualization using DOT/Graphviz

Implement Three Approaches:
1. Graph-based approach:
- Use text similarity between question and table metadata
- Use graph traversal to find related tables
- Return top-3 most relevant tables

2. Baseline 1 (Keyword):
- Use simple keyword matching between question and table metadata
- Return top-3 matches

3. Baseline 2 (Random):
- Randomly select 3 tables

Question Answering:
- Use gpt-4o-mini through the proxy server
- Format selected tables as context
- Generate answers for each approach

Evaluation Pipeline:
1. For each question:
- Run all three approaches
- Record table selection accuracy
- Record answer accuracy
- Record F1 score

2. Statistical Analysis:
- Use bootstrap resampling to compare approaches
- Generate performance plots

Pilot Structure:
MINI_PILOT:
- 10 questions from training set
- Run full pipeline
- Basic accuracy metrics
- Simple graph visualization

PILOT:
- 50 questions (35 train, 15 dev)
- Full pipeline with all metrics
- Statistical comparisons
- Detailed error analysis on 5 random failures

FULL_EXPERIMENT (not to be run initially):
- 100-200 questions (70/15/15 split)
- Complete evaluation
- Error analysis on 20 failures

Required Outputs:
1. Logs of all operations
2. Graph visualization (PDF)
3. Performance plots (PDF)
4. Results CSV containing:
- Question ID
- Approach used
- Selected tables
- Answer generated
- Accuracy metrics
5. Statistical comparison results

Note: Use gpt-4o-mini for all LLM operations. Stop after PILOT and await human verification before proceeding to FULL_EXPERIMENT.
