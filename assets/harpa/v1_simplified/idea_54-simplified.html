ID: idea_54-simplified

simple-knowledge-editing

Hypothesis

Low-Rank Adaptation (LoRA) will demonstrate improved accuracy and consistency in editing commonsense knowledge in GPT-2 Small compared to traditional fine-tuning, while requiring fewer computational resources.

Elements

  • Independent variable: Knowledge editing method (LoRA vs. traditional fine-tuning)
  • Dependent variables: 1) Accuracy of edited knowledge, 2) Consistency of knowledge across contexts, 3) Computational resources required
  • Comparison groups: LoRA-edited model vs. traditionally fine-tuned model
  • Baseline/control: Unmodified GPT-2 Small model
  • Context/setting: Editing commonsense knowledge in GPT-2 Small
  • Assumptions: LoRA can be effectively applied to edit commonsense knowledge
  • Relationship type: Causation
  • Population: GPT-2 Small model
  • Timeframe: Two-week evaluation period
  • Measurement method: Comparison of accuracy, consistency, and computational resource metrics

Description

This research investigates the effectiveness of Low-Rank Adaptation (LoRA) for editing commonsense knowledge in smaller language models. Rather than combining multiple complex techniques, this study focuses solely on LoRA as a lightweight approach to knowledge editing. The research will evaluate how well LoRA can update specific commonsense facts in a small pre-trained language model (GPT-2 Small) compared to traditional fine-tuning methods. By focusing on a smaller model and a single editing technique, this research provides an accessible entry point to knowledge editing research while still addressing the important challenge of maintaining accurate commonsense knowledge in language models.

Operationalization

Please implement a pilot-based experiment to evaluate LoRA for commonsense knowledge editing in GPT-2 Small. The experiment should support three modes (PILOT_MODE): MINI_PILOT, PILOT, and FULL_EXPERIMENT.

Core Parameters by Mode:
MINI_PILOT:
- 3 commonsense facts
- 3 question variations per fact
- 1 training epoch
- Evaluate on training set only

PILOT:
- 10 commonsense facts
- 5 question variations per fact
- 2 training epochs
- Train on training set, evaluate on dev set

FULL_EXPERIMENT:
- 50 commonsense facts
- 5 question variations per fact
- 3 training epochs
- Train on training set, tune on dev set, final eval on test set

Implementation Steps:
1. Initialize logging and environment setup
2. Load GPT-2 Small using Huggingface Hub
3. Create knowledge dataset for current PILOT_MODE:
- Generate simple factual statements
- Create question variations
- Split into train/dev/test sets

4. Implement three model conditions:
a) Baseline: Unmodified GPT-2 Small
b) Fine-tuned: Traditional fine-tuning
c) LoRA: Using PEFT library (rank=8, alpha=16)

5. Training process:
- Record start time
- Monitor memory usage
- Track parameter counts
- Save checkpoints

6. Evaluation process:
- Use gpt-4o-mini to score model outputs
- Evaluate accuracy and consistency
- Measure computational metrics

7. Analysis:
- Calculate accuracy/consistency scores
- Perform bootstrap comparison tests
- Generate visualization plots
- Save detailed results
