ID: idea_10-simplified

simple-mbr-exec-evaluation

Hypothesis

Basic MBR-EXEC will produce higher execution success rates in Python programming tasks compared to traditional BLEU-based evaluation methods, even when applied to a limited set of examples.

Elements

  • Independent variable: Evaluation method (MBR-EXEC vs. BLEU-based)
  • Dependent variable: Execution success rate of generated Python code
  • Comparison groups: Code generated using MBR-EXEC vs. code generated using BLEU-based evaluation
  • Baseline/control: Traditional BLEU-based evaluation method
  • Context/setting: Small subset of Python programming tasks from MBPP
  • Assumptions: Basic MBR-EXEC is applicable and effective in the context
  • Relationship type: Causation
  • Population: Generated Python code solutions
  • Timeframe: Not specified
  • Measurement method: Execution success rate

Description

This research aims to evaluate a simplified version of execution result-based minimum Bayes risk decoding (MBR-EXEC) on a small subset of Python programming tasks. Rather than implementing multiple test cases and unit test filtering, this project focuses on comparing basic MBR-EXEC against a traditional BLEU-based evaluation method. The study will use a manageable subset of the MBPP dataset to assess whether execution-based evaluation improves code generation quality compared to text-similarity metrics. This simplified approach allows for a focused investigation with limited computational resources while still addressing an important question in code generation evaluation.

Operationalization

Please implement an experiment comparing basic MBR-EXEC against BLEU-based evaluation on Python programming tasks. The experiment should be implemented with three pilot modes (MINI_PILOT, PILOT, FULL_EXPERIMENT) defined by a global PILOT_MODE variable.

Pilot Modes:
- MINI_PILOT: Use 3 programming problems, 3 candidate solutions each
- PILOT: Use 10 programming problems, 5 candidate solutions each
- FULL_EXPERIMENT: Use 20 programming problems, 10 candidate solutions each

Core Implementation Steps:

1. Dataset Preparation:
- Download a subset of simple Python programming problems from MBPP dataset
- Each problem should have: description, one test case, reference solution
- MINI_PILOT: First 3 problems from training set
- PILOT: First 10 problems from training set
- FULL_EXPERIMENT: 20 problems (15 training, 5 dev)

2. Code Generation:
- Use gpt-4o-mini through the LLM proxy server
- For each problem:
* Generate multiple candidate solutions
* MINI_PILOT: 3 candidates
* PILOT: 5 candidates
* FULL_EXPERIMENT: 10 candidates
- Store all generated solutions

3. Evaluation Implementation:
a. MBR-EXEC approach:
- For each problem:
* Execute each candidate solution
* Use try/except for safe execution
* Set 5-second timeout for each execution
* Select solution that passes the test case
b. BLEU-based approach:
- For each problem:
* Calculate BLEU score between each candidate and reference
* Select solution with highest BLEU score

4. Metrics Collection:
For each problem and approach:
- Record execution success (0/1)
- Record BLEU score
- Record execution time
- Record any errors/exceptions

5. Analysis:
- Calculate overall execution success rate for each approach
- Calculate mean BLEU scores
- Perform bootstrap resampling to compare approaches
- Generate plots:
* Bar chart comparing success rates
* Box plot of BLEU scores

6. Output:
- Save all generated code and results to CSV
- Generate summary statistics
- Create visualization plots
- Log all major steps and any errors

Specific Requirements:
1. Use safe code execution with timeouts
2. Log all steps using the logger
3. Generate clear visualizations
4. Implement proper error handling
5. Save all intermediate results

Execution Flow:
1. Run MINI_PILOT first
2. If successful, run PILOT
3. Stop after PILOT (await human verification)
4. (FULL_EXPERIMENT requires manual activation)

Success Criteria:
- All code executes without errors
- Results are properly logged
- Visualizations are clear and informative
- Statistical comparisons are properly implemented
- All data is properly saved for analysis
