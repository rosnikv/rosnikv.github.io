ID: idea_102-simplified

simple-prompt-selection

Hypothesis

A simple rule-based prompt selection method will improve LLM precision and task performance across different input categories compared to using a single static prompt.

Elements

  • Independent variable: Prompt selection method (rule-based dynamic vs. static)
  • Dependent variable: LLM precision and task performance
  • Comparison groups: Rule-based prompt selection vs. static prompt
  • Baseline/control: Static prompt
  • Context/setting: Different input categories (e.g., technical questions, creative tasks, factual queries)
  • Assumptions: ['Pre-defined prompts can be effective for specific input categories', 'Input categories can be reliably identified using simple features']
  • Relationship type: Causation
  • Population: LLMs (specifically one accessible model like GPT-3.5-turbo)
  • Timeframe: ['Short-term experiment with fixed dataset']
  • Measurement method: ['Precision, recall, and F1-score for classification tasks', 'Task-specific metrics for other tasks']

Description

This research investigates a simplified approach to dynamic prompt selection for large language models (LLMs) when faced with different types of input data. Rather than implementing a full meta-controller as in DY-NAICL, this study will explore a rule-based approach to select from a small set of pre-defined prompts based on input features. The research will compare this simple dynamic selection method against a static prompt baseline, measuring improvements in precision and task performance across different data categories. This simplified approach maintains the core concept of adapting prompts to different inputs while being feasible for implementation with limited resources and technical expertise.

Operationalization

Please create an experiment to evaluate a simple rule-based prompt selection method for improving LLM performance across different input types. The experiment should use gpt-4o-mini as the base model.

The experiment should have three pilot modes (controlled by PILOT_MODE:str):

MINI_PILOT:
- Generate 9 examples (3 per category) using the Data Generation LLM
- Categories: technical questions, creative tasks, factual queries
- Run baseline (static prompt), experimental (rule-based), and random selection
- Maximum 2-3 minutes runtime

PILOT:
- Generate 90 examples (30 per category)
- Split: 70% training (63 examples), 30% testing (27 examples)
- Run all three conditions (baseline, experimental, random)
- Maximum 1 hour runtime

FULL_EXPERIMENT:
- Generate 150 examples (50 per category)
- Split: 70% training, 30% testing
- Run all conditions

Implementation Steps:

1. Dataset Generation:
- Use the Data Generation LLM to create examples for each category
- Technical questions: Programming/math problems
- Creative tasks: Story writing prompts
- Factual queries: Historical/scientific questions
- Store with category labels and expected outputs

2. Prompt Design:
- General prompt (baseline): 'Please provide a detailed, accurate response to the following: {input}'
- Technical prompt: 'You are a technical expert. Please solve this technical problem: {input}'
- Creative prompt: 'You are a creative writer. Please respond creatively to: {input}'
- Factual prompt: 'You are a knowledgeable expert. Please provide factual information about: {input}'

3. Rule-Based Selection:
- Technical: Match keywords like 'code', 'program', 'calculate', 'solve'
- Creative: Match 'write', 'create', 'imagine', 'story'
- Factual: Match 'what is', 'who was', 'when did', 'where is'
- Default to general prompt if no clear match

4. Evaluation:
- Technical: Accuracy (correct/incorrect)
- Creative: Length and keyword diversity
- Factual: Accuracy against ground truth
- Calculate precision/recall/F1 for category detection

5. Statistical Analysis:
- Use bootstrap resampling to compare:
* Baseline vs Rule-based
* Baseline vs Random
* Rule-based vs Random
- Generate plots of performance metrics

6. Logging:
- Log all inputs, selected prompts, outputs
- Log performance metrics
- Log statistical test results

The experiment should:
1. Start with MINI_PILOT
2. If successful, run PILOT
3. Stop after PILOT (await human verification)

Required outputs:
1. Performance metrics per condition
2. Statistical comparison results
3. Plots of performance across categories
4. Full logs of all runs
5. Dataset used (with categories)

Success criteria:
1. Rule-based selection shows better performance than baseline
2. Category detection accuracy > 80%
3. Statistical significance (p < 0.05) in bootstrap tests
