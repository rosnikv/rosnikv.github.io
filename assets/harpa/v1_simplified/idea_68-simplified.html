ID: idea_68-simplified

exemplar-schema-mini

Hypothesis

Language models fine-tuned with a small set of consistently formatted exemplars will perform better on unseen classification tasks than models fine-tuned with unformatted task definitions alone.

Elements

  • Independent variable: Instruction format (consistently formatted exemplars vs. unformatted task definitions)
  • Dependent variable: Performance (accuracy and precision) on unseen classification tasks
  • Comparison groups: Models fine-tuned with consistently formatted exemplars vs. models fine-tuned with unformatted task definitions
  • Baseline/control: Models fine-tuned with unformatted task definitions
  • Context/setting: Simple text classification tasks
  • Assumptions: The formatting schema is consistently applied and the exemplars are representative of the tasks
  • Relationship type: Causation
  • Population: Small pre-trained language models (e.g., DistilBERT, BERT-base)
  • Timeframe: Not specified
  • Measurement method: Accuracy and precision on unseen classification tasks

Description

This research investigates whether using a small set of consistently formatted exemplars improves language model performance on simple classification tasks compared to using unformatted task definitions alone. The study will focus on text classification tasks (such as sentiment analysis, topic classification, and intent detection) as they are well-defined and easier to evaluate. The research will use a small pre-trained language model (e.g., DistilBERT or BERT-base) and fine-tune it using two different approaches: (1) with task definitions formatted in a consistent schema along with a few exemplars, and (2) with only unformatted task definitions. The consistent schema will involve a simple template that breaks down each task into its objective, input format, output format, and constraints. For each task, 3-5 exemplars will be provided to demonstrate the expected input-output behavior. The models will then be evaluated on unseen classification tasks to measure their accuracy and precision. This simplified approach maintains the core idea of combining schema and exemplars while reducing the complexity and resource requirements of the original research.

Operationalization

Create an experiment to test whether consistently formatted exemplars improve language model performance on classification tasks. The experiment should use gpt-4o-mini as the base model.

The experiment should support three modes controlled by a PILOT_MODE variable:

MINI_PILOT:
- Use 5 examples each from 2 training tasks (sentiment and topic classification)
- Use 5 examples from evaluation task (intent detection)
- Run 2 evaluation rounds
- Maximum 10 steps per task

PILOT:
- Use 25 examples each from 2 training tasks
- Use 25 examples from evaluation task
- Run 5 evaluation rounds
- Maximum 25 steps per task

FULL_EXPERIMENT:
- Use 100 examples each from training tasks
- Use 100 examples from evaluation task
- Run 10 evaluation rounds
- Maximum 50 steps per task

Dataset Requirements:
1. Load small subsets of classification datasets using Huggingface Datasets:
- SST-2 (sentiment)
- AG News (topic)
- CLINC150 (intent)

Experimental Conditions:
1. Baseline Condition (unformatted):
Task prompt template:
"Classify the following text into [categories]. Text: [input_text]"

2. Experimental Condition (formatted with exemplars):
Task prompt template:
"Task: [task_name]\nObjective: [task_description]\nInput Format: A text string\nOutput Format: One of [categories]\nConstraints: Select exactly one category\n\nExamples:\n1. Input: [example1_input]\n Output: [example1_output]\n2. Input: [example2_input]\n Output: [example2_output]\n3. Input: [example3_input]\n Output: [example3_output]\n\nNow classify the following text:\n[input_text]"

Experiment Steps:
1. Initialize logging system for tracking all experimental steps

2. For each pilot mode:
a. Load datasets according to mode parameters
b. Format prompts for both conditions
c. Run classification tasks using gpt-4o-mini
d. Log all model inputs/outputs
e. Calculate accuracy and precision
f. Perform bootstrap resampling to test significance
g. Generate performance plots

3. Generate results including:
- Accuracy and precision for each condition
- Statistical significance tests
- Example correct/incorrect classifications
- Performance plots

Required Output Files:
1. results_[mode].csv containing:
- Condition (baseline/experimental)
- Task (sentiment/topic/intent)
- Example ID
- Input text
- True label
- Predicted label
- Correct (True/False)

2. summary_[mode].json containing:
- Overall accuracy per condition
- Precision per condition
- Bootstrap test results
- Confidence intervals

3. plots_[mode].pdf containing:
- Accuracy comparison plot
- Precision comparison plot
- Performance over time plot

Success Criteria:
1. All code runs without errors
2. Results files are generated correctly
3. Statistical tests are performed correctly
4. Plots are generated and saved

IMPORTANT NOTES:
1. Use gpt-4o-mini for all LLM calls
2. Run MINI_PILOT first
3. If MINI_PILOT succeeds, run PILOT
4. Stop after PILOT - do not run FULL_EXPERIMENT
5. Log all steps and errors comprehensively

7. Generate clear error messages for any failures
