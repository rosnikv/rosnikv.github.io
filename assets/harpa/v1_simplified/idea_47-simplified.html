ID: idea_47-simplified

simple-privacy-bert

Hypothesis

Applying differential privacy through gradient clipping and noise addition during fine-tuning will significantly reduce BERT model vulnerability to membership inference attacks in clinical text classification tasks, with only a modest decrease in classification accuracy.

Elements

Independent variable: Application of differential privacy (gradient clipping and noise addition) during BERT fine-tuning. Dependent variables: (1) Vulnerability to membership inference attacks, measured by attack success rate; (2) Model utility, measured by classification accuracy. Control: Standard BERT fine-tuning without privacy mechanisms. Setting: Clinical text classification tasks using publicly available datasets. Population: Pre-trained BERT models fine-tuned for clinical text classification.

Description

This research explores a simplified approach to enhancing privacy in BERT models trained on clinical text data. Rather than implementing complex token-level loss optimization and adversarial regularization techniques, this study focuses on evaluating how a basic differential privacy mechanism (gradient clipping and noise addition) affects BERT model vulnerability to membership inference attacks. The research will use a publicly available clinical text dataset and a pre-trained BERT model to investigate the trade-off between privacy protection and model utility. By implementing a straightforward differential privacy approach, the study aims to provide practical insights into privacy-preserving techniques for language models in sensitive domains, suitable for researchers with limited computational resources and experience.

Implementation Design

This experiment will evaluate how differential privacy affects BERT model vulnerability to membership inference attacks in clinical text classification. Follow these steps:

1. Data Preparation:
- Download a public clinical text classification dataset (e.g., i2b2 2014 de-identification challenge dataset or MIMIC-III clinical notes with associated labels).
- Preprocess the text data (tokenization, cleaning) and split into train/validation/test sets (60%/20%/20%).
- For the pilot, randomly sample 1000 examples from the dataset.

2. Model Implementation:
- Use Hugging Face's Transformers library to load a pre-trained BERT model (e.g., DistilBERT or BERT-base).
- Implement two fine-tuning approaches:
a) Standard fine-tuning (baseline): Fine-tune BERT on the training data using standard cross-entropy loss.
b) DP fine-tuning: Fine-tune BERT using differential privacy via the Opacus library, which implements gradient clipping and noise addition.
- For DP fine-tuning, experiment with different privacy budgets (ε values): [1.0, 2.0, 4.0, 8.0].

3. Membership Inference Attack Implementation:
- Implement a simple threshold-based membership inference attack:
a) For each example in the training and test sets, record the model's prediction loss.
b) Determine an optimal threshold that best separates training and test examples based on loss values.
c) Classify examples with loss below the threshold as 'member' and above as 'non-member'.
- Calculate attack success rate as the percentage of correctly classified examples (true positives + true negatives).

4. Evaluation:
- For each model (baseline and DP with different ε values), measure:
a) Classification accuracy on the test set.
b) Membership inference attack success rate.
- Plot a privacy-utility trade-off curve showing classification accuracy vs. attack success rate for different ε values.
- Calculate the privacy-utility trade-off ratio: the percentage decrease in attack success rate divided by the percentage decrease in classification accuracy.

5. Analysis and Reporting:
- Compare the baseline and DP models in terms of classification accuracy and vulnerability to membership inference attacks.
- Analyze how different ε values affect the privacy-utility trade-off.
- Report findings in a table showing ε values, classification accuracy, attack success rate, and privacy-utility trade-off ratio.
- Generate visualizations: privacy-utility trade-off curve, loss distributions for training vs. test examples.
- Save all models, results, and visualizations for future reference.

Code Organization:
- Create separate Python scripts for data preparation, model training, attack implementation, and evaluation.
- Use a configuration file to manage hyperparameters and experiment settings.
- Implement logging to track experiment progress and results.
- Save results in CSV format for easy analysis.

- Privacy budgets (ε): Test only two values [1.0, 8.0]
