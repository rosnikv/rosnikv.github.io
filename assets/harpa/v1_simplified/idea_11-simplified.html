ID: idea_11-simplified

emotion-detection-with-conceptnet

Hypothesis

Integrating relevant commonsense knowledge from ConceptNet will improve the accuracy of dialogue emotion detection compared to models without external knowledge.

Elements

  • Independent variable: Integration of ConceptNet knowledge (present vs. absent)
  • Dependent variable: Accuracy of dialogue emotion detection (F1-score)
  • Comparison groups: Baseline model without knowledge vs. model with ConceptNet knowledge
  • Baseline/control: Standard emotion detection model without external knowledge
  • Context/setting: Text-based dialogues from a public emotion-labeled dialogue dataset
  • Assumptions: ConceptNet contains relevant commonsense knowledge for understanding emotional contexts
  • Relationship type: Causation
  • Population: English-language dialogues from selected dataset
  • Timeframe: Not time-dependent
  • Measurement method: F1-score, precision, recall, and confusion matrix analysis

Description

This research explores how integrating commonsense knowledge from ConceptNet can improve emotion detection in dialogues. Rather than implementing a complex Graph Attention Network with dynamic knowledge selection, this simplified approach will use a static knowledge retrieval method to extract relevant ConceptNet triples based on dialogue content. The study will compare a baseline emotion detection model against one augmented with ConceptNet knowledge, focusing on a small, well-defined dialogue dataset. The research aims to quantify the impact of commonsense knowledge on emotion detection accuracy and identify which types of emotional contexts benefit most from external knowledge integration.

Implementation Design

This experiment will evaluate whether integrating commonsense knowledge from ConceptNet improves emotion detection in dialogues. Follow these steps:

1. Data Preparation:
- Download the EmpatheticDialogues dataset, which contains conversations labeled with emotions
- Preprocess the data by tokenizing, removing special characters, and splitting into train/validation/test sets (70%/15%/15%)
- For the pilot, use only 20% of the data to ensure quick iterations

2. Baseline Model Implementation:
- Use a pre-trained BERT model (bert-base-uncased) from Hugging Face
- Fine-tune it for emotion classification using the EmpatheticDialogues training set
- The model should take dialogue context as input and predict one of the emotion categories
- Save the trained model weights for later comparison

3. ConceptNet Knowledge Retrieval:
- Download a subset of ConceptNet (the English-language portion)
- Implement a simple knowledge retrieval function that:
a. Extracts key nouns, verbs, and adjectives from the dialogue using NLTK
b. Queries ConceptNet for related triples (subject, relation, object)
c. Ranks triples by relevance using simple word overlap with the dialogue
d. Selects the top-5 most relevant triples

4. Knowledge-Enhanced Model:
- Modify the baseline model to accept additional input
- For each dialogue, retrieve the top-5 ConceptNet triples
- Convert these triples to natural language (e.g., "cake HasProperty sweet" → "cake has property sweet")
- Concatenate these to the dialogue input with a separator token
- Fine-tune this model on the same training data

5. Evaluation:
- Evaluate both models on the test set
- Calculate and report F1-score, precision, and recall for each emotion category
- Generate a confusion matrix for each model
- Perform statistical significance testing (McNemar's test) to determine if improvements are significant
- Create a detailed analysis of which emotion categories benefit most from knowledge integration

6. Error Analysis:
- Identify 10 examples where the knowledge-enhanced model outperforms the baseline
- Identify 10 examples where the knowledge-enhanced model performs worse
- Analyze patterns in these examples to understand when knowledge helps or hurts

7. Output and Reporting:
- Save all model predictions to CSV files for further analysis
- Generate plots comparing performance across emotion categories
- Write a summary report with methodology, results, and analysis
- Include recommendations for future work on knowledge integration for emotion detection

Operationalization

Please implement an experiment to evaluate whether integrating ConceptNet knowledge improves emotion detection in dialogues. The experiment should support three modes controlled by a global PILOT_MODE variable:

MINI_PILOT:
- Use 10 dialogues from EmpatheticDialogues training set
- Retrieve max 2 ConceptNet triples per dialogue
- Run 2 epochs of training
- Quick verification of pipeline

PILOT:
- Use 100 dialogues from training set, 20 from validation
- Retrieve max 5 ConceptNet triples per dialogue
- Run 5 epochs of training
- Initial performance assessment

FULL_EXPERIMENT:
- Use full EmpatheticDialogues dataset
- Retrieve max 10 ConceptNet triples per dialogue
- Run full training (early stopping)
- Complete evaluation

Implementation Steps:

1. Dataset Preparation:
- Use Huggingface Datasets to load EmpatheticDialogues
- Select appropriate subset based on PILOT_MODE
- Split into train/val/test (70/15/15)
- Log dataset statistics

2. Knowledge Retrieval:
- Use ConceptNet Knowledge Base to extract relevant triples
- For each dialogue:
* Extract key terms using simple word matching
* Query ConceptNet for related triples
* Select top N triples (N varies by PILOT_MODE)
* Convert triples to natural language
- Log example knowledge retrievals

3. Model Implementation:
- Baseline: Use gpt-4o-mini to classify emotions directly
- Experimental: Add retrieved ConceptNet knowledge to input
- Format prompts as: "Classify the emotion in this dialogue: [dialogue]\nPossible emotions: [list]\nEmotion:"
- For experimental, add: "Related knowledge: [conceptnet_facts]\n"

4. Evaluation:
- Calculate F1-score, precision, recall per emotion
- Generate confusion matrices
- Use bootstrap resampling to test significance
- Create performance plots

5. Analysis:
- Log 5 examples where knowledge helps
- Log 5 examples where knowledge hurts
- Analyze patterns in these cases

Required Outputs:
1. Performance metrics CSV
2. Confusion matrix plots
3. Statistical test results
4. Error analysis report

Start with MINI_PILOT. If successful, proceed to PILOT. Stop before FULL_EXPERIMENT for human verification.

Note: Use gpt-4o-mini for all LLM calls as specified in conditioning instructions.
