ID: idea_119-simplified

simplified-sentiment-lexicon-toxicity

Hypothesis

Integrating a custom toxicity sentiment lexicon into a BERT-based toxicity detection model will improve accuracy, as measured by F1 score, compared to a standard BERT model.

Elements

  • Independent variable: Integration of a custom toxicity sentiment lexicon into a BERT-based toxicity detection model
  • Dependent variable: Accuracy of toxicity detection
  • Comparison groups: Standard BERT model vs. BERT model with custom lexicon integration
  • Baseline/control: Standard BERT model fine-tuned for toxicity detection
  • Context/setting: General population text data
  • Assumptions: Custom sentiment lexicons can be effectively integrated into BERT-based models
  • Relationship type: Causation
  • Population: General text data from social media or online forums
  • Timeframe: Not specified
  • Measurement method: F1 score

Description

This research explores the integration of a simple custom sentiment lexicon into a pre-trained BERT model for toxicity detection. Rather than focusing on multiple demographic groups, this simplified approach will create a single custom sentiment lexicon that captures domain-specific toxic language and integrate it with BERT's contextual understanding. The research will compare the performance of a standard BERT model for toxicity detection against a BERT model augmented with the custom sentiment lexicon. The goal is to determine whether this lightweight integration approach can improve toxicity detection accuracy across a general population, providing a foundation for more complex demographic-specific approaches in future work.

Operationalization

Please implement a pilot experiment comparing a baseline BERT toxicity classifier against one augmented with a custom toxicity lexicon. The experiment should support three modes (set via PILOT_MODE global variable):

MINI_PILOT:
- Dataset: 100 examples (70 train, 15 val, 15 test)
- Lexicon size: 20 words
- Training: 2 epochs
- Bootstrap iterations: 100

PILOT:
- Dataset: 1000 examples (700 train, 150 val, 150 test)
- Lexicon size: 50 words
- Training: 3 epochs
- Bootstrap iterations: 500

FULL_EXPERIMENT:
- Dataset: Full Jigsaw dataset
- Lexicon size: 200 words
- Training: Early stopping (max 5 epochs)
- Bootstrap iterations: 1000

Implementation Steps:

1. Dataset Preparation:
- Use Huggingface Datasets to load 'jigsaw-toxic-comment-classification-challenge'
- Subsample based on PILOT_MODE
- Split into train/val/test sets
- Log dataset statistics

2. Lexicon Creation:
- Use gpt-4o-mini to generate toxic words and assign toxicity scores (0-1)
- Prompt: 'Generate a list of [size] toxic words commonly found in online comments. For each word, assign a toxicity score between 0-1, where 1 is most toxic. Format as JSON: {"word": score}'
- Save lexicon to JSON file

3. Feature Extraction:
- For each text:
* Count toxic words
* Calculate mean toxicity score
* Calculate max toxicity score
- Normalize features to 0-1 range

4. Model Implementation:
Baseline:
- Load BERT-base-uncased
- Add classification head
- Train on binary toxicity labels

Experimental:
- Load BERT-base-uncased
- Concatenate [CLS] output with lexicon features
- Add classification head
- Train on binary toxicity labels

5. Training:
- Batch size: 16
- Learning rate: 2e-5
- Log loss/accuracy every 10 steps
- Plot training curves
- Save best model checkpoint

6. Evaluation:
- Calculate metrics (F1, precision, recall, accuracy)
- Perform bootstrap comparison
- Generate confusion matrices
- Log example predictions

7. Output:
- Save models
- Generate results CSV
- Create summary plots
- Output statistical analysis
