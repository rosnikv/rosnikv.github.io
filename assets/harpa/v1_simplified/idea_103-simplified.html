ID: idea_103-simplified

bert-sentiment-graph-enhancement

Hypothesis

Augmenting a pre-trained BERT model with features derived from a rule-based dependency graph will improve F1-score on aspect-based sentiment analysis tasks compared to using BERT alone.

Elements

  • Independent variable: Integration of dependency graph features with BERT embeddings
  • Dependent variable: Accuracy of aspect-based sentiment analysis
  • Comparison groups: BERT with graph features vs. BERT alone
  • Baseline/control: Standard fine-tuned BERT model
  • Context/setting: Aspect-based sentiment analysis on a subset of the SemEval dataset
  • Assumptions: Dependency relationships capture important sentiment information
  • Relationship type: Causation
  • Population: English restaurant reviews
  • Timeframe: Not applicable
  • Measurement method: Accuracy, Precision, Recall, and F1-score

Description

This research aims to enhance sentiment analysis by integrating a simple graph-based approach with a pre-trained BERT model. Instead of using complex GCNs and LLMs, this project will focus on creating a lightweight graph representation of text that captures basic relationships between sentiment-bearing words and aspects. The graph will be constructed using dependency parsing and simple rules, then features from this graph will be combined with BERT embeddings to improve sentiment classification. This approach addresses limitations in standard BERT models by incorporating structural information about sentiment relationships in text, potentially improving performance on aspect-based sentiment analysis tasks while remaining computationally efficient.

Implementation Design

This experiment will enhance BERT-based sentiment analysis with dependency graph features. Follow these steps:

1. Data Preparation:
- Download the SemEval 2014 Task 4 restaurant reviews dataset (or a similar aspect-based sentiment dataset)
- Preprocess the data: clean text, tokenize, and split into train/validation/test sets (70/15/15 split)
- Extract aspect terms and their sentiment polarities

2. Baseline BERT Implementation:
- Use the Hugging Face transformers library to load a pre-trained BERT-base-uncased model
- Fine-tune BERT for aspect-based sentiment classification by concatenating the aspect term with the review text using a [SEP] token
- Train for 3-5 epochs with early stopping based on validation performance
- Record performance metrics (accuracy, precision, recall, F1-score) on the test set

3. Dependency Graph Construction:
- Use spaCy to perform dependency parsing on each review
- Implement a rule-based system to extract relationships between aspect terms and sentiment words
- For each aspect term, identify sentiment words that are directly or indirectly connected to it in the dependency tree
- Create a simple feature vector for each aspect that includes:
* Distance to nearest sentiment word in the dependency tree
* Count of positive/negative sentiment words connected to the aspect
* Whether the aspect is modified by negation
- Use a predefined sentiment lexicon (like VADER or SentiWordNet) to determine word polarities

4. Enhanced BERT Model:
- Modify the BERT model to accept both text input and graph-derived features
- Concatenate the [CLS] token embedding from BERT with the graph feature vector
- Pass the combined representation through a simple feed-forward network for classification
- Train the enhanced model using the same training procedure as the baseline

5. Evaluation:
- Compare the performance of the baseline BERT and the graph-enhanced BERT on the test set
- Conduct statistical significance testing (e.g., McNemar's test) to verify improvements
- Analyze cases where the graph-enhanced model performs better or worse than the baseline
- Measure and compare inference time between the two models

6. Output and Reporting:
- Save the trained models and evaluation results
- Generate confusion matrices and performance metrics for both models
- Create visualizations of example dependency graphs where the enhancement helped
- Prepare a report summarizing the methodology, results, and conclusions

The code should be modular, with separate components for data processing, model training, graph construction, and evaluation. Use configuration files to make hyperparameters easily adjustable. Document all functions and include comments explaining the logic behind the graph feature extraction rules.
