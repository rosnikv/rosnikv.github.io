ID: idea_80-simplified

bias-evaluation-cda

Hypothesis

Fine-tuning a small language model on a dataset augmented with counterfactual examples that swap gendered terms will significantly reduce gender bias in the model's outputs compared to the same model fine-tuned on the original, unaugmented dataset.

Elements

  • Independent variable: Dataset used for fine-tuning (original vs. counterfactually augmented)
  • Dependent variable: Gender bias in model outputs
  • Comparison groups: Model fine-tuned on original dataset vs. model fine-tuned on counterfactually augmented dataset
  • Baseline/control: Model fine-tuned on original dataset without augmentation
  • Context/setting: Small, open-source language model (e.g., DistilBERT, BERT-small)
  • Assumptions: Counterfactual Data Augmentation will effectively reduce gender bias
  • Relationship type: Causation
  • Population: Text generated by the language model in response to gender-sensitive prompts
  • Timeframe: Not applicable
  • Measurement method: Established bias metrics (e.g., WEAT, StereoSet)

Description

This research explores the effectiveness of Counterfactual Data Augmentation (CDA) in reducing gender bias in a small pre-trained language model. The study will focus on implementing a simplified CDA approach by creating a balanced dataset where gendered terms are systematically swapped (e.g., 'he'/'she', 'man'/'woman'). The augmented dataset will be used to fine-tune a small, open-source language model. The research will evaluate the model's bias before and after fine-tuning using established bias metrics, providing insights into how effectively CDA can mitigate gender bias in language models without requiring extensive computational resources or complex reinforcement learning techniques.

Operationalization

Please implement an experiment to evaluate how Counterfactual Data Augmentation (CDA) affects gender bias in language models. The experiment should support three modes (PILOT_MODE): MINI_PILOT, PILOT, and FULL_EXPERIMENT.

Data Sizes by Mode:
- MINI_PILOT: 100 sentences, 1 epoch, 10 evaluation prompts
- PILOT: 1000 sentences, 2 epochs, 50 evaluation prompts
- FULL_EXPERIMENT: 10000 sentences, 3-5 epochs, 200 evaluation prompts

Implementation Steps:

1. Dataset Preparation:
- Use the Huggingface Datasets API to load a small subset of Wikipedia articles
- Create a gender term mapping dictionary: {'he':'she', 'him':'her', 'his':'her', 'man':'woman', etc.}
- Implement CDA by creating copies of sentences with gender terms swapped
- Split into train/validation sets (80/20)

2. Model Setup:
- Load DistilBERT-base-uncased from Huggingface
- Create two identical copies (baseline and experimental)
- Configure hyperparameters:
* MINI_PILOT: batch_size=4, learning_rate=2e-5
* PILOT: batch_size=8, learning_rate=2e-5
* FULL_EXPERIMENT: batch_size=16, learning_rate=2e-5

3. Training Loop:
- Fine-tune baseline model on original data
- Fine-tune experimental model on CDA-augmented data
- Log training loss, validation loss per epoch
- Save checkpoints after each epoch

4. Evaluation:
a) Custom Bias Evaluation:
- Create paired gender-sensitive prompts (e.g., 'The doctor said [he/she]...')
- Calculate probability difference between gendered variants
- Average bias scores across all prompt pairs

b) Model Quality Check:
- Calculate perplexity on validation set for both models
- Ensure CDA hasn't degraded model performance

5. Analysis:
- Use bootstrap resampling to compare bias scores between models
- Create line plots showing:
* Training/validation loss over epochs
* Bias scores distribution
* Perplexity comparison

6. Output Requirements:
- Save all results in a structured JSON format
- Generate PDF plots for all visualizations
- Log all experimental parameters and results

IMPORTANT NOTES:
1. Start with MINI_PILOT mode
2. If successful, proceed to PILOT mode
3. Stop after PILOT mode - do not run FULL_EXPERIMENT
4. Use gpt-4o-mini for any LLM calls
5. Log all steps and intermediate results
6. Include error handling and validation checks

Success Criteria:
1. Both models successfully train without errors
2. Bias evaluation shows measurable differences
3. Statistical analysis completed successfully
4. All visualizations generated
5. Results properly logged and saved
