Hypothesis

Boosting Dense Passage Retrieval results with keyword-based re-ranking will improve retrieval performance for low-frequency knowledge compared to using Dense Passage Retrieval alone.

Elements

  • Independent variable: Method of retrieval (DPR alone vs. DPR with keyword-based re-ranking)
  • Dependent variable: Retrieval performance (precision, recall, and mean reciprocal rank)
  • Comparison groups: DPR alone vs. DPR with keyword-based re-ranking
  • Baseline/control: Dense Passage Retrieval alone
  • Context/setting: Retrieving low-frequency knowledge from a small, curated dataset
  • Assumptions: Keyword extraction can identify terms that help prioritize relevant passages
  • Relationship type: Causation
  • Population: A small, curated dataset containing examples of low-frequency knowledge
  • Timeframe: Not specified
  • Measurement method: Precision, recall, and mean reciprocal rank metrics

Description

This research explores a simplified approach to enhancing Dense Passage Retrieval (DPR) with keyword extraction for improved information retrieval. Rather than developing a full Keyword Augmented Retrieval system, this project focuses on using existing keyword extraction techniques (like TF-IDF or RAKE) to identify important terms from queries, which are then used to boost the ranking of passages retrieved by a pre-trained DPR model. The study will implement this lightweight integration on a small, well-curated dataset containing examples of low-frequency knowledge, and evaluate whether this simple boosting approach improves retrieval performance compared to using DPR alone. This research provides an accessible entry point to investigating hybrid retrieval methods while requiring minimal computational resources and implementation complexity.

Implementation Design

# Keyword-Boosted Retrieval Experiment Design

## Overview
This experiment will evaluate whether enhancing Dense Passage Retrieval (DPR) with simple keyword extraction techniques improves retrieval performance for low-frequency knowledge. You will implement a system that combines DPR with keyword-based re-ranking and compare it against DPR alone and a keyword-only baseline.

## Implementation Details

### 1. Dataset Preparation
- Use a subset of the Natural Questions dataset (100-200 passages) that contains examples of low-frequency knowledge
- Create a test set of 20-30 queries that specifically target low-frequency information
- Ensure each query has known relevant passages (gold standard annotations)
- Split the data into development (80%) and test (20%) sets

### 2. Retrieval Systems Implementation

#### Baseline 1: Dense Passage Retrieval (DPR)
- Use a pre-trained DPR model from Hugging Face (e.g., facebook/dpr-question_encoder-single-nq-base and facebook/dpr-ctx_encoder-single-nq-base)
- Encode all passages in the dataset using the context encoder
- For each query, encode it using the question encoder and retrieve the top-k passages using cosine similarity

#### Baseline 2: Keyword-Based Retrieval
- Implement a simple BM25 retrieval system using the rank_bm25 library
- Index all passages in the dataset
- For each query, retrieve the top-k passages using BM25 scoring

#### Proposed Method: Keyword-Boosted DPR
- Use the same pre-trained DPR model as in Baseline 1
- Extract keywords from each query using one of these methods:
- TF-IDF: Use scikit-learn's TfidfVectorizer to identify important terms
- RAKE: Use the python-rake library to extract key phrases
- Retrieve the top-k*2 passages using DPR (to ensure we have a larger candidate pool)
- Re-rank these passages using a simple scoring function:
- Score = α * DPR_similarity + (1-α) * keyword_overlap_score
- Where keyword_overlap_score is the proportion of query keywords found in the passage
- Experiment with α values (0.3, 0.5, 0.7) to find the optimal balance

### 3. Evaluation
- For each system, calculate the following metrics on the test set:
- Precision@k (for k=1,3,5)
- Recall@k (for k=1,3,5)
- Mean Reciprocal Rank (MRR)
- Use paired t-tests to determine if differences between systems are statistically significant (p < 0.05)
- Perform a qualitative analysis of 5-10 examples where the keyword-boosted approach performs better or worse than DPR alone

### 4. Output and Reporting
- Save the retrieval results for each system in JSON format with the following structure:
```
{
"query_id": "q1",
"query_text": "what is the capital of france",
"extracted_keywords": ["capital", "france"],
"relevant_passage_ids": ["p42", "p57"],
"dpr_results": [{"passage_id": "p42", "rank": 1, "score": 0.85}, ...],
"bm25_results": [{"passage_id": "p57", "rank": 1, "score": 12.3}, ...],
"keyword_boosted_results": [{"passage_id": "p42", "rank": 1, "score": 0.92}, ...]
}
```
- Generate a summary report with tables showing the performance metrics for each system
- Include visualizations comparing the performance across different metrics and α values
- Document any interesting patterns or insights from the qualitative analysis

## Implementation Tips
- Use existing libraries whenever possible (Hugging Face transformers, rank_bm25, scikit-learn, etc.)
- Focus on the integration of components rather than implementing everything from scratch
- Start with a very small dataset for initial debugging before scaling to the full pilot dataset
- Save intermediate results to avoid recomputing expensive operations (like DPR encodings)
- Use a simple caching mechanism for DPR embeddings to speed up experimentation

Operationalization

Please implement a keyword-boosted retrieval experiment that compares DPR baseline against keyword-enhanced DPR retrieval. The experiment should support three modes (MINI_PILOT, PILOT, FULL_EXPERIMENT) with the following specifications:

Global Configuration:
- Set PILOT_MODE as a global string variable with possible values: 'MINI_PILOT', 'PILOT', 'FULL_EXPERIMENT'
- Initially set PILOT_MODE = 'MINI_PILOT'
- Use gpt-4o-mini for any LLM calls

Dataset Sizes:
- MINI_PILOT: 10 passages, 5 queries
- PILOT: 50 passages, 15 queries
- FULL_EXPERIMENT: 200 passages, 30 queries

Implementation Steps:

1. Dataset Preparation:
- Use the Huggingface Datasets API to load a subset of Natural Questions
- Filter for passages containing low-frequency information (use term frequency in the corpus as a proxy)
- Create splits based on PILOT_MODE size requirements
- Format data as: {passage_id: str, text: str, query: str, is_relevant: bool}

2. System Implementation:

A. DPR Baseline:
- Load pre-trained DPR model (facebook/dpr-question_encoder-single-nq-base)
- Encode passages and queries
- Implement cosine similarity ranking
- Return top-k results (k=5)

B. Keyword-Enhanced DPR:
- Extract keywords using TF-IDF
- Combine DPR similarity with keyword overlap using formula:
score = alpha * dpr_score + (1-alpha) * keyword_overlap
- Test alpha values: [0.3, 0.5, 0.7]

3. Evaluation Pipeline:
- Calculate metrics:
* Precision@k (k=1,3,5)
* Recall@k (k=1,3,5)
* Mean Reciprocal Rank
- Use bootstrap resampling to test statistical significance
- Generate plots comparing performance across methods

4. Output Format:

"keywords": List[str],
"relevant_passages": List[str],

5. Execution Flow:
1. Run MINI_PILOT first (should take <5 minutes)
2. If successful, proceed to PILOT (should take <30 minutes)
3. Stop after PILOT - await human verification before FULL_EXPERIMENT

6. Required Logging:

- For MINI_PILOT: Log every operation

7. Error Handling:

- Include cleanup of temporary files
