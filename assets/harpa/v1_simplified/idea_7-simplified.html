Hypothesis

Task-specific prompt personas will improve GPT-3.5-turbo's logic puzzle solving performance compared to static general personas or no personas, as measured by task accuracy and completion time.

Elements

  • Independent variable: Prompt-based persona configuration (task-specific, static general, or none)
  • Dependent variable: Logic puzzle solving performance
  • Comparison groups: Task-specific persona vs. static general persona vs. no persona
  • Baseline/control: No persona configuration
  • Context/setting: Logic puzzles of varying difficulty
  • Assumptions: Prompt-based personas can influence model behavior without modifying model activations
  • Relationship type: Causation
  • Population: GPT-3.5-turbo model instances
  • Timeframe: Single-session experiments
  • Measurement method: Task accuracy and completion time

Description

This research investigates how different prompt-based persona configurations affect GPT-3.5-turbo's performance on logic puzzles. Rather than implementing complex Role Vector embeddings that modify model activations, this study focuses on comparing different prompt-based persona approaches: (1) a static persona that remains constant throughout the interaction, (2) a task-specific persona tailored to logic puzzles, and (3) a baseline with no explicit persona. The research aims to determine which prompt-based approach yields better performance on a standardized set of logic puzzles, measuring both accuracy and completion time. This simplified approach maintains the core investigation of how model behavior can be guided through personas, but uses accessible prompt engineering techniques rather than requiring direct model modification.

# Experiment Design: Comparing Prompt-Based Personas for Logic Puzzle Solving

## 1. Implementation Details

### Prompt Configurations
Implement three different prompt configurations for GPT-3.5-turbo:

1. **Task-specific persona**: 'You are LogicSolverGPT, an expert in solving logic puzzles. You excel at breaking down problems step-by-step, identifying constraints, and methodically working through possible solutions until you find the correct answer.'

2. **Static general persona**: 'You are a helpful assistant.'

3. **No persona (baseline)**: No explicit persona statement, just present the puzzle directly.

### Logic Puzzle Dataset
Create a dataset of 30 logic puzzles divided into three difficulty levels:
- 10 Easy puzzles (e.g., simple deduction problems)
- 10 Medium puzzles (e.g., grid-based logic puzzles)
- 10 Hard puzzles (e.g., complex constraint satisfaction problems)

Each puzzle should have:
- A clear problem statement
- A single correct answer
- A verification method to check correctness

You can source puzzles from websites like 'Logic Puzzles' (logic-puzzles.org) or puzzle books, ensuring proper attribution.

### Experiment Procedure
1. For each puzzle and prompt configuration combination:
- Send the prompt + puzzle to the GPT-3.5-turbo API
- Record the complete response
- Track token count and response time
- Evaluate solution correctness

2. Use a consistent system prompt across all configurations, only varying the persona element.

3. For each puzzle, use the same temperature setting (0.7) and max tokens (1000).

4. Run each puzzle-prompt combination 3 times to account for model variability.

## 2. Pilot Experiment
For the pilot, select 3 puzzles from each difficulty level (9 total) and run them through all three prompt configurations once.

## 3. Data Collection and Analysis

### Data to Collect
For each run, record:
- Puzzle ID and difficulty level
- Prompt configuration used
- Complete model response
- Token count for response
- Response time
- Correctness of solution (binary: correct/incorrect)
- Number of reasoning steps taken (count explicit steps in response)
- Presence of logical errors (binary: present/absent)

### Data Storage
Store results in a CSV file with the following columns:
- `puzzle_id`: Unique identifier for the puzzle
- `difficulty`: Easy, Medium, or Hard
- `prompt_type`: Task-specific, Static, or None
- `run_id`: Run number (1-3)
- `correct`: Boolean (True/False)
- `token_count`: Integer
- `response_time_s`: Float (seconds)
- `reasoning_steps`: Integer
- `logical_errors`: Boolean (True/False)
- `full_response`: Text of complete response (store in separate text files if needed)

### Analysis
1. Calculate accuracy for each prompt configuration overall and by difficulty level
2. Compare mean token counts and response times across configurations
3. Run statistical tests (chi-square for accuracy, t-tests or ANOVA for token counts and times)
4. Create visualizations:
- Bar charts comparing accuracy across configurations
- Box plots for token counts and response times
- Line graphs showing performance by difficulty level
