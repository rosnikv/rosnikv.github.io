Hypothesis

Integrating a basic scene graph representation with the Chain of Draft (CoD) approach improves decision-making accuracy in 2D grid-based navigation tasks compared to using the Chain of Draft approach alone.

Elements

  • Independent variable: Integration of a basic scene graph representation with the Chain of Draft (CoD) approach
  • Dependent variable: Decision-making accuracy in navigation tasks
  • Comparison groups: Using the integrated scene graph and CoD approach vs. using the CoD approach alone
  • Baseline/control: Using the Chain of Draft (CoD) approach alone
  • Context/setting: 2D grid-based navigation tasks with static obstacles
  • Assumptions: The integration of a basic scene graph with CoD is feasible and applicable in the given context
  • Relationship type: Causation
  • Population: Simulated 2D grid-based navigation scenarios
  • Timeframe: Not specified
  • Measurement method: Success rate in reaching target locations and path optimality

Description

This research investigates the integration of a simplified Scene Graph representation with the Chain of Draft (CoD) approach for improving decision-making in a constrained robotic navigation task. Rather than implementing a full Scene Graph Simulator, this study focuses on using a basic graph-based representation of the environment to provide contextual information to the CoD process. The research will evaluate whether this lightweight integration improves decision-making accuracy in a 2D grid-based navigation scenario compared to using CoD alone. This simplified approach maintains the core concept of enhancing CoD with environmental context while being feasible for implementation with limited resources.

Implementation Design

# Experiment Design: Enhancing Chain of Draft with Basic Scene Graphs for 2D Navigation

## 1. Implementation Details

### 1.1 Chain of Draft (CoD) Baseline
Implement the Chain of Draft approach using an LLM (e.g., GPT-3.5-turbo) for navigation in a 2D grid environment:
- Create a prompt template that describes the navigation task, including start position, goal position, and a textual description of the environment.
- Implement the CoD approach where the LLM generates concise reasoning steps to determine the next move (up, down, left, right).
- After each move, update the agent's position and provide this information back to the LLM for the next decision.
- Record the path taken, success/failure, and number of steps.

### 1.2 Scene Graph Enhanced CoD
Extend the baseline implementation by adding a basic scene graph representation:
- Represent the 2D grid environment as a graph where nodes are grid cells and edges connect adjacent navigable cells.
- For each decision step, provide the LLM with:
- The current position
- The goal position
- A list of immediately adjacent cells and whether they are navigable
- A list of visible landmarks/obstacles within a 3-cell radius
- Use the same CoD prompting strategy but include this additional scene graph information.

### 1.3 Rule-based Navigation Baseline
Implement a simple A* pathfinding algorithm as a secondary baseline that:
- Takes the same grid environment as input
- Computes the optimal path from start to goal
- Records the path and number of steps

## 2. Data for Pilot Experiment

### 2.1 Environment Generation
- Create 10 different 2D grid environments of size 10x10
- Each environment should have:
- A designated start position
- A designated goal position
- Randomly placed obstacles covering 20-30% of the grid
- 3-5 labeled landmarks (e.g., "tree", "rock", "house")
- Ensure that a valid path exists between start and goal positions
- Save these environments in JSON format with the following structure:
```json
{
"grid_size": [10, 10],
"start": [x, y],
"goal": [x, y],
"obstacles": [[x1, y1], [x2, y2], ...],
"landmarks": [{"position": [x, y], "type": "tree"}, ...]
}
```

### 2.2 Task Definition
- For each environment, define 3 navigation tasks:
- Direct path: Start to goal with minimal obstacles in between
- Complex path: Start to goal with multiple obstacles requiring detours
- Landmark-based: Navigate to a specific landmark first, then to the goal

## 3. Output and Evaluation

### 3.1 Data Collection
For each approach (CoD, Scene Graph Enhanced CoD, Rule-based) and each task, record:
- The complete path taken (sequence of coordinates)
- Success or failure in reaching the goal
- Number of steps taken
- For LLM approaches: The reasoning provided at each step
- For LLM approaches: Number of backtracking or correction steps

Save this data in a structured format (JSON or CSV) with the following fields:
```
environment_id, task_type, approach, success, path_length, optimal_path_length, path_coordinates, backtrack_count, reasoning_steps
```

### 3.2 Analysis and Reporting
- Calculate and report the following metrics for each approach:
- Success rate (percentage of tasks completed successfully)
- Path optimality ratio (path length / optimal path length)
- Average number of backtracking steps (for LLM approaches)
- Perform statistical analysis:
- Conduct paired t-tests to determine if the difference between CoD and Scene Graph Enhanced CoD is statistically significant
- Calculate effect sizes (Cohen's d) to quantify the magnitude of improvement
- Generate visualizations:
- Bar charts comparing success rates and path optimality across approaches
- Sample path visualizations showing the different paths taken by each approach
- Heatmaps showing areas where each approach struggled or excelled

### 3.3 Error Analysis
- Categorize failures into types (e.g., collision with obstacle, inability to find path, exceeding step limit)
- Analyze the reasoning steps to identify patterns in decision-making errors
- Compare error patterns between CoD and Scene Graph Enhanced CoD

## 4. Implementation Notes
- Use Python for implementation
- Use the OpenAI API for LLM access
- Use NetworkX for graph representation and manipulation
- Use Matplotlib for visualization
- Structure the code in a modular way to allow for easy extension to more complex environments or approaches

Operationalization

Please implement an experiment comparing Chain of Draft (CoD) navigation with and without scene graph integration. The experiment should include three pilot modes (MINI_PILOT, PILOT, FULL_EXPERIMENT) with the following specifications:

PILOT SETTINGS:
- MINI_PILOT: 2 environments (5x5 grid), 3 episodes each, max 10 steps per episode
- PILOT: 5 environments (10x10 grid), 5 episodes each, max 25 steps per episode
- FULL_EXPERIMENT: 10 environments (10x10 grid), 10 episodes each, max 50 steps per episode

IMPLEMENTATION REQUIREMENTS:

1. Environment Setup:
- Create grid environments with start position, goal position, and obstacles
- For MINI_PILOT: 5x5 grid, 20% obstacles
- For PILOT/FULL: 10x10 grid, 20-30% obstacles
- Ensure valid path exists between start and goal
- Add 2-3 landmarks (e.g., 'tree', 'rock') for MINI_PILOT, 3-5 for larger pilots

2. Implement Three Approaches:
a) Baseline CoD:
- Use ReAct framework with gpt-4o-mini
- Input: Current position, goal position, visible obstacles
- Output: Next move (up/down/left/right)
- Record reasoning steps and actions

b) Scene Graph Enhanced CoD:
- Create DOT graph representation of environment
- Nodes: Grid cells
- Edges: Connections between adjacent navigable cells
- Include landmark information within 2-cell radius
- Use same ReAct framework but include graph information

c) A* Pathfinding Baseline:
- Implement simple A* for optimal path reference

3. Data Collection (per episode):
- Path taken (coordinate sequence)
- Success/failure
- Number of steps
- Path optimality ratio
- Reasoning steps (for LLM approaches)
- Number of backtracking steps

4. Evaluation Metrics:
- Success rate
- Path optimality (compared to A*)
- Average steps to goal
- Statistical significance using bootstrap resampling

5. Visualization Requirements:
- Plot environments with paths taken
- Bar charts comparing metrics
- Save all plots as PDFs

EXECUTION ORDER:
1. Run MINI_PILOT first
2. If successful, run PILOT
3. Stop after PILOT (await human verification)

OUTPUT REQUIREMENTS:
1. Log all experiment parameters and results
2. Generate summary statistics for each pilot phase
3. Save all raw data in JSON format
4. Create visualization PDFs
5. Report statistical comparisons between approaches

ERROR HANDLING:
- Log all LLM interaction errors
- Implement timeout for LLM calls (30 seconds)
- Save partial results if experiment interrupts

NOTE: Use gpt-4o-mini for all LLM calls as specified in conditioning instructions.
