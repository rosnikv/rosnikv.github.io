ID: idea_15-simplified

simplified-cod-scene-graph

Hypothesis

Integrating a basic scene graph representation with the Chain of Draft (CoD) approach improves decision-making accuracy in 2D grid-based navigation tasks compared to using the Chain of Draft approach alone.

Elements

  • Independent variable: Integration of a basic scene graph representation with the Chain of Draft (CoD) approach
  • Dependent variable: Decision-making accuracy in navigation tasks
  • Comparison groups: Using the integrated scene graph and CoD approach vs. using the CoD approach alone
  • Baseline/control: Using the Chain of Draft (CoD) approach alone
  • Context/setting: 2D grid-based navigation tasks with static obstacles
  • Assumptions: The integration of a basic scene graph with CoD is feasible and applicable in the given context
  • Relationship type: Causation
  • Population: Simulated 2D grid-based navigation scenarios
  • Timeframe: Not specified
  • Measurement method: Success rate in reaching target locations and path optimality

Description

This research investigates the integration of a simplified Scene Graph representation with the Chain of Draft (CoD) approach for improving decision-making in a constrained robotic navigation task. Rather than implementing a full Scene Graph Simulator, this study focuses on using a basic graph-based representation of the environment to provide contextual information to the CoD process. The research will evaluate whether this lightweight integration improves decision-making accuracy in a 2D grid-based navigation scenario compared to using CoD alone. This simplified approach maintains the core concept of enhancing CoD with environmental context while being feasible for implementation with limited resources.

Operationalization

Please implement an experiment comparing Chain of Draft (CoD) navigation with and without scene graph integration. The experiment should include three pilot modes (MINI_PILOT, PILOT, FULL_EXPERIMENT) with the following specifications:

PILOT SETTINGS:
- MINI_PILOT: 2 environments (5x5 grid), 3 episodes each, max 10 steps per episode
- PILOT: 5 environments (10x10 grid), 5 episodes each, max 25 steps per episode
- FULL_EXPERIMENT: 10 environments (10x10 grid), 10 episodes each, max 50 steps per episode

IMPLEMENTATION REQUIREMENTS:

1. Environment Setup:
- Create grid environments with start position, goal position, and obstacles
- For MINI_PILOT: 5x5 grid, 20% obstacles
- For PILOT/FULL: 10x10 grid, 20-30% obstacles
- Ensure valid path exists between start and goal
- Add 2-3 landmarks (e.g., 'tree', 'rock') for MINI_PILOT, 3-5 for larger pilots

2. Implement Three Approaches:
a) Baseline CoD:
- Use ReAct framework with gpt-4o-mini
- Input: Current position, goal position, visible obstacles
- Output: Next move (up/down/left/right)
- Record reasoning steps and actions

b) Scene Graph Enhanced CoD:
- Create DOT graph representation of environment
- Nodes: Grid cells
- Edges: Connections between adjacent navigable cells
- Include landmark information within 2-cell radius
- Use same ReAct framework but include graph information

c) A* Pathfinding Baseline:
- Implement simple A* for optimal path reference

3. Data Collection (per episode):
- Path taken (coordinate sequence)
- Success/failure
- Number of steps
- Path optimality ratio
- Reasoning steps (for LLM approaches)
- Number of backtracking steps

4. Evaluation Metrics:
- Success rate
- Path optimality (compared to A*)
- Average steps to goal
- Statistical significance using bootstrap resampling

5. Visualization Requirements:
- Plot environments with paths taken
- Bar charts comparing metrics
- Save all plots as PDFs

EXECUTION ORDER:
1. Run MINI_PILOT first
2. If successful, run PILOT
3. Stop after PILOT (await human verification)

OUTPUT REQUIREMENTS:
1. Log all experiment parameters and results
2. Generate summary statistics for each pilot phase
3. Save all raw data in JSON format
4. Create visualization PDFs
5. Report statistical comparisons between approaches

ERROR HANDLING:
- Log all LLM interaction errors
- Implement timeout for LLM calls (30 seconds)
- Save partial results if experiment interrupts

NOTE: Use gpt-4o-mini for all LLM calls as specified in conditioning instructions.
