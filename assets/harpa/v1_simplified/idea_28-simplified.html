ID: idea_28-simplified

simple-semantic-retrieval-benchmark

Hypothesis

Augmenting an LLM with semantic retrieval will significantly improve its precision and recall in question answering tasks compared to the same LLM without retrieval augmentation.

Elements

  • Independent variable: Use of semantic retrieval augmentation
  • Dependent variable: Precision and recall of LLM responses
  • Comparison groups: LLM with semantic retrieval vs. LLM without retrieval
  • Baseline/control: Standard LLM without retrieval
  • Context/setting: Question answering tasks on a static benchmark dataset
  • Assumptions: Pre-trained embedding models can effectively capture semantic similarity for retrieval purposes
  • Relationship type: Causation
  • Population: LLMs used in question answering applications
  • Timeframe: Not time-dependent (using static benchmark)
  • Measurement method: Precision and recall metrics

Description

This research aims to evaluate the effectiveness of semantic retrieval techniques in improving the precision and recall of Large Language Models (LLMs) for question answering tasks. Instead of implementing a complex dynamic benchmarking system like DyKnow, this simplified study will focus on comparing a basic semantic retrieval augmented LLM against a standard LLM without retrieval on a static benchmark dataset. The research will use pre-trained embedding models to implement semantic retrieval, retrieving relevant documents from a curated corpus based on query similarity. The performance will be evaluated using standard precision and recall metrics, with the hypothesis that semantic retrieval will significantly improve the LLM's ability to provide accurate answers by grounding responses in relevant information.

Implementation Design

This experiment will evaluate whether semantic retrieval improves LLM performance on question answering tasks.

1. Implementation:
a. Document Corpus: Create a small corpus by collecting 100-200 Wikipedia articles on diverse topics. Store these as plain text files with clear titles.
b. Embedding System: Use a pre-trained sentence transformer model (e.g., 'all-MiniLM-L6-v2' from sentence-transformers) to create vector embeddings for all documents in the corpus.
c. Retrieval System: Implement a function that takes a question, converts it to an embedding using the same model, and retrieves the top-k most similar documents using cosine similarity.
d. LLM Interface: Set up an interface to a publicly available LLM API (e.g., OpenAI's GPT-3.5-turbo).
e. Retrieval-Augmented System: Create a system that takes a question, retrieves relevant documents, and then prompts the LLM with both the question and the retrieved context.
f. Baseline System: Create a system that sends questions directly to the LLM without retrieval.

2. Data:
a. Create or obtain a test set of 50-100 factual questions that can be answered using information in your document corpus.
b. Ensure questions span multiple domains (e.g., science, history, geography).
c. Create a ground truth file with correct answers for each question.

3. Experiment Procedure:
a. For each question in the test set:
i. Process it through the baseline system (LLM only).
ii. Process it through the retrieval-augmented system (retrieval + LLM).
iii. For the retrieval system, experiment with retrieving different numbers of documents (k=1, 3, 5).
b. Save all system outputs to a results file, including the question, retrieved documents (if applicable), and generated answers.

4. Evaluation:
a. Calculate precision and recall for both systems by comparing generated answers against ground truth.
b. Calculate F1 score as the harmonic mean of precision and recall.
c. For the retrieval system, also calculate Mean Reciprocal Rank (MRR) to evaluate retrieval quality.
d. Perform statistical significance testing (e.g., paired t-test) to determine if differences in performance are statistically significant.
e. Conduct error analysis by categorizing the types of errors made by each system.

5. Output and Reporting:
a. Generate tables comparing precision, recall, and F1 scores for both systems.
b. Create visualizations showing performance differences across different domains.
c. Report on the impact of varying the number of retrieved documents (k).
d. Provide examples of questions where retrieval significantly improved or hurt performance.
e. Summarize findings and discuss implications for future research.

Operationalization

Please implement a semantic retrieval benchmark experiment comparing an LLM with and without retrieval augmentation. The experiment should be implemented in three possible modes (controlled by PILOT_MODE global variable): MINI_PILOT, PILOT, and FULL_EXPERIMENT.

Data Generation and Setup:
1. Use the Huggingface Datasets API to download a subset of Wikipedia articles (science, history, geography). For MINI_PILOT: 10 articles. For PILOT: 50 articles. For FULL_EXPERIMENT: 200 articles.

2. Generate test questions using the LLM:
- MINI_PILOT: 10 questions (2-3 from each domain)
- PILOT: 50 questions (15-20 from each domain)
- FULL_EXPERIMENT: 200 questions (60-70 from each domain)
Generate questions using gpt-4o-mini with the prompt: 'Given this article, generate a specific factual question that can be answered using only information from this article. The question should be clear and have a single correct answer.'

3. For each question, generate a ground truth answer using gpt-4o-mini with the source article.

Implementation:
1. Create two systems:
a. Baseline: Direct LLM (gpt-4o-mini) question answering
b. Experimental: Semantic retrieval augmented LLM
- Convert all documents to embeddings using sentence-transformers
- For each question:
* Convert to embedding
* Find top-k similar documents (k=1 for MINI_PILOT, k=1,3,5 for PILOT/FULL)
* Combine question + retrieved docs in prompt
* Get LLM answer

2. For each question:
a. Run baseline system
b. Run experimental system
c. Log full inputs/outputs, including retrieved documents

Evaluation:
1. Calculate metrics:
- Precision: % of answers that are correct
- Recall: % of answerable questions that were answered
- F1 Score: Harmonic mean of precision/recall
- MRR: Mean Reciprocal Rank of correct document in retrieved set

2. Statistical Testing:
- Use bootstrap resampling to compare baseline vs experimental
- Report p-values and confidence intervals

3. Visualization:
- Create line plots showing performance across different k values
- Plot performance by domain

Output Requirements:
1. results.json: Contains all raw results
2. metrics.json: Contains computed metrics
3. plots/: Directory containing all visualizations
4. log.txt: Detailed logging of experiment progress

Execution Order:
1. Always start with MINI_PILOT
2. If successful, proceed to PILOT
3. Stop after PILOT - await human verification before FULL_EXPERIMENT

Logging Requirements:
1. Log all major steps and decisions
2. Log all errors and exceptions
3. Log timing information for major components
4. For MINI_PILOT, log extra debugging information

Error Handling:
1. Implement robust error handling for API calls
2. Cache intermediate results to prevent data loss
3. Implement rate limiting for API calls

Validation Steps:
1. Verify question generation quality
2. Verify embedding creation
3. Verify retrieval quality
4. Verify metric calculations
