ID: idea_35-simplified

simple-ngram-contamination-detection

Hypothesis

If GPT-3.5 is evaluated using N-gram Overlap Detection for data contamination, then its BLEU scores will more accurately reflect its true capabilities on a subset of the British National Corpus.

Elements

  • Independent variable: Use of N-gram Overlap Detection for contamination identification
  • Dependent variable: BLEU scores on the British National Corpus subset
  • Comparison groups: Evaluation with contamination detection vs. without contamination detection
  • Baseline/control: Standard evaluation without contamination detection
  • Context/setting: Subset of the British National Corpus (approximately 1,000 samples)
  • Assumptions: N-gram Overlap Detection can effectively identify potential data contamination
  • Relationship type: Causation
  • Population: GPT-3.5
  • Timeframe: Not specified
  • Measurement method: BLEU scores

Description

This research investigates the impact of using N-gram Overlap Detection to evaluate GPT-3.5's performance on historical English texts from the British National Corpus. The study focuses on a manageable subset of the corpus (approximately 1,000 text samples) to make the project feasible for a student researcher. By implementing a simple N-gram Overlap Detection method, the research aims to identify potential data contamination in the model's training data that might artificially inflate performance metrics. The project will compare BLEU scores calculated with and without contamination detection to determine if removing potentially contaminated samples leads to a more accurate assessment of the model's capabilities. This simplified approach addresses an important issue in NLP evaluation while remaining within the technical and resource constraints of an undergraduate or MSc research project.

Implementation Design

This experiment will evaluate whether N-gram Overlap Detection can identify data contamination in GPT-3.5's evaluation on historical English texts, leading to more accurate performance assessment.

1. Implementation:
a. N-gram Overlap Detection:
- Implement a function to extract n-grams (n=2,3,4) from text samples
- For each evaluation sample, calculate the percentage of n-grams that appear in other samples
- Set a threshold (e.g., 30% overlap) to flag potentially contaminated samples
b. Text Generation with GPT-3.5:
- For each sample in the evaluation set, use the first 50 words as a prompt
- Generate a continuation of similar length to the original text
- Store both the original text and the generated continuation
c. BLEU Score Calculation:
- Calculate BLEU scores comparing generated text to original text
- Implement two evaluation modes: with all samples and with contaminated samples removed

2. Data:
a. Download a subset of the British National Corpus (BNC)
- Focus on historical texts from the 18th-19th centuries
- Select approximately 1,000 samples of 200-300 words each
- Split into 80% for the main evaluation and 20% for the pilot
b. Preprocessing:
- Clean text (remove special characters, normalize whitespace)
- Tokenize text for n-gram extraction
- Store processed samples in a CSV file with unique identifiers

3. Output and Evaluation:
a. Generate the following outputs:
- CSV file with all samples, their n-gram overlap percentages, and contamination flags
- CSV file with BLEU scores for each sample in both evaluation modes
- Summary statistics (mean, median, standard deviation) of BLEU scores in both modes
- Histogram plots comparing BLEU score distributions
b. Statistical Analysis:
- Perform a paired t-test to determine if the difference in BLEU scores is statistically significant
- Calculate the effect size (Cohen's d) to quantify the magnitude of the difference
c. Qualitative Analysis:
- Manually review 20 samples flagged as contaminated to verify accuracy
- Document patterns in false positives/negatives

4. Implementation Steps:
a. Set up the environment with required libraries
b. Download and preprocess the BNC subset
c. Implement the N-gram Overlap Detection function
d. Set up the GPT-3.5 API connection and text generation pipeline
e. Implement BLEU score calculation
f. Run the pilot experiment on 100 samples
g. Analyze pilot results and adjust parameters if needed
h. Scale to the full experiment with 1,000 samples
i. Generate all outputs and perform statistical analysis
j. Document findings and limitations

Operationalization

Please implement an experiment to evaluate GPT-4o-mini using N-gram Overlap Detection for data contamination assessment. The experiment should follow a pilot-based approach with three modes (MINI_PILOT, PILOT, FULL_EXPERIMENT) defined by a global variable PILOT_MODE.

Data Scope:
- MINI_PILOT: 10 samples from BNC
- PILOT: 100 samples from BNC
- FULL_EXPERIMENT: 1000 samples from BNC

Core Steps:
1. Dataset Preparation:
- Use Huggingface Datasets to load the British National Corpus
- Filter for historical texts (18th-19th centuries)
- Select samples based on PILOT_MODE
- Clean and preprocess text (remove special characters, normalize whitespace)

2. N-gram Processing:
- Implement functions to extract 2-grams, 3-grams, and 4-grams
- For each sample, calculate overlap percentages with other samples
- Flag samples as contaminated if overlap exceeds 30%

3. Text Generation:
- Use gpt-4o-mini (via LLM proxy) to generate continuations
- Input: First 50 words of each sample
- Output: Generate continuation matching original length

4. Evaluation:
- Calculate BLEU scores for each sample in two conditions:
a) All samples
b) Non-contaminated samples only
- Implement random baseline (remove same percentage randomly)
- Use bootstrap resampling to compare conditions

5. Visualization:
- Create histograms of BLEU scores for each condition
- Plot overlap percentages distribution

Output Requirements:
1. CSV files containing:
- Sample texts and their n-gram overlap percentages
- BLEU scores for all conditions
- Contamination flags
2. Statistical analysis results:
- Bootstrap comparison results
- Effect sizes
3. Visualization PDFs:
- BLEU score distributions
- Overlap percentage distributions

Execution Flow:
1. Run MINI_PILOT first (10 samples)
2. If successful, proceed to PILOT (100 samples)
3. Stop after PILOT - await human verification before FULL_EXPERIMENT

Logging Requirements:
- Log all major steps and decisions
- Record any errors or warnings
- Save intermediate results at each stage

Success Criteria:
1. Successfully processes samples according to PILOT_MODE
2. Identifies potentially contaminated samples

4. Generates all required visualizations and outputs
