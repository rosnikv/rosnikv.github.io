ID: idea_112-simplified

simple-tapp-classification

Hypothesis

Adding explicit answer choices to prompts improves the performance of large language models on zero-shot text classification tasks compared to prompts without explicit answer choices.

Elements

  • Independent variable: Presence of explicit answer choices in prompts
  • Dependent variable: Performance of large language models on zero-shot text classification tasks
  • Comparison groups: Prompts with explicit answer choices vs. prompts without explicit answer choices
  • Baseline/control: Prompts without explicit answer choices
  • Context/setting: Zero-shot text classification tasks
  • Assumptions: Explicit answer choices help guide model responses
  • Relationship type: Causation
  • Population: Open-source large language models
  • Timeframe: Not specified
  • Measurement method: Accuracy and F1 score

Description

This research explores whether adding explicit answer choices to prompts improves zero-shot text classification performance of large language models. Rather than implementing the full Task-Agnostic Prefix Prompt (TAPP) approach with cross-task demonstrations, this simplified study focuses on comparing standard classification prompts with and without explicit answer choices on a small set of classification tasks. The study will use a publicly available pre-trained language model and evaluate performance on established text classification benchmarks. This approach maintains the core hypothesis about explicit answer choices while reducing implementation complexity and computational requirements.

Operationalization

Please create an experiment to test whether adding explicit answer choices to prompts improves zero-shot text classification performance. The experiment should have the following components:

1. PILOT MODE SETTINGS:
Implement a global PILOT_MODE variable that can be set to one of:
- MINI_PILOT: Use 2 datasets (AG News and SST-2), 10 examples each from training set
- PILOT: Use 2 datasets, 100 examples each from training (for initial testing) and dev set (for evaluation)
- FULL_EXPERIMENT: Use all datasets, full train/dev/test splits

Start with MINI_PILOT, then if successful, run PILOT. Stop before FULL_EXPERIMENT for human verification.

2. DATASETS:
Use the Huggingface datasets library to load:
- AG News (4 categories: World, Sports, Business, Tech)
- SST-2 (2 categories: Positive, Negative)

3. MODEL:
Use gpt-4o-mini through the LLM proxy server for all experiments.

4. PROMPT TEMPLATES:
For each dataset, create two prompt types:
a) Standard (baseline):
"Classify the following text into one of these categories: [CATEGORIES]. Text: [INPUT]"

b) Explicit Answer Choices (experimental):
"Classify the following text into one of these categories: [CATEGORIES]. Your answer must be exactly one of: [CATEGORY_LIST]. Text: [INPUT]"

5. EVALUATION PIPELINE:
a) For each example:
- Format both prompt versions
- Get model predictions using gpt-4o-mini
- Extract predicted category
- Compare to ground truth
- Log full prompt, response, and correctness

b) For each dataset:
- Calculate accuracy and macro F1 score
- Generate confusion matrix
- Create visualization comparing prompt types
- Perform bootstrap resampling to test statistical significance

6. OUTPUT:
a) Results directory structure:
/results/
/MINI_PILOT/
raw_predictions.csv
metrics.json

performance_plots.pdf
/PILOT/
[same structure]

[same structure]

b) Metrics to track:
- Overall accuracy per prompt type
- Per-category F1 scores
- Statistical significance (p-value from bootstrap test)
- Confusion matrices

7. LOGGING:
- Log all experimental parameters
- Log all raw model inputs/outputs
- Log any errors or unexpected behaviors
- Log timing information

8. VISUALIZATION:
- Bar plots comparing accuracy between prompt types
- Line plots showing per-category F1 scores
- Confusion matrices for each condition

Please implement the experiment starting with MINI_PILOT mode. After successful completion, proceed to PILOT mode, then stop for human verification before FULL_EXPERIMENT.

Success Criteria:
1. Code runs without errors
2. All metrics are properly calculated
