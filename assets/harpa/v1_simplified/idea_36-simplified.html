ID: idea_36-simplified

simple-attention-text-molecule-retrieval

Hypothesis

Implementing a basic attention mechanism in a text-to-molecule retrieval system will improve precision and recall compared to non-attention baselines by focusing on relevant features across modalities.

Elements

  • Independent variable: Presence of a basic attention mechanism
  • Dependent variable: Precision and recall in retrieval tasks
  • Comparison groups: Attention-based model vs. non-attention baseline
  • Baseline/control: Simple embedding-based retrieval without attention
  • Context/setting: Text-to-molecule retrieval using a public dataset
  • Assumptions: Basic attention mechanisms can effectively connect relevant features across modalities
  • Relationship type: Causation
  • Population: Text-molecule pairs from a public dataset
  • Timeframe: Single experiment with multiple evaluation runs
  • Measurement method: Precision@k, Recall@k, Mean Reciprocal Rank

Description

This research investigates the effectiveness of a simple attention mechanism in a text-to-molecule retrieval system. Instead of implementing a complex dual-stream architecture with adaptive attention, this project focuses on a single-stream model with a basic attention mechanism that connects text descriptions to molecular fingerprints. The study will evaluate whether even a simplified attention approach can improve retrieval performance compared to non-attention baselines. This research provides an accessible entry point into cross-modal retrieval while still offering potential insights into how attention mechanisms can bridge the gap between natural language and molecular representations.

Implementation Design

This experiment will implement and evaluate a simple attention mechanism for text-to-molecule retrieval. Follow these steps:

1. Data Preparation:
- Download the ChEBI-20 dataset, which contains molecule-text pairs.
- Process molecules into Morgan fingerprints using RDKit (radius=2, nBits=1024).
- Split the dataset into training (70%), validation (15%), and test (15%) sets.

2. Model Implementation:
- Text Encoder: Use a pre-trained sentence-transformer model (e.g., 'all-MiniLM-L6-v2') to encode text descriptions.
- Molecule Encoder: Implement a simple feedforward neural network (2 layers) to project Morgan fingerprints to the same dimension as text embeddings.
- Attention Mechanism: Implement a basic dot-product attention mechanism between text and molecule embeddings.
- Retrieval System: Calculate similarity scores between a query text and all molecules in the database.

3. Baseline Implementation:
- Implement a non-attention baseline that encodes text and molecules separately and calculates cosine similarity directly between embeddings.

4. Training:
- Train the attention model using contrastive loss (e.g., InfoNCE) to maximize similarity between paired text-molecule examples and minimize similarity for non-paired examples.
- Use the validation set to tune hyperparameters and prevent overfitting.

5. Evaluation:
- Evaluate both the attention model and baseline on the test set.
- Calculate Precision@k and Recall@k for k=1, 5, and 10.
- Calculate Mean Reciprocal Rank (MRR).
- Perform statistical significance testing (e.g., paired t-test) to compare the performance of the attention model against the baseline.

6. Analysis:
- Analyze cases where the attention model performs better or worse than the baseline.
- Visualize attention weights for a few examples to understand what features the model focuses on.

7. Output and Reporting:
- Save the trained models and evaluation results.
- Generate a report with tables and figures showing performance metrics.
- Include visualizations of attention weights for representative examples.

The code should be modular and well-documented, with separate components for data processing, model implementation, training, and evaluation.

Operationalization

Please implement a text-to-molecule retrieval experiment comparing a simple attention mechanism against a non-attention baseline. The experiment should be implemented in three pilot phases, controlled by a global PILOT_MODE variable.

Data Requirements:
MINI_PILOT:
- Use 50 molecule-text pairs total (35 train, 8 validation, 7 test)
- Maximum 5 training epochs
- Evaluate with k=1,3 for Precision@k/Recall@k

PILOT:
- Use 1000 molecule-text pairs total (700 train, 150 validation, 150 test)
- Maximum 10 training epochs
- Evaluate with k=1,5,10 for Precision@k/Recall@k

FULL_EXPERIMENT:
- Use the complete ChEBI-20 dataset
- Maximum 50 training epochs
- Evaluate with k=1,5,10,20 for Precision@k/Recall@k

Implementation Steps:

1. Dataset Preparation:
- Use the Huggingface Datasets API to load the ChEBI-20 dataset
- For each molecule:
* Generate Morgan fingerprints (radius=2, nBits=512 for MINI_PILOT/PILOT, 1024 for FULL)
* Store the SMILES string and text description
- Split data according to pilot mode specifications

2. Model Implementation:
Baseline Model:
- Text: Use gpt-4o-mini to generate text embeddings (dimension=384)
- Molecule: Single feedforward layer (input: fingerprint_size, output: 384)
- Similarity: Cosine similarity between embeddings

Experimental Model:
- Text: Same as baseline
- Molecule: Same initial layer as baseline
- Attention: Simple dot-product attention between text and molecule embeddings
- Output: Weighted sum of attention outputs

3. Training Loop:
- Use batch size 16 for MINI_PILOT, 32 for PILOT, 64 for FULL_EXPERIMENT
- Implement InfoNCE contrastive loss
- Log training/validation loss every epoch
- Save best model based on validation loss

4. Evaluation:
- Calculate Precision@k and Recall@k for specified k values
- Calculate Mean Reciprocal Rank
- Use bootstrap resampling to compare baseline vs experimental performance
- Generate plots showing:
* Training/validation loss curves
* Precision@k and Recall@k comparisons
* MRR comparison

5. Analysis and Reporting:
- Save all metrics in JSON format
- Generate summary plots using matplotlib
- For each pilot phase, report:
* Final training/validation losses
* All evaluation metrics with confidence intervals
* Statistical significance of differences

IMPORTANT NOTES:
1. Start with MINI_PILOT mode
2. Only proceed to PILOT if MINI_PILOT succeeds
3. Stop after PILOT - do not run FULL_EXPERIMENT
4. Log all major steps and any errors
5. Save all models and results with clear pilot phase labels

Required Output Format:
1. results.json: Contains all metrics and comparisons
2. models/: Directory containing saved models
3. plots/: Directory containing all visualizations
4. logs/: Directory containing execution logs

Error Handling:
- Log all errors with stack traces
- Save partial results if execution fails
- Include error summary in results.json
