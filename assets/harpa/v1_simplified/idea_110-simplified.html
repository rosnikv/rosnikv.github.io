ID: idea_110-simplified

SQP-Basic-Retrieval

Hypothesis

Self-Questioning Prompting combined with basic keyword retrieval will improve the accuracy of LLM responses to gastroenterology questions compared to standard prompting.

Elements

  • Independent variable: Prompting technique (SQP with basic retrieval vs. standard prompting)
  • Dependent variable: Accuracy of LLM responses
  • Comparison groups: LLM responses using SQP with basic retrieval vs. standard prompting
  • Baseline/control: Standard prompting without retrieval
  • Context/setting: Gastroenterology question answering
  • Assumptions: The integration of SQP with basic retrieval is feasible and can be implemented with limited resources.
  • Relationship type: Causation
  • Population: LLM responses to gastroenterology questions
  • Timeframe: Not specified
  • Measurement method: Accuracy measurement against reference answers

Description

This research explores the effectiveness of combining Self-Questioning Prompting (SQP) with a basic keyword-based retrieval system to improve LLM responses to gastroenterology questions. Instead of implementing complex semantic retrieval with vector embeddings, this simplified approach will use keyword matching to retrieve relevant information from a small, curated dataset of gastroenterology texts. SQP will be implemented by designing prompts that encourage the LLM to generate and answer its own questions about the gastroenterology topic before providing a final response. The hypothesis is that this combined approach will lead to more accurate responses compared to standard prompting without retrieval. This research focuses on a practical implementation that can be accomplished with limited resources while still providing valuable insights into how simple retrieval and prompting techniques can enhance LLM performance in specialized domains.

Operationalization

Please implement an experiment to evaluate whether Self-Questioning Prompting (SQP) with basic keyword retrieval improves LLM responses to gastroenterology questions. The experiment should support three modes (PILOT_MODE): MINI_PILOT, PILOT, and FULL_EXPERIMENT.

Pilot Settings:
- MINI_PILOT: Use 10 gastroenterology questions, 2 source texts, evaluate with gpt-4o-mini
- PILOT: Use 50 gastroenterology questions, 5 source texts, evaluate with gpt-4o-mini
- FULL_EXPERIMENT: Use 200 questions, 15 source texts (not implemented in this phase)

Implementation Steps:

1. Dataset Generation:
- Use the Data Generation with LLM codeblock to create gastroenterology questions
- Prompt: "Generate a gastroenterology question and its reference answer. The question should be factual and have a clear, objective answer. Format as JSON with keys 'question' and 'reference_answer'. Example topics: inflammatory bowel disease, GERD, peptic ulcers."
- Save questions and reference answers in a JSON file

2. Keyword Retrieval System:
- Use WordNet to extract medical/technical terms from questions
- For each question, count keyword overlap with each paragraph in source texts
- Return top 2 paragraphs with highest overlap

3. Implement Three Conditions:
a. Baseline: Standard prompting
- Prompt: "Answer this gastroenterology question: [QUESTION]"
b. Retrieval Only:
- Prompt: "Answer this gastroenterology question using the provided context: [QUESTION]\nContext: [RETRIEVED_TEXT]"
c. SQP + Retrieval (Experimental):
- Prompt: "I'll provide you with a gastroenterology question and relevant context. First, generate 2-3 questions that would help better understand the main question. Then answer those questions using the context. Finally, provide a comprehensive response to the original question.\n\nQuestion: [QUESTION]\nContext: [RETRIEVED_TEXT]"

4. Evaluation Process:
- For each question:
* Generate responses using all three conditions
* Score accuracy (0/1) by comparing to reference answer
* Rate relevance and completeness (1-5 scale)
- Save results in CSV: question_id, question, condition, response, accuracy, relevance, completeness

5. Analysis:
- Calculate mean scores for each condition
- Use bootstrap resampling to compare conditions
- Generate plots of accuracy, relevance, completeness distributions

Execution Order:
1. Run MINI_PILOT first (10 questions)
2. If successful, run PILOT (50 questions)
3. Stop before FULL_EXPERIMENT for human verification

Logging Requirements:
- Log all LLM calls, responses, and scores
- Log timing information for each component
- Log any errors or unexpected behaviors

Output Requirements:
1. Results CSV file with all responses and scores
2. Summary statistics for each condition
3. Bootstrap comparison results
4. Error analysis highlighting any systematic patterns

Note: Use gpt-4o-mini for all LLM calls as specified in the conditioning instructions.
