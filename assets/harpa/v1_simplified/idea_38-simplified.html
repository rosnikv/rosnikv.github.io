ID: idea_38-simplified

basic-syntactic-diversity-icl

Hypothesis

Using three demonstrations with high syntactic diversity improves the accuracy of in-context learning in text summarization tasks compared to using three demonstrations with low syntactic diversity.

Elements

  • Independent variable: Syntactic diversity in demonstrations (high vs. low)
  • Dependent variable: Accuracy of in-context learning in text summarization tasks
  • Comparison groups: Three demonstrations with high syntactic diversity vs. three demonstrations with low syntactic diversity
  • Baseline/control: Three demonstrations with low syntactic diversity
  • Context/setting: Text summarization tasks using a public dataset
  • Assumptions: Syntactic diversity can be measured and manipulated in a meaningful way
  • Relationship type: Causation
  • Population: News articles from CNN/Daily Mail dataset
  • Timeframe: Not time-dependent
  • Measurement method: ROUGE scores for summarization quality

Description

This research investigates how syntactic diversity in demonstrations affects in-context learning (ICL) performance for text summarization. Rather than exploring multiple variables simultaneously, this study focuses specifically on comparing high versus low syntactic diversity in a fixed number of demonstrations (three). The experiment will use a publicly available summarization dataset and an accessible language model to determine if demonstrations with diverse sentence structures lead to better summarization performance compared to demonstrations with similar sentence structures. This targeted approach allows for a meaningful contribution while requiring fewer resources and less technical expertise than the original proposal.

Operationalization

Please create an experiment to test whether high syntactic diversity in demonstrations improves in-context learning performance for text summarization compared to low diversity. The experiment should be implemented in three pilot modes (MINI_PILOT, PILOT, FULL_EXPERIMENT), with the following specifications for each:

MINI_PILOT:
- Use 5 articles from CNN/Daily Mail training set for demonstration selection pool
- Select 2 test articles
- Run basic verification that the pipeline works

PILOT:
- Use 50 articles from CNN/Daily Mail training set for demonstration selection pool
- Select 20 test articles from validation set
- Full analysis pipeline, but smaller scale

FULL_EXPERIMENT:
- Use 200 articles from training set for demonstration selection pool
- Select 100 test articles from test set
- Complete analysis

Implementation Steps:

1. Dataset Loading:
- Use Huggingface Datasets API to load CNN/Daily Mail dataset
- Log the number of articles loaded and basic statistics

2. Demonstration Selection:
- For each article in the demonstration pool:
* Split into sentences
* Calculate syntactic diversity score (unique dependency patterns / total sentences)
* Store scores in a dictionary
- Select demonstrations:
* High diversity: Top 15% of diversity scores (select 3)
* Low diversity: Bottom 15% of diversity scores (select 3)
- Log the selected demonstrations and their scores

3. Experiment Setup:
- For each test article:
* Create two prompts (high diversity demos vs low diversity demos)
* Format: "Please summarize the following article. Here are some examples:\n\n[3 demonstrations]\n\nNow summarize this article: [test article]"
* Use gpt-4o-mini to generate summaries
* Calculate ROUGE scores (1, 2, L) against reference summaries
* Store results in a dictionary

4. Analysis:
- Calculate mean, std of ROUGE scores for each condition
- Use bootstrap resampling to compare conditions
- Generate plots comparing ROUGE scores
- Save all results to JSON files

Required Output Files:
1. experiment_log.txt: Detailed logging of each step
2. diversity_scores.json: Syntactic diversity scores for all articles
3. selected_demonstrations.json: The selected demonstrations for each condition
4. results.json: All generated summaries and their ROUGE scores
5. analysis.json: Statistical analysis results
6. plots/rouge_comparison.pdf: Visualization of results

Notes:
- Start with MINI_PILOT mode
- If successful, proceed to PILOT mode
- Stop before FULL_EXPERIMENT (requires manual verification)
- Use gpt-4o-mini for all LLM calls
- Log all major steps and any errors
- Save intermediate results frequently

Success Criteria:
1. Pipeline runs without errors
2. Demonstrations show clear diversity difference between conditions
3. ROUGE scores are calculated successfully
4. Statistical analysis shows whether differences are significant
5. All results are properly logged and saved
