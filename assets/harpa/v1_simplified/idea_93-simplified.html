ID: idea_93-simplified

simplified-consistency-evaluation

Hypothesis

A simplified content-unit evaluation approach will provide better alignment with human judgments of semantic consistency in abstractive summarization compared to traditional metrics like ROUGE.

Elements

  • Independent variable: Evaluation method (simplified content-unit approach vs. traditional metrics)
  • Dependent variable: Alignment with human judgments of semantic consistency
  • Comparison groups: Summaries evaluated with simplified content-unit approach vs. traditional metrics
  • Baseline/control: ROUGE score evaluation
  • Context/setting: Abstractive summarization on a subset of CNN/Daily Mail dataset
  • Assumptions: Content-unit analysis improves evaluation; human evaluations are a valid standard
  • Relationship type: Correlation
  • Population: LLM-generated abstractive summaries
  • Timeframe: Not specified
  • Measurement method: Pearson correlation with human evaluations

Description

This research aims to evaluate the effectiveness of a simplified approach to semantic consistency evaluation in abstractive summarization. Rather than implementing the full Decompose and Aggregate framework with LLM-ACU integration, this study focuses on using a basic atomization technique to break down summaries into content units and evaluate their semantic consistency with source documents. The research will compare this simplified approach against traditional metrics like ROUGE on a small subset of the CNN/Daily Mail dataset, examining whether atomization-based evaluation better aligns with human judgments of summary quality. This provides a focused investigation into whether even basic content unit analysis can improve evaluation methods for LLM-generated summaries.

Operationalization

Please implement a pilot experiment to evaluate a simplified content-unit approach for semantic consistency assessment in abstractive summarization. The experiment should support three modes (PILOT_MODE): MINI_PILOT, PILOT, and FULL_EXPERIMENT.

Data sizes for different pilot modes:
- MINI_PILOT: 5 articles from CNN/Daily Mail training set
- PILOT: 25 articles from CNN/Daily Mail training set
- FULL_EXPERIMENT: 50 articles (40 train, 5 dev, 5 test)

Implementation Steps:

1. Dataset Preparation:
- Use the Huggingface datasets library to load CNN/Daily Mail dataset
- Select articles based on PILOT_MODE
- For each article, generate a summary using T5-base model
- Store article-summary pairs in a simple CSV format

2. Content Unit Extraction:
- Use NLTK's sentence tokenizer to break summaries into sentences
- Each sentence is considered one content unit
- Store the content units in the CSV, one per row

3. Semantic Consistency Evaluation:
- For each content unit, use gpt-4o-mini to evaluate consistency
- Prompt template: "Rate how consistent this statement is with the source text (1-5):\nStatement: [content_unit]\nSource: [source_text]\nRate ONLY with a number 1-5, where 1 is completely inconsistent and 5 is perfectly consistent."
- Calculate average score across content units for each summary

4. ROUGE Baseline:
- Calculate ROUGE-1, ROUGE-2, ROUGE-L scores for each summary
- Store scores in the CSV

5. Human Evaluation:
- MINI_PILOT: 3 summaries, 2 evaluators
- PILOT: 10 summaries, 3 evaluators
- FULL_EXPERIMENT: 15 summaries, 5 evaluators
- Create simple text files for human evaluators with clear instructions
- Store human scores in CSV

6. Analysis:
- Calculate Pearson correlation between:
a) Human scores vs content-unit scores
b) Human scores vs ROUGE scores
- Use bootstrap resampling to compare correlations
- Create scatter plots of relationships

7. Output:
- Save all data in a structured CSV with columns:
* article_id
* source_text
* generated_summary
* content_units (JSON list)
* consistency_scores (JSON list)
* avg_consistency_score
* rouge_1
* rouge_2
* rouge_l
* human_scores (JSON list)
* avg_human_score
- Generate plots:
* Scatter plot: Human vs Content-Unit scores
* Scatter plot: Human vs ROUGE scores
- Save statistical analysis results

Important Notes:
1. Use gpt-4o-mini for all LLM evaluations (not GPT-3.5-turbo)
2. Run MINI_PILOT first, then PILOT if successful
3. Stop before FULL_EXPERIMENT for human verification
4. Log all steps and intermediate results
5. Include error handling for LLM calls
6. Save checkpoints after each major step

Success Criteria:
1. All data processing steps complete without errors
2. Correlations are calculated and statistically valid
3. Visualizations are clear and properly labeled
4. Results are reproducible (use fixed random seeds)
5. All output files are properly formatted and saved
