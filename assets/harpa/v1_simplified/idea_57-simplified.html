ID: idea_57-simplified

simple-tot-reasoning-for-slms

Hypothesis

A Small Language Model using a simplified Tree-of-Thought reasoning approach will achieve better task planning performance than the same model using standard prompting techniques in a simulated household environment.

Elements

  • Independent variable: Reasoning approach (Tree-of-Thought vs. standard prompting)
  • Dependent variable: Task planning performance (success rate, planning steps quality, and planning time)
  • Comparison groups: SLM with Tree-of-Thought reasoning vs. SLM with standard prompting
  • Baseline/control: SLM with standard prompting
  • Context/setting: Simplified virtual household environment with predefined tasks
  • Assumptions: The SLM has sufficient capabilities to benefit from structured reasoning
  • Relationship type: Causation
  • Population: Household planning tasks
  • Timeframe: Not specified
  • Measurement method: Automated evaluation of task planning success and quality

Description

This research explores the potential of implementing a simplified Tree-of-Thought (ToT) reasoning approach for Small Language Models (SLMs) to enhance their performance on household task planning. Rather than building a complex hybrid system with collaborative mechanisms, this project focuses on adapting the ToT reasoning framework to work effectively with a single SLM in a simplified virtual home environment. The study will compare the performance of an SLM with ToT reasoning against the same SLM using standard prompting techniques on a set of predefined household tasks. The research aims to determine whether structured reasoning paths can improve task planning capabilities in resource-constrained language models, providing insights into efficient reasoning techniques for smaller AI models.

Operationalization

Please implement a pilot experiment comparing Tree-of-Thought (ToT) reasoning versus standard prompting for household task planning using gpt-4o-mini. The experiment should have three pilot modes (MINI_PILOT, PILOT, FULL_EXPERIMENT) with the following specifications:

PILOT MODES:
1. MINI_PILOT:
- 3 household tasks (1 simple, 1 medium, 1 complex)
- 5 evaluation runs per task
- Purpose: Quick debugging and verification
- Runtime target: 5-10 minutes

2. PILOT:
- 6 household tasks (2 each: simple, medium, complex)
- 10 evaluation runs per task
- Purpose: Initial assessment of approach viability
- Runtime target: 30-60 minutes

3. FULL_EXPERIMENT:
- 15 household tasks (5 each: simple, medium, complex)
- 25 evaluation runs per task
- Purpose: Complete experimental evaluation
- Runtime target: 3-4 hours

PLEASE START WITH MINI_PILOT MODE.

EXPERIMENTAL SETUP:

1. Task Generation:
- Use the Data Generation LLM to create household tasks at three complexity levels
- Simple tasks: 'make tea', 'turn on TV'
- Medium tasks: 'set table for four people', 'organize desk'
- Complex tasks: 'prepare full breakfast', 'clean and reorganize refrigerator'
- For each task, generate:
* Task description
* List of required objects
* Success criteria
* Expected sequence of steps (for evaluation)

2. Implement Two Conditions:

A. Baseline (Standard Prompting):
Prompt template:
"Please create a step-by-step plan for the following household task: [TASK_DESCRIPTION]\nAvailable objects: [OBJECTS]\nCreate a detailed, feasible plan."

B. Experimental (Tree-of-Thought):
Five-step prompt template:
"Task: [TASK_DESCRIPTION]\nAvailable objects: [OBJECTS]\n\n1. First, understand the goal:\n[Your understanding]\n\n2. List required objects and key actions:\n[List objects and actions]\n\n3. Generate two possible action sequences:\nPlan A: [First sequence]\nPlan B: [Second sequence]\n\n4. Evaluate each sequence:\nPlan A evaluation: [Evaluation]\nPlan B evaluation: [Evaluation]\n\n5. Select and justify the best plan:\n[Selection and justification]"

3. Evaluation Metrics:
For each generated plan, score:
- Completeness (0-1): Does it achieve the task goal?
- Efficiency (0-1): Avoids unnecessary steps
- Feasibility (0-1): All steps are possible
- Overall score: Average of above metrics
- Also record: Generation time, token count

4. Analysis Steps:
a. Calculate mean scores for each condition
b. Use bootstrap resampling to test for significant differences
c. Generate plots comparing performance metrics
d. Save detailed logs of all generations and scores

5. Required Output:
a. JSON results file with structure:
{
"task_id": str,
"complexity": str,
"baseline": {
"plan": str,
"scores": {
"completeness": float,
"efficiency": float,
"feasibility": float,
"overall": float
},
"metrics": {
"time": float,
"tokens": int
}
},
"tot": {similar structure as baseline}
}

b. Performance plots:
- Bar charts comparing metrics
- Line plots showing performance by task complexity

c. Statistical analysis report

IMPORTANT NOTES:
1. Use gpt-4o-mini for all LLM calls
2. Start with MINI_PILOT mode
3. Log all major steps and errors
4. Save all generated plans and evaluations
5. Stop after PILOT mode for human verification

Success Criteria:
1. Code runs without errors in MINI_PILOT mode
2. All metrics are properly calculated and logged
3. Statistical comparisons are performed correctly
4. Visualization clearly shows performance differences
5. Results are saved in specified JSON format
