ID: idea_129-simplified

simple-socratic-reasoning

Hypothesis

Applying structured Socratic prompting techniques will significantly improve GPT-2 medium's performance on arithmetic reasoning tasks compared to standard prompting approaches.

Elements

  • Independent variable: Prompting technique (Socratic prompting vs. standard prompting)
  • Dependent variable: Arithmetic reasoning accuracy of GPT-2 medium
  • Comparison groups: GPT-2 medium with Socratic prompting vs. GPT-2 medium with standard prompting
  • Baseline/control: GPT-2 medium with standard prompting
  • Context/setting: Using a curated dataset of arithmetic problems
  • Assumptions: Socratic prompting will guide the model through a more structured reasoning process
  • Relationship type: Causation
  • Population: GPT-2 medium model
  • Timeframe: Not specified
  • Measurement method: Accuracy on arithmetic reasoning tasks

Description

This research investigates the effectiveness of Socratic reasoning techniques on a small language model's arithmetic problem-solving capabilities. Rather than implementing the full Socratic Chain-of-Thought with Early-Stopping Self-Consistency, this simplified study focuses on applying basic Socratic questioning prompts to guide GPT-2 medium through arithmetic reasoning tasks. The study will use a small, curated dataset of arithmetic problems of varying difficulty levels to evaluate whether structured Socratic prompting can improve the model's reasoning abilities compared to standard prompting. This approach reduces computational requirements while still exploring how reasoning frameworks can enhance smaller language models' capabilities on structured tasks.

Implementation Design

This experiment will evaluate whether Socratic prompting techniques can improve GPT-2 medium's arithmetic reasoning capabilities. Follow these steps:

1. Setup:
- Install the required libraries: transformers, numpy, pandas, matplotlib
- Load the pre-trained GPT-2 medium model using the Hugging Face transformers library
- Create a curated dataset of 100 arithmetic problems divided into three difficulty levels: simple (e.g., single-digit addition/subtraction), moderate (e.g., multi-digit operations, simple word problems), and complex (e.g., multi-step word problems)

2. Prompting Templates:
- Standard Prompt: "Solve the following arithmetic problem: [PROBLEM]"
- Socratic Prompt: "I need to solve this arithmetic problem: [PROBLEM]. Let me break this down step by step. What information do I have? What operation(s) should I perform? Let me calculate each step carefully. The final answer is:"

3. Experiment Implementation:
- For each problem in the dataset:
a. Apply the standard prompting approach and record the model's answer
b. Apply the Socratic prompting approach and record the model's answer
c. Run each prompt 3 times to assess consistency
- Calculate accuracy for each approach (percentage of correct answers)
- Analyze the quality of reasoning steps in the Socratic approach using a simple rubric (identifies relevant information, applies correct operations, shows calculations, reaches correct conclusion)

4. Data Collection:
- For each problem and approach, save:
a. The problem text
b. The prompt used
c. The model's complete response
d. The extracted final answer
e. Whether the answer is correct (binary)
f. For Socratic prompting, a score for reasoning quality (0-3)
- Save all results to a CSV file for analysis

5. Analysis:
- Calculate overall accuracy for each approach
- Calculate accuracy by difficulty level for each approach
- Perform statistical significance testing (McNemar's test) to determine if differences in accuracy are significant
- Create visualizations comparing performance across approaches and difficulty levels
- Analyze common error patterns in each approach

6. Reporting:
- Generate a summary report with:
a. Overall accuracy comparison
b. Performance breakdown by difficulty level
c. Statistical significance results
d. Sample responses showing reasoning differences between approaches
e. Discussion of limitations and potential improvements

The experiment should be run on a machine with at least 8GB RAM. All code should be organized in a modular fashion with separate functions for data loading, prompting, evaluation, and analysis.

Operationalization

Please create an experiment to evaluate whether Socratic prompting improves arithmetic reasoning capabilities compared to standard prompting. The experiment should follow these specifications:

1. PILOT MODES AND DATASET:
Implement a PILOT_MODE variable with three settings:
- MINI_PILOT: Generate and evaluate 10 arithmetic problems (5 simple, 5 moderate). Run each problem 2 times per condition.
- PILOT: Generate and evaluate 50 arithmetic problems (20 simple, 20 moderate, 10 complex). Run each problem 3 times per condition.
- FULL_EXPERIMENT: Generate and evaluate 100 arithmetic problems (40 simple, 40 moderate, 20 complex). Run each problem 5 times per condition.

For dataset generation, use the Data Generation with LLM codeblock to create arithmetic problems. Example prompt for generation:
"Generate a [DIFFICULTY] arithmetic problem. The problem should be clear and have a single, unambiguous numerical answer. Include the correct answer."
where [DIFFICULTY] is:
- simple: single-digit addition/subtraction
- moderate: two-digit operations or simple word problems
- complex: multi-step word problems

2. MODEL AND PROMPTING:
Use gpt-4o-mini (not GPT-2) through the LLM proxy server. Implement two prompting conditions:

Baseline (Standard) Prompt:
"Solve this arithmetic problem: [PROBLEM]"

Experimental (Socratic) Prompt:
"Let's solve this arithmetic problem step by step:
[PROBLEM]
1. What information is given in the problem?
2. What operation(s) do we need to perform?
3. Let's solve it step by step:
4. Therefore, the final answer is:"

3. EVALUATION:
For each problem:
- Store the problem text, difficulty level, correct answer
- For each condition (standard/Socratic):
* Store the full model response
* Extract the final numerical answer
* Compare to correct answer (exact match)
* For Socratic responses, score reasoning quality (0-3):
0: No clear reasoning
1: Identifies information OR operations
2: Identifies both information AND operations
3: Shows complete, correct reasoning

4. ANALYSIS AND VISUALIZATION:
- Calculate accuracy per condition and difficulty level
- Use bootstrap resampling to test for significant differences
- Create plots showing:
* Overall accuracy comparison
* Accuracy by difficulty level
* Reasoning quality scores (Socratic only)

5. EXECUTION ORDER:
1. Run MINI_PILOT first
2. If successful, run PILOT
3. Stop after PILOT (await human verification before FULL_EXPERIMENT)

6. LOGGING:
Log all major steps, including:
- Dataset generation
- Each model query and response
- Evaluation results
- Analysis steps and results

7. OUTPUT:
Generate a report including:
- Accuracy metrics for both conditions
- Statistical significance results
- Plots of performance comparisons
- Sample responses showing reasoning differences
- Recommendations for proceeding to full experiment

Note: All model interactions should use the LLM proxy server, and all major steps should be logged using the Logger/Debugging codeblock.
