ID: idea_26-simplified

simplified-siamese-retrieval

Hypothesis

A simplified Siamese network trained on a subset of MSCOCO will achieve higher precision and recall in image-text retrieval tasks compared to traditional cosine similarity between pre-trained image and text embeddings.

Elements

  • Independent variable: The retrieval method (Siamese network vs. cosine similarity baseline)
  • Dependent variable: Precision and recall in image-text retrieval tasks
  • Comparison groups: Siamese network retrieval vs. cosine similarity retrieval
  • Baseline/control: Cosine similarity between pre-trained image and text embeddings
  • Context/setting: A subset of the MSCOCO dataset (e.g., 5,000 image-text pairs)
  • Assumptions: The Siamese network can learn meaningful cross-modal representations even with limited training data
  • Relationship type: Causation
  • Population: Image-text pairs in the MSCOCO dataset
  • Timeframe: Not specified
  • Measurement method: Precision@k and Recall@k metrics (k=1, 5, 10)

Description

This research explores a simplified approach to enhancing image-text retrieval using a basic Siamese network architecture. Rather than tackling the full complexity of retrieval-augmented prompting, this project focuses on implementing a lightweight Siamese network to learn mappings between images and their corresponding text descriptions on a small subset of the MSCOCO dataset. The goal is to demonstrate that even a basic Siamese architecture can improve retrieval performance compared to traditional similarity-based retrieval methods. The project will implement a straightforward contrastive loss function to train the network and evaluate its performance using standard precision and recall metrics. This simplified approach provides a foundation for understanding cross-modal alignment while being feasible for implementation with limited computational resources.

Operationalization

Please implement a simplified Siamese network for image-text retrieval, comparing it against a cosine similarity baseline. The implementation should support three pilot modes (MINI_PILOT, PILOT, FULL_EXPERIMENT) with the following specifications:

PILOT MODE SETTINGS:
1. MINI_PILOT:
- Dataset: 100 training pairs, 20 validation pairs, 20 test pairs from MSCOCO
- Training: 2 epochs, batch size 8
- Evaluation: Calculate metrics on all test pairs

2. PILOT:
- Dataset: 1000 training pairs, 200 validation pairs, 200 test pairs from MSCOCO
- Training: 5 epochs, batch size 16
- Evaluation: Calculate metrics on all test pairs

3. FULL_EXPERIMENT:
- Dataset: 5000 training pairs, 1000 validation pairs, 1000 test pairs from MSCOCO
- Training: 20 epochs, batch size 32
- Evaluation: Calculate metrics on all test pairs

IMPLEMENTATION REQUIREMENTS:

1. Data Preparation:
- Use the Huggingface Datasets API to load MSCOCO
- Preprocess images: resize to 224x224, normalize using ImageNet statistics
- Preprocess text: tokenize and pad to 64 tokens
- Split data into train/val/test based on pilot mode settings

2. Model Architecture:
- Siamese network with two branches:
* Image: ResNet-18 (frozen) + Linear(256)
* Text: BERT-base (frozen) + Linear(256)
- Contrastive loss with margin 0.2

3. Training Loop:
- Initialize models and optimizer (Adam, lr=0.001)
- For each epoch:
* Train on batches (size varies by pilot mode)
* Evaluate on validation set
* Save best model checkpoint
* Log training/validation metrics

4. Baseline Implementation:
- Extract features using same frozen ResNet-18 and BERT-base
- Compute cosine similarity directly

5. Evaluation:
- For both methods (Siamese and baseline):
* Compute Precision@k, Recall@k (k=1,5,10)
* Compute Mean Average Precision
* Generate example retrievals
- Use bootstrap resampling to test significance

6. Visualization and Logging:
- Plot training curves
- Create tables of evaluation metrics
- Log example retrievals (successful and failed)
- Save all results to CSV files

EXECUTION ORDER:
1. Run MINI_PILOT first
2. If successful, run PILOT
3. Stop after PILOT (await human verification before FULL_EXPERIMENT)

SUCCESS CRITERIA:
- All code runs without errors
- Evaluation metrics are properly calculated
- Statistical testing shows meaningful comparison
- Results are properly logged and visualized

Please implement this experiment, starting with the MINI_PILOT mode to verify basic functionality.
