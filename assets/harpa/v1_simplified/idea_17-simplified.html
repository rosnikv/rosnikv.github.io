ID: idea_17-simplified

basic-error-pattern-visualization

Hypothesis

A simple visualization tool that applies k-means clustering to LLM evaluation errors will improve the interpretability of evaluation results by helping researchers identify recurring error patterns more efficiently than manual error analysis.

Elements

  • Independent variable: Use of error pattern clustering visualization tool
  • Dependent variable: Interpretability of LLM evaluation results (measured by time to identify patterns and accuracy of pattern identification)
  • Comparison groups: Manual error analysis vs. clustering-based visualization
  • Baseline/control: Traditional manual error analysis
  • Context/setting: Analysis of errors from LLM evaluations on a benchmark dataset
  • Assumptions: K-means clustering can effectively group similar errors
  • Relationship type: Causation
  • Population: LLM evaluation errors from a specific benchmark dataset
  • Timeframe: Single evaluation session
  • Measurement method: Time to identify patterns, accuracy of pattern identification, user satisfaction survey

Description

This research explores a simplified approach to visualizing error patterns in Large Language Model (LLM) evaluations. Rather than fully integrating with the complex LEVA framework, this project focuses on developing a basic visualization tool that applies clustering techniques to identify common error patterns in LLM outputs. The tool will use simple k-means clustering to group similar errors and create intuitive visualizations that help researchers identify recurring issues in model performance. By providing a clear visual representation of error patterns, the tool aims to enhance the interpretability of LLM evaluations and enable more targeted model improvements. This approach offers a more accessible entry point to error pattern analysis while still providing valuable insights into LLM performance.

Implementation Design

Design and implement a simple error pattern visualization tool for LLM evaluations following these steps:

1. Data Preparation:
- Use a publicly available LLM evaluation dataset (e.g., a subset of the HELM benchmark or BIG-bench).
- Extract 100-200 error instances where the LLM's response differs from the expected answer.
- For each error, create a simple feature vector including:
* Error length (character count)
* Presence/absence of key terms (create a list of 10-20 domain-specific terms)
* Basic semantic similarity to other errors (using sentence embeddings)

2. Clustering Implementation:
- Implement k-means clustering using scikit-learn.
- Experiment with different k values (3-7) to find optimal clustering.
- Apply dimensionality reduction (PCA or t-SNE) to visualize clusters in 2D space.

3. Visualization Development:
- Create a simple web-based visualization using matplotlib or Plotly.
- Implement:
* Scatter plot showing error clusters in 2D space
* Color-coding for different cluster assignments
* Hover functionality to display the full error text
* Basic filtering options (e.g., by error type if available in the dataset)

4. Evaluation Setup:
- Recruit 5-10 participants (fellow students or researchers)
- Design two tasks:
* Task 1: Manually review 50 errors and identify common patterns
* Task 2: Use the visualization tool to identify patterns in the same 50 errors
- Measure:
* Time taken to complete each task
* Number of distinct patterns identified
* Accuracy of patterns (compared to pre-labeled patterns)
* User satisfaction via a 5-question survey

5. Analysis and Reporting:
- Compare performance metrics between manual analysis and tool-assisted analysis
- Calculate statistical significance using paired t-tests
- Generate visualizations of the results (bar charts, box plots)
- Prepare a short report (3-5 pages) documenting the approach, implementation, results, and limitations

Deliverables:
1. Python code for the clustering and visualization tool
2. Documentation on how to use the tool
3. Results of the user study
4. Short research report

The code should be modular, with separate functions for data loading, feature extraction, clustering, visualization, and evaluation. Use clear variable names and include comments to make the code accessible to other researchers.

Operationalization

Please implement a basic error pattern visualization experiment that compares manual error analysis to a clustering-based visualization approach. The experiment should follow these specifications:

GLOBAL SETTINGS:
- Set PILOT_MODE to one of: 'MINI_PILOT', 'PILOT', or 'FULL_EXPERIMENT'
- Initially run with MINI_PILOT. If successful, proceed to PILOT, then stop.
- Data scale for each mode:
* MINI_PILOT: 10 LLM errors, 2 participants, 5 mins per analysis task
* PILOT: 50 LLM errors, 3 participants, 15 mins per analysis task
* FULL_EXPERIMENT: 200 LLM errors, 10 participants, 30 mins per analysis task

STEP 1: Generate Error Dataset
- Use gpt-4o-mini to generate errors by asking it questions and comparing to ground truth
- For each pilot mode:
* MINI_PILOT: Generate 10 question-answer pairs, get LLM responses
* PILOT: Generate 50 question-answer pairs, get LLM responses
* FULL_EXPERIMENT: Generate 200 question-answer pairs, get LLM responses
- Store errors with metadata: question, expected answer, LLM answer, error type (if available)

STEP 2: Feature Extraction
- For each error, compute:
* Length (character count)
* Word count
* Basic error category (if available)
* Semantic similarity between expected and actual answer

STEP 3: Clustering
- Apply k-means clustering (k=3 for MINI_PILOT, k=5 for others)
- Create 2D visualization using MatPlotLib:
* X-axis: First principal component
* Y-axis: Second principal component
* Color-code by cluster
* Add hover text showing full error details

STEP 4: User Study
- For each participant:
* Task 1 (Baseline): Manual error analysis
- Present errors in spreadsheet format
- Ask to identify and describe error patterns
- Record time taken and patterns found
* Task 2 (Experimental): Clustering visualization
- Present clustering visualization
- Ask to identify and describe error patterns
- Record time taken and patterns found
* Brief satisfaction survey (1-5 scale)

STEP 5: Analysis
- Compare between baseline and experimental:
* Time taken to identify patterns
* Number of patterns identified
* Pattern quality (if ground truth available)
* User satisfaction scores
- Use bootstrap resampling to test for significant differences

STEP 6: Visualization and Reporting
- Generate plots comparing baseline vs experimental:
* Box plots of time taken
* Bar plots of patterns identified
* User satisfaction scores
- Save all results and visualizations
