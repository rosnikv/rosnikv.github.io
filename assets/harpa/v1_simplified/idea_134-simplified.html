simple-prompt-syntax-enhancement

Hypothesis

Incorporating basic syntactic features (sentence length, clause count, and POS patterns) into prompt templates will improve language model performance on few-shot text classification tasks compared to standard prompts without syntactic information.

Elements

  • Independent variable: Type of prompt template (with or without syntactic features)
  • Dependent variable: Model performance on few-shot text classification tasks (accuracy, F1 score)
  • Comparison groups: Standard prompts vs. Syntax-enhanced prompts
  • Baseline/control: Standard prompt templates without syntactic information
  • Context/setting: Few-shot text classification tasks using pre-trained language models
  • Assumptions: Basic syntactic information can be effectively incorporated into prompt templates
  • Relationship type: Causation
  • Population: Text classification datasets (e.g., SST-2, AG News subset)
  • Timeframe: Not applicable
  • Measurement method: Classification accuracy, F1 score, and qualitative analysis of model outputs

Description

This research explores how incorporating basic syntactic information into prompt templates can improve the performance of language models on text classification tasks. Rather than implementing complex soft prompts with semantic role labeling, this study focuses on using simple syntactic features (such as sentence length, number of clauses, and part-of-speech patterns) to create enhanced prompt templates. These enhanced templates will be compared against standard prompts on a few-shot text classification task to determine if even basic syntactic awareness can improve model performance and interpretability. The research aims to provide insights into how structural linguistic information, even when implemented in a straightforward manner, might help language models better understand and classify text.

# Experiment Design: Simple Prompt Syntax Enhancement

## 1. Implementation Details

### 1.1 Syntactic Feature Extraction
Implement a simple syntactic feature extractor using NLTK that computes the following features for each input text:
- Sentence length (number of words)
- Number of clauses (approximated by counting commas plus one)
- Part-of-speech (POS) patterns (the sequence of POS tags for the first 5 words)

```python
import nltk
from nltk import pos_tag
from nltk.tokenize import word_tokenize, sent_tokenize

def extract_syntactic_features(text):
# Tokenize text
sentences = sent_tokenize(text)
words = word_tokenize(text)

# Calculate sentence length
sent_length = len(words)

# Approximate clause count (commas + 1)
clause_count = text.count(',') + 1

# Get POS tags for first 5 words (or fewer if text is shorter)
pos_tags = pos_tag(words[:5])
pos_pattern = ' '.join([tag for _, tag in pos_tags])

return {
'sentence_length': sent_length,
'clause_count': clause_count,
'pos_pattern': pos_pattern
}
```

```python
few_shot_prompt = ""

# Add examples
for ex in examples:
if include_syntax:

else:

categories=', '.join(CATEGORIES),
input_text=ex['text']
)
few_shot_prompt += example_prompt + f" {ex['label']}\n\n"

# Add query
if include_syntax:
syntax_features = extract_syntactic_features(query)
query_prompt = template.format(
categories=', '.join(CATEGORIES),
input_text=query,
sentence_length=syntax_features['sentence_length'],
clause_count=syntax_features['clause_count'],
pos_pattern=syntax_features['pos_pattern']
)
else:
query_prompt = template.format(
categories=', '.join(CATEGORIES),
input_text=query
)

return few_shot_prompt + query_prompt
```

```python
import random
from sklearn.metrics import accuracy_score, f1_score

def run_experiment(dataset, prompt_template, include_syntax=False, k=5):
predictions = []
true_labels = []

for example in dataset:
```

### 4.2 Statistical Analysis
Perform statistical significance testing to determine if the differences between standard and syntax-enhanced prompts are significant:

```python
from scipy import stats

def perform_statistical_analysis(standard_results, syntax_results):
# Create binary array where 1 = correct prediction, 0 = incorrect
standard_correct = [pred == true for pred, true in zip(standard_results['predictions'], standard_results['true_labels'])]
syntax_correct = [pred == true for pred, true in zip(syntax_results['predictions'], syntax_results['true_labels'])]

# Perform McNemar's test for paired nominal data
contingency_table = [
[sum(1 for s, e in zip(standard_correct, syntax_correct) if s and e), # Both correct
sum(1 for s, e in zip(standard_correct, syntax_correct) if s and not e)], # Standard correct, Syntax wrong
[sum(1 for s, e in zip(standard_correct, syntax_correct) if not s and e), # Standard wrong, Syntax correct
sum(1 for s, e in zip(standard_correct, syntax_correct) if not s and not e)] # Both wrong
]

result = stats.mcnemar(contingency_table, correction=True)
return {
'statistic': result.statistic,
'p_value': result.pvalue,
'significant': result.pvalue < 0.05
}

# Perform statistical analysis
sst2_stats = perform_statistical_analysis(sst2_standard_results, sst2_syntax_results)
ag_news_stats = perform_statistical_analysis(ag_news_standard_results, ag_news_syntax_results)

print(f"SST-2 Statistical Analysis: p-value = {sst2_stats['p_value']:.4f}, Significant: {sst2_stats['significant']}")
print(f"AG News Statistical Analysis: p-value = {ag_news_stats['p_value']:.4f}, Significant: {ag_news_stats['significant']}")
```

Operationalization

Create an experiment to test whether incorporating basic syntactic features into prompt templates improves language model performance on text classification tasks. The experiment should follow a three-stage pilot framework:

GLOBAL CONFIGURATION:
- Set PILOT_MODE to one of: 'MINI_PILOT', 'PILOT', or 'FULL_EXPERIMENT'
- Use gpt-4o-mini as the language model for all conditions
- Log all major steps and results

PILOT CONFIGURATIONS:
1. MINI_PILOT:
- Dataset: SST-2 only
- Sample size: 10 examples total (5 positive, 5 negative)
- Few-shot examples: 2 per class
- Maximum examples to process: 10

2. PILOT:
- Dataset: SST-2 only
- Sample size: 100 examples total (50 positive, 50 negative)
- Few-shot examples: 5 per class
- Maximum examples to process: 100

3. FULL_EXPERIMENT (not to be run initially):
- Datasets: SST-2 and AG News
- Sample sizes: Full validation sets
- Few-shot examples: 5 per class
- Maximum examples to process: All available

EXPERIMENT STEPS:

1. Data Loading and Preprocessing:
- Use Huggingface Datasets to load SST-2
- Select appropriate subset based on PILOT_MODE
- Split into train (for few-shot examples) and test portions

2. Syntactic Feature Extraction:
- For each text input, extract:
* Sentence length (word count)
* Clause count (commas + 1)
* POS pattern (first 5 words)
- Use NLTK's POS tagger for feature extraction

3. Prompt Templates:
a) Baseline (without syntax):
"Classify the following text as positive or negative:\n\nText: {input_text}\n\nCategory:"

b) Syntax-enhanced:
"Classify the following text as positive or negative:\n\nText: {input_text}\n\nSyntactic information:\n- Length: {length} words\n- Clauses: {clauses}\n- POS pattern: {pos_pattern}\n\nBased on both content and structure, the category is:"

4. Experiment Execution:
- For each example in the test set:
* Randomly select k few-shot examples (k based on PILOT_MODE)
* Create both baseline and syntax-enhanced prompts
* Query gpt-4o-mini with both prompts
* Record predictions and ground truth

5. Analysis:
- Calculate accuracy and F1 score for both conditions
- Perform bootstrap resampling to test for significant differences
- Generate confusion matrices
- Log all results

6. Output Requirements:
- Save all results in JSON format
- Include per-example predictions and metrics
- Generate summary statistics
- Create error analysis report

IMPORTANT NOTES:
1. Start with MINI_PILOT mode
2. If MINI_PILOT successful, proceed to PILOT mode
3. Stop after PILOT mode - do not proceed to FULL_EXPERIMENT
4. Log all major steps and any errors
